## Отправка напоминаний (уведомлений) пользователям

Разберем следующую ситуацию - необходим агент, который работает с определенной периодичностью (ежедневно) или ежедневно запускается вручную и отправляет однократные напоминания (уведомления) о необходимости завершения изучения электронного курса сотрудникам и их руководителям через некоторое количество дней после назначения.  
Данный агент должен рассылать однократные сообщения сотрудникам через 10 дней после назначения им курса (только в том случае, если они не завершили этот курс) и через 20 дней - их руководителям.  
Параметры 10 и 20 дней задаются переменными _DAYS\_TO\_REMIND\_EMPLOYEE_ и _DAYS\_TO\_REMIND\_BOSS_. Если срок рассылки напоминаний должен быть другим, то значения этих переменных нужно изменить.  
В коде агента используется каталог _active\_learning_ (_Незаконченный электронный курс_). В этом каталоге содержится информация о незаконченных электронных курсах.  
Если агент будет запускаться вручную и хотя бы один день будет пропущен, то сообщения сотрудникам и их руководителям, соответствующие этому дню, не будут отправлены.   
  
Пакет с агентом и шаблонами уведомлений можно скачать в полезных компонентах. 

1.  **Программный код агента**  
      
    Сначала разберем программный код агента.  
    Комментарии выделены красным шрифтом (текст комментария относится к блоку кода, расположенного выше него), код шаблона - синим.
    
    NOTIFICATION\_1 = "elearning\_reminder\_1";   
    NOTIFICATION\_2 = "elearning\_reminder\_2";   
    // Код типа уведомления   
      
    DAYS\_TO\_REMIND\_EMPLOYEE = 10;  
    // Количество дней, за которые необходимо уведомлять сотрудника  
      
    DAYS\_TO\_REMIND\_BOSS = 20;  
    // Количество дней, за которые необходимо уведомлять руководителя  
      
    from = DateOffset(DateNewTime(Date()),(0-1)\*86400\*DAYS\_TO\_REMIND\_EMPLOYEE);  
    to = DateOffset(DateNewTime(Date()),(0-1)\*86400\*(DAYS\_TO\_REMIND\_EMPLOYEE-1));  
    // Отсчитаем дни назад от текущей даты, которую получим с помощью вызова DateNewTime(Date())  
    // В переменной from будет хранится дата начала дня 10 дней назад, в переменной _to_ - дата начала дня 9 дней назад  
      
    acs = XQuery('for $elem in active\_learnings where $elem/start\_usage\_date >= '+XQueryLiteral(from)+' and $elem/start\_usage\_date < '+XQueryLiteral(to)+' return $elem');  
    // Найдем курсы, назначенные в диапазоне дат from и to  
      
    for (ac in acs)  
    {  
         // Пройдем циклом по найденным незавершенным курсам  
         tools.create\_notification(NOTIFICATION\_1, ac.id);  
         // Вызовем функцию create\_notification, в которую передадим код типа уведомления и идентификатор базового документа (незавершенного курса)  
    }  
      
    from = DateOffset(DateNewTime(Date()),(0-1)\*86400\*DAYS\_TO\_REMIND\_BOSS);  
    to = DateOffset(DateNewTime(Date()),(0-1)\*86400\*(DAYS\_TO\_REMIND\_BOSS-1));  
    // Далее аналогично для курсов назначенных 20 дней назад, но будем отправлять уведомление другого типа - руководителю  
      
    acs = XQuery('for $elem in active\_learnings where $elem/start\_usage\_date >= '+XQueryLiteral(from)+' and $elem/start\_usage\_date < '+XQueryLiteral(to)+' return $elem');  
      
    for (ac in acs)  
    {  
         tools.create\_notification(NOTIFICATION\_2, ac.id);  
    }
    
    Далее нужно создать типы и шаблоны уведомлений. Типы уведомлений лучше создавать после того, как были созданы шаблоны уведомлений.
    
  
3.  **Создание типов уведомлений для сотрудника и руководителя**  
      
    Для того, чтобы уведомления отправлялись необходимо также создать два типа уведомления (Блок "**Дизайнер**", раздел "**Типы уведомлений**"). Код типа уведомления должен совпадать с кодом, указанным в агенте (переменная **NOTIFICATION\_1**) (см. п. 1).  
    Настройка типа уведомления для сотрудника такова:  
      
      
    Такая настройка говорит, что в документе (прикрепленном) (в данном случае - это незавершенный курс), идентификатор которого мы указали в функции tools.create\_notification, есть поле _person\_id_ (идентификатор сотрудника) и именно этому пользователю мы будем отсылать уведомление. Шаблон уведомления надо выбрать из списка (его мы рассмотрим далее - см. п. 3).  
      
    Для отправки уведомления руководителю нашего обучаемого мы создадим другой тип уведомления. Обратите внимание, что в нем мы выберем опцию отправки письма не самому сотруднику, привязанному к незавершенному курсу, а его руководителю (по оргструктуре). Код типа уведомления должен совпадать с кодом, указанным в агенте (переменная **NOTIFICATION\_2**) (см. п. 1).  
      
     
4.  **Настройка шаблонов уведомлений для сотрудника и руководителя**  
      
    Теперь нам необходимо настроить шаблоны уведомлений (тексты писем, с программным кодом) (Блок "**Дизайнер**", раздел "**Шаблоны уведомлений**"). Эти шаблоны мы указали выше в карточках созданных ранее типов уведомлений.  
    Карточка шаблона уведомления сотруднику выглядит так. Код мы разберем ниже.  
      
      
    Так же, как и другие шаблоны (например, шаблон портала), данный шаблон может содержать как программный код (заключенный в блоках, обрамленных конструкциями <% и %>), так и обычный текст (в данном случае - содержание письма).  
     
    
    <%  
    // В переменной _objDoc_ находится уже открытый документ (в нашем случае - незавершенный курс), идентификатор которого был передан в функцию create\_notification  
    try {  
         employeeDoc = OpenDoc( UrlFromDocID( objDoc.person\_id )).TopElem;  
         // Откроем документ сотрудника  
         name\_employee = employeeDoc.firstname + ' ' + employeeDoc.middlename;  
         // Сохраним в переменную его имя и отчество  
    }  
    catch (err){ };  
      
    try   
    {  
         learning\_program = objDoc.course\_id.ForeignElem.name;  
         // Получим название электронного курса   
    }  
    catch (err) { };  
      
    curHostSettings = global\_settings.settings;  
    // Откроем документ глобальных настроек системы  
      
    curWebDesign = global\_settings.settings.web\_designs.GetChildByKey( curHostSettings.default\_web\_design );  
    // Узнаем код текущего дизайна  
      
    curWebDesignUrl = curWebDesign.url;  
    // Для текущего дизайна возьмем его базовый URL (для того, чтобы корректно построить ссылку в письме)  
      
    PORTAL\_URL = ( curHostSettings.default\_web\_design != 'default' ? (global\_settings.settings.portal\_base\_url + "/" + curWebDesignUrl) : global\_settings.settings.portal\_base\_url );  
    // Построим базовый путь в зависимости от того у нас дизайн по умолчанию или нет  
      
    try   
    {  
         \_header\_host=UrlAppendPath( PORTAL\_URL,'/view\_doc.html?mode=');  
         link = \_header\_host+'learning\_proc&course\_id=' + objDoc.course\_id+'&object\_id='+objDocID;   
    }  
    catch (err) { };  
    %>  
      
    // Далее идет обычный текст - содержание сообщения  
    // (_name\_employee, learning\_program и link_ \- строковые переменные, сформированные в программном коде шаблона (см. выше)):   
      
    _Уважаемый_ <%\=name\_employee%>,  
      
    _Напоминаем Вам, что с момента начала изучения электронного курса_ ”<%\=learning\_program%>”, _прошло 10 дней. Просим завершить изучение курса! Для продолжения изучения откройте ссылку:_ <%\=link%>.  
      
    _Спасибо за понимание!_  
      
    _Сотрудники отдела обучения._
    
    Теперь рассмотрим шаблон, отправляемый руководителю. Он несколько проще, т.к. в нем не надо формировать URL для ссылки на карточку курса. Однако необходимо определить руководителя, чтобы внести в текст письма его имя и отчество.
    
    <%  
    // В переменной objDoc находится уже открытый документ (в нашем случае - незавершенный курс), идентификатор которого был передан в функцию create\_notification  
    try {  
         employeeDoc = OpenDoc( UrlFromDocID( objDoc.person\_id )).TopElem;  
         // Откроем документ сотрудника  
      
         name\_employee = employeeDoc.firstname + ' ' + employeeDoc.middlename + ' ' + employeeDoc.lastname;  
         // Сохраним в переменную ФИО сотрудника  
      
         bossRecord = tools.get\_user\_boss( objDoc.person\_id );  
         // Откроем документ руководителя сотрудника. Функция get\_user\_boss вернет запись сотрудника, являющегося руководителем, из каталога (аналог результата выполнения функции XQuery)  
      
         bossDoc = OpenDoc( UrlFromDocID( bossDoc.person\_id )).TopElem;  
         // Откроем документ руководителя  
      
         name\_boss = bossDoc.firstname + ' ' + bossDoc.middlename;  
         // Сохраним в переменную имя и отчество руководителя  
    }  
    catch (err){ };  
      
    try {  
         learning\_program = objDoc.course\_id.ForeignElem.name;  
         // Получим название электронного курса   
    }  
    catch (err) { };  
    %>  
      
    // Далее идет обычный текст - содержание сообщения:   
    // (name\_boss, _name\_employee и learning\_program_ \- строковые переменные, сформированные в программном коде шаблона (см. выше)):   
      
    _Уважаемый_ <%\=name\_boss%>,  
      
    _Напоминаем Вам, что Ваш сотрудник_ <%\=name\_employee%> _начал(а) изучение электронного курса_ ”<%\=learning\_program%>”_, 20 дней назад и до сих пор не завершил(а) его изучение. Просим принять меры!_   
      
    _Спасибо за понимание!_  
      
    _Сотрудники отдела обучения._
