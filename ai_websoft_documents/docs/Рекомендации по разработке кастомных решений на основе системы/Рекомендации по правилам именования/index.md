## Рекомендации по правилам именования

При выборе наименований для кастомного приложения и его компонентов (объектов) необходимо обратить внимание на следующие основные положения:

•             Код библиотеки – для кастомных клиентских приложений может быть использован код организации-пользователя (заказчика), для объемных кастомных приложений широкого пользования рекомендуется отображать в наименованиях группы бизнес-процессов (модули) (например, _edu, portal, personal_ и т.д.)

•             Код приложения может быть составным и включать в себя код вендора, код библиотеки и собственно код приложения.

Например: _websoftgpb\_compass01_ (компетенции), _websoftgpb\_mbo02_ (цели).

•             Коды всех объектов, связанных с приложением, желательно начинать с кода приложения, а затем, через подчеркивание, добавлять код самого объекта внутри приложения. Также рекомендуется использовать определенные унифицированные значения. В частности, в приложениях по оценке для шаблона дерева можно было бы применять суффикс _tree_, для шаблонов формы – _pa_, для обработки сохранения – _save_.

Например: websoftgpb\_compass01\_tree, websoftgpb\_compass01\_pa, websoftgpb\_compass01\_save_._

Другой вариант именования объектов: _websoftgpb\_compass01\_pacomp, websoftgpb\_compass01\_savecomp, websoftgpb\_compass01\_listappraises_ (коллекция для кастомного списка процедур).
