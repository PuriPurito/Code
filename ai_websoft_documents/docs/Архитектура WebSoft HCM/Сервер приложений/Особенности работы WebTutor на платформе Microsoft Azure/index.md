## Особенности работы WebTutor на платформе Microsoft Azure

В этом разделе мы перечислим основные особенности работы системы WebTutor в облачной платформе Microsoft Azure

**1\. Распределение системы по нескольким виртуальным машинам**

Типовая конфигурация работы системы WebTutor в Microsoft Azure следующая: используются две виртуальные машины (так называемые веб-роли) для обслуживания пользователей портала и администраторов системы, использующих программу Администратор WebTutor, и одна виртуальная машина (так называемая рабочая роль) для выполнения агентов на стороне сервера. При необходимости обеспечить работу под очень большой нагрузкой количество веб-ролей и рабочих ролей может быть увличено произвольным образом (например, 4 веб-роли и 1 рабочая роль).

Развертывание системы WebTutor на указанных виртуальных машинах выполняется в автоматическом режиме из созданного разработчиками WebSoft так называемого deployment-пакета. Программа Конфигуратор WebTutor позволяет сформировать depoyment-пакет автоматически на базе данных, хранящихся в системе WebTutor заказчика. Т.е. клиенты WebSoft имеют в своем распоряжении инструмент, позволяющий и в любой момент мигрировать свою систему WebTutor в облачную платформу Microsoft Azure.

В то время как веб-роли и рабочие роли представляют из себя обычные виртуальные машины с ОС Windows, установка WebTutor на них никогда не выполняется вручную. Вместо этого, про создании новой виртуальной машины на ней автоматически разворачивается и запускается WebTutor из подготовленного ранее deployment-пакета. Изменение файлов системы после развертывания возможно но не рекомендуется, так как в рамках обслуживания своей облачной платформы Micrisift периодически (как правило, раз в месяц, но, возможно, и чаще) перезагружает и инициализирует виртуальные машины, заново разворачивая систему на них из deployment-пакета.

**2\. Хранение данных системы WebTutor в Microsoft Azure**

В облачной платформе Microsoft Azure есть два способа хранения данных, которые используются в системе WebTutor:

*   Так называемое "хранилище" (table storage) используется для хранения произвольной информации (BLOBs, файлы и прочее) в NoSQL базе данных
*   Облачная СУБД SQL Azure позволяет создавать обычные реляционные базы данных, с которыми можно работать с помощью SQL

Стоимость размещения данных в хранилище гораздо меньше, чем в SQL Azure, поэтому на платформе Microsoft Azure хранение данных WebTutor оптимизировано следующим образом:

*   Каталоги WebTutor (т.е. все поля объектов WebTutor, которые включены в каталоги) хранятся в SQL Azure
*   Полные карточки объектов размещаются в хранилище (table storage)
*   Дополнительные поля размещаются в отдельных таблицах в SQL Azure
*   Ресурсы базы и данные, публикуемые на портале (например, электронные курсы и тесты), размещаются в хранилище (table storage)

**3\. Написание программного кода и расширение системы**

Клиенты получают доступ к системе WebTutor, развернутой на платформе Microsoft Azure, через программу Администратор WebTutor. Любые доработки (агенты, веб-шаблоны, отчеты), которые клиенты хотят выполнить и разместить в системе, должны загружаться в WebTutor через программу Аминистратор WebTutor. Доступ к файлам системы WebTutor при размещении системы на платформе Microsoft Azure в аккаунте WebSoft не предоставляется.

В связи с тем, что в БД SQL Azure находится только часть данных, работа с данными в программном коде должна осуществляться следующим образом:

*   Можно использовать любые запросы XQuery и получать полные данных объектов через OpenDoc
*   При необходимости через запросы SQL можно обращаться к данным, хранящимся в SQL Azure, т.е. к полям, хранящимся в каталогах, и настраиваемым полям

Обратите внимание, что программный код, написанный для типового "корпоративного" варианта размещения WebTutor, когда вся база данных системы размещается под управлением СУБД MS SQL Server, не будет работать на платформе Microsoft Azure, если с помощью SQL производится обращение к данным объектов, не хранящимся в каталогах и не являющимся настраиваемыми полями.
