## Способы расширения структуры данных

При необходимости пользователи могут расширить структуру данных, добавив дополнительные (собственные) данные с помощью:  
1) создания настраиваемых полей в карточке некоторого объекта.   
2) создания пользовательского (кастомного, настраиваемого) типа документа, который может быть привязан к карточке объекта.  
3) создания специальных пользовательских структур, которые называются «**Данные объектов**».

В системе предусмотрена возможность расширить перечень системных полей и разделов карточек объектов за счет использования настраиваемых полей. 

Создание и настройка настраиваемых полей и разделов карточек производятся в окне «**Настраиваемые поля**» (кнопка   (**Настройки**) раздел **Настраиваемые поля** главного меню интерфейса администратора, расположенного с левой стороны).

На приведенном скриншоте настраиваемое поле добавляется на карточку **Сотрудник**:  

**Типы документов** - это типы объектов базы, настроенные администратором в дополнение к стандартным. Настраиваемые объекты так же, как и системные, описываются в карточках, которые хранятся в интерфейсе администратора, могут быть размещены на Портале и использоваться в системе наравне с объектами стандартных типов.

Пользовательские типы документов отображаются и настраиваются в разделе **Модули - Типы документов** блока **Дизайнер**. Для создания нового типа документа нажмите на кнопку «**Новая запись**» и заполните карточку нового типа документа.

При добавлении настраиваемого типа документа система создает для него в базе данных таблицу-каталог с определенным именем (**cc\_<имя\_типа\_документа>s**).  
Для XML-базы при добавлении настраиваемого типа документа с именем, например, **cc\_doc** в папке _WebTutorServer/wt\_data/catalogs/_ создается файл _cc\_docs.xdb_. При использовании SQL-базы в этом случае формируются две таблицы - **cc\_docs** и **cc\_doc**.  
  
  
Третий способ расширения структуры – добавление _данных объекта_. **Данные объекта** \- это специальный объект системы (и каталог), который может быть привязан к любому объекту системы.  
По сути – это некий дополнительный документ, в который можно вынести некоторые дополнительные данные, чтобы они не «засоряли» основную карточку.  
Особенно эффективно будет использование данных объекта, если имеются достаточно громоздкие дополнительные данные, необходимые для выполнения некоторых процессов, а в системе отсутствуют стандартные объекты для хранения такой информации или у компании не был приобретен соответствующий модуль.  
В описываемом случае можно будет создать **Тип данных объекта**, добавить в него соответствующее дополнительное поле, в котором можно хранить нужные данные.   
Указанный **Тип данных объекта** можно будет привязать к карточке основного объекта (например, к карточке **Сотрудник**).

По умолчанию в карточках объектов отображается стандартный перечень полей. Однако зачастую возникает необходимость добавить к данным объекта некоторые специфические поля, необходимые для обеспечения тех или иных бизнес-процессов. Например, если мы создаем данные о несовершеннолетних детях сотрудника, то потребуется добавление полей для хранения такой информации, как фамилия, имя, отчество и дата рождения ребенка.  
Система позволяет добавить к типу данных объектов произвольный набор дополнительных полей разных форматов. При этом такие поля будут автоматически добавляться ко всем данных объектов этого типа. Поля отображаются непосредственно в карточках данных объектов в программе WebTutor Administrator.

В принципе, можно было бы хранить указанную информацию в дополнительных полях карточки основного объекта, но при этом карточка основного объекта станет слишком «тяжелой» и будет тормозить при открытии…

Другой вариант использования **Типа данных объектов** – это связывание двух объектов между собой; в карточке **Типа данных объектов** имеются ссылки на два разных документа в системе (**Тип объекта** и **Тип связанного объекта**).

Пользовательский **Тип данных объектов** создается в модуле **Дизайнер** в разделе **Справочники – Типы данных объектов**.

Для создания нового объекта данного типа нажмите на кнопку **Новая запись** и введите в открывшуюся карточку типа данных объектов всю необходимую информацию:  

Для одного и того же объекта может быть создано несколько типов данных.

Использование **Типов данных объектов** во многих случаях позволяет обойтись без создания настраиваемых типов документов.

Итак, подведем итоги способов расширения структуры:  
\- при добавлении настраиваемого поля не создаются ни новые каталоги (таблицы), ни новые документы в базе данных (расширяется только структура существующих документов);  
\- при добавлении настраиваемого типа документа создается новый каталог (таблица), а в ней - документы, в которых сохраняются данные;  
\- при добавлении типа данных объекта новые каталоги не создаются, но формируется новый документ в базе, в котором сохраняются данные.
