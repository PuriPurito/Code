## Агенты в интерфейсе администратора

Агенты сервера могут реализовывать различные процессы в системе и являются важным инструментом автоматизации процессов.

Агенты могут быть различных типов:   
_\- Исполняемый код;   
\- Выгрузка базы;   
\- Импорт сотрудников из Excel;   
\- Скачивание пакетов обновлений;   
\- Отправка данных;   
\- Прием данных;   
\- Назначения для пользователей._ 

Агенты могут запускаться в системе автоматически (по расписанию) или вручную. Ручной запуск может выполняться из карточки агента по кнопке “Запустить агент” или “Выполнить агент на стороне клиента”, а также над объектами системы Websoft HCM. 

В рамках работы агента, при необходимости, может выполняться журналирование событий и показателей. Запись может выполняться в следующие журналы:   
\- в журнал xhttp (...\\WebTutorServer\\Logs\\);   
\- в события базы (Системное администрирование -> События базы);   
\- в отдельный txt-лог (...\\WebTutorServer\\Logs\\) или в Excel-файл.

Далее речь будет идти об агентах типа **Исполняемый код**. Такие агенты – это встроенный инструмент разработки, позволяющий разработчику (программисту) выполнять программный код.

Про агенты в системе Websoft HCM ранее уже говорилось. В этом разделе мы рассмотрим _более сложные агенты_, используемые в реальной системе для облегчения работы администратора.

Программный код в агенте может быть указан на вкладке **Программный код** или с помощью ссылки на файл, в котором этот код был сохранен.  
Ссылка на указанный файл указывается в поле **Ссылка на файл выполняемого кода** на вкладке **Общие сведения**.   
Пример ссылки на файл выполняемого кода:  
_x-local://wtv/agents/agnt\_add\_points.js_  
Для запуска на сервере данный файл должен быть размещен по адресу: _WebTutorServer/wtv/agents/agnt\_add\_points.js_, а для запуска на клиенте по адресу: _WebTutorAdmin/wtv/agents/agnt\_add\_points.js_.  
Данный файл может быть размещен в обоих указанных местах.

Если в агенте указана ссылка на файл выполняемого кода, то код из данного файла отображается в поле программного кода на вкладке **Программный код**.

Если же в поле программного кода на вкладке **Программный код** ранее был записан какой-либо код, то после подключения файла с программным кодом ранее записанный код автоматически удаляется.

На вкладке **Общие сведения** имеется область **Переменные**, к данным которой можно обращаться в программном коде с помощью ключевого слова _Param_.  
Пример обращения к переменной _bCourse_ из области **Переменные**:  
_Param.bCourse_

В приведенном примере (см. скриншот агента, размещенный выше) значение выражения _Param.bCourse_ равно _true_.   
  
Агенты размещаются в интерфейсе Webtutor Administrator в разделе **Дизайнер – Агенты сервера**.  
    
Рассмотрим несколько примеров агентов из реальной практики программирования.

В первом и во втором примерах производится программное изменение параметров обрабатываемых объектов, в третьем примере - удаление объектов.

Несколько предварительных замечаний:

Агенты сервера часто используются для задач «пакетного» изменения параметров объектов системы.  
Обратите внимание на _общую схему_ выполнения задач подобного типа:  
1) Определение массива объектов, для которых производится изменение параметров.  
2) Обход отобранного массива объектов с помощью цикла.  
3) Открытие документа каждого из объектов массива (изменение параметров объекта возможно только в документе объектов).  
4) Выполнение изменения параметров в открытом документе объекта.  
5) Сохранение измененного документа.

Внимание! Начинающие программисты часто забывают сохранить документы измененных объектов. В этом случае все действия, выполненные с документами объектов, аннулируются, и объекты возвращаются к первоначальному состоянию.

Внимание! Все приведенных ниже примеры программного кода приводят к изменению базы данных.  
В первом и во втором примерах производится сохранение измененного состояния объектов (функция **Save**).  
В третьем примере удаляются некоторые из объектов (функция **DeleteDoc**).  
Такие программные коды **являются потенциально опасными** (особенно, если они разрабатывались начинающими программистами или если не совсем ясно, какие действия выполняет данный код). Подобные программы необходимо предварительно **хорошо отладить** на тестовой базе или на тестовом примере.   
Никогда не выполняйте код, если вы точно не знаете, какие действия он выполняет или как он работает!
