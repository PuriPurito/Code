## Использование программного кода для настройки столбцов настраиваемого отчета в режиме функции

Для начала создадим простой настраиваемый отчет **Законченные тесты** (блок **Дизайнер** – группа **Шаблоны – Настраиваемые отчеты**). Этот отчет станет основой для изучения использования программного кода при настройке столбцов.  

Перейдем на вкладку **Отчет** и выполним команду **Создать отчет**:  

Для демонстрации использования режима функции вернемся на вкладку **Настройка отчета**, добавим новый столбец и установим переключатель в значение **f(x)**.  

Теперь в данное поле можно вписать однострочный исполняемый код, который должен быть записан по определенным правилам, несколько отличающимся от стандартных.   
Перечислим некоторые основные особенности формирования такого кода:

1) Для вывода в столбец значений некоторого параметра указываем латинское наименование этого параметра в фигурных скобках (например, для получения и преобразования количества баллов – _{score}_). Фигурные скобки означают, что мы берем некоторое значение параметра из выборки, формируемой настройками параметров или программным кодом.  
Далее со значениями, заключенными в фигурные скобки, можно выполнять некоторые программные действия. Например:    
_({score}/{max\_score})\*100_  
(результат типа _Real_) 

Вот пример использования оператора ветвления '?'   
_{score} > 7 ? "Успешно" : "Неуспешно"_  
(результат типа _String_) 

2) Обращение к данным другого столбца:  
_%col<номер\_столбца>_  
Например, _%col4_ – обращение к данным столбца номер 4.

_%col4 > 20 ? "Успешно" : "Неуспешно"_  
(результат типа _String_)   

3) Для преодоления ограничения «однострочности» кода функции столбца можно использовать «невидимые» столбцы. Для формирования «невидимого» столбца нажмите на значок  (_Изменить визуальные настройки_) и снимите флажок параметра **Видимость**:  

Далее результат этого столбца можно использовать для определения значений функций других столбцов.

4) Программирование переходов к другим (связанным) каталогам.  
Переход к другим каталогам производится с помощью функции _ForeignElem_:  
_{person\_id}.ForeignElem.position\_id.ForeignElem.parent\_object\_id.ForeignElem.name_  
В данном примере мы перешли от ID сотрудника, сдававшего тест, к ID должности, далее к ID родительского объекта для каталога **Должность** (это **Подразделение**) и к названию подразделения, в котором работает сотрудник.

На следующем скриншоте выражение для столбца 8 аналогично выражению столбца 7, но в столбце 7 доступно только три перехода, а в столбце 8 выполняется также четвертый переход (_parent\_object\_id.ForeignElem.name_).  
   
Ограничений на количество переходов, выполненных с помощью функции ForeignElem, нет.

5) Обращение из настраиваемого отчета к XML-структуре документа.  
Некоторые данные не хранятся в каталоге, а находятся в XML-структуре документа (например, пароли сотрудников).  
Поэтому в ряде случаев необходимо обращаться из настраиваемого отчета к документу объекта. Такое обращение можно выполнить с помощью встроенных функций UrlFromDocID (поиск URL объекта по ID) и OpenDoc (открытие документа):

Вот пример выражения, получающего значения паролей сотрудников с помощью обращения к документу объекта **Сотрудник**:  
_OpenDoc(UrlFromDocID({person\_id})).TopElem.password_

Данное выражение применимо для случая, если пароли сотрудников не шифруются.

Использование встроенных функций в настраиваемом отчете приводит к значительному замедлению скорости формирования отчета.

6) В коде функции столбца может встретиться конструкция типа  
_ListElem.<имя поля>_  
Она означает получение данных указанного параметра из массива, отобранного настраиваемым отчетом.  
Например, выражение _ListElem.person\_id_ в рассматриваемом нами примере выдает значение ID сотрудника, завершившего тест, и соответствует выражению _{person\_id}_.
