## Особенности разработки удаленных действий

Под **удаленными действиями** подразумеваются действия, связанные с добавлением, изменением, сохранением и удалением различных объектов в системе. Все действия из XAML-шаблонов должны реализовываться через объект **Удаленное действие** в блоке **Дизайнер - Удаленные действия**.

Основные возвращаемые переменные объекта **Удаленное действие**:  
_ERROR (целое число) – номер ошибки;  
MESSAGE (строка) – текст сообщения;  
RESULT (объект) – результат действия._

Файлы программ удаленных действий находятся в папке _WebSoftServer\\wt\\web_.  
Например, удаленному действию **Добавление вакансии в избранные** соответствует программный файл _view\_add\_vacancy\_to\_selected\_action.bs_.

Простой пример программного кода удаленного действия:

RESULT = {"id": 1, "name": "имя"};  
ERROR = 0;  
MESSAGE = "Удачное завершение!";

Начиная с релиза 2023.2 реализована передача переменных в окно, открывающееся по команде open\_doc удаленного действия. Переменные можно передать через объект wvars результата действия.  
Для более ранних релизов доступен специальный патч, позволяющий испрользовать данную функциональность.  
  
wvars – объект параметров, который будет передан в открывающееся окно документа, аналогичен объекту SCOPE\_WVARS. Для извлечения данного объекта в коде экранной формы (xms) необходимо использовать вызов функции SCOPE\_WVARS = ms\_tools.get\_doc\_screen\_wvars ( TopElem.Doc ).  
Переменные можно передать через объект wvars результата действия:

RESULT = {  
        command: "open\_doc",  
        doc\_id: OBJECT\_ID,  
        is\_dialog: false,  
        is\_edit: true,  
        catalog\_name: 'event',  
        form\_url: "x-local://wtv/ui\_forms/event\_simple.xms",  
        wvars: {  
                code: "123",  
                type: \[1,2,3\]  
        }  
}

  
С помощью специальной функции _ms\_tools.get\_doc\_screen\_wvars( TopElem.Doc )_ можно получить переменные в том виде, как они были заданы (объект со свойствами).  
В коде удаленного действия можно просто указывать _wvars = SCOPE\_WVARS_.  
Имеются следующие ограничения: если окно открывается в диалоге, то переменные могут быть любого типа и доступны в любой  момент. Но если указано значение переменной _is\_dialog = false_, то в коде, который работает до формирования окна (_BEFORE-INIT_) доступны только значения, имеющие тип примитивов (строка, число). Переменные комплексного типа (объект, массив) доступны только в коде внутри формы или в коде событий. Например, массив type может быть задан в любом коде, если окно в формате диалога (_is\_dialog = true_), или в событии _SET-VALUE-ACTION_, если окно не в формате диалога (_is\_dialog = false_).

Начиная с релиза 2023.2 в формах диалогов удаленных действий реализованы возможности:  
\- Многоколоночной компоновки.  
\- Расширенной компоновки формы: склеивания колонок и строк. Это сделано для того, чтобы таблицу можно было более гибко настраивать. Например, часть формы отображается в две колонки, а часть - в одну колонку.  
\- Задания формул скрытия/показа колонок и строк (для динамической перерисовки без запроса на сервер).  
\- Поддержки массивов - использования нескольких наборов значений, каждый элемент которого может состоять из нескольких полей.  
\- Поддержки вкладок - поля формы могут быть распределены по нескольким вкладками. 

Начиная с релиза 2023.2 реализована поддержка произвольного числа колонок в таблицах в формах удаленных действий:  
\- В описании поля параметр column теперь можно указать любое число.  
\- Добавлено объединение ячеек.  
\- Поле таблицы может быть растянуто на всю ширину диалога.  
\- Если указан атрибут span (число), то поле растягивается на указанное число ячеек.  
\- Если в строке нет поля с нужной колонкой и на него не распространяется атрибут span, то отображается пустая ячейка.  
\- Если задан массив с указанием ширин колонок, то используются эти значения, в противном случае отображаются все колонки одинаковой ширины.
