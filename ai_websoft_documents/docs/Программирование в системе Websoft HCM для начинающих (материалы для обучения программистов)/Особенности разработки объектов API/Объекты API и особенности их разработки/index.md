## Объекты API и особенности их разработки

Опытные и внимательные пользователи, наверное, заметили, что в 2020-2021 гг. система поменяла свое название с «**WebTutor**» на «**Websoft HCM**». Это изменение не было случайным.  
Сокращение **HCM** в названии дословно переводится, как _«Управление человеческим капиталом» (Human Capital Management)_. Теперь система позволяет отображать весь жизненный цикл сотрудника – от подбора до увольнения.   
С программной точки зрения, основными целями трансформации являются:  
\- отделение интерфейса от бизнес-логики;  
\- независимость системы от используемого устройства (в том числе – мобильного);  
\- унификация и возможность повторного использования бизнес-логики во всех видах интерфейсов (в частности, с помощью функций (методов), описанных в библиотеках программного кода);  
\- возможность доступа ко всем функциям системы через программный интерфейс приложений API (с помощью собственно, приложений, выборок, показателей и удаленных действий);  
\- повышение безопасности системы.  
  
**Документирование** новых функциональностей производится в вики-базах «**WebSoft HCM. Функциональная часть**» (в особенности, подразделы «**Документация по бизнес-процессам**», «**Документация по приложениям**» и др.) и «**Разработка на платформе WebSoft HCM**» (в частности, описание функций (методов) библиотек программного кода).

В составе Websoft HCM выделяются следующие составные части:  
\- ядро системы;  
\- бизнес-логика системы;  
\- фронтенд системы;  
\- бизнес-логика заказчика;  
\- фронтенд заказчика.  
Последние два элемента позволяют потребителю реализовать собственные решения и разработки, отличающиеся от «коробочных».  
   
В структуру системы Websoft HCM, так же, как и ранее, заложен принцип открытого кода – весь коробочный код, за исключением ядра системы, открыт и доступен для просмотра.   
В следующих разделах мы будем рассматривать, как правило, бизнес-логику системы (бэкенд), программный код которой написан, преимущественно, на языке программирования Server Side Java Script. 

В настоящее время обращение к данным системы производится с помощью трех типов компонентов (которые обобщенно можно назвать «объектами API»):  
\- Выборки;  
\- Показатели;  
\- Удаленные действия.  
В процессе реализации данных компонентов обычно используются функции (методы) библиотек программного кода.  

В настоящем разделе перечислим основные особенности трех указанных компонентов, которые далее будут описаны более подробно.  
**Выборки** производят отбор объектов системы для их последующего отображения на портале или в других интерфейсах системы. Выборки возвращают набор данных, который в дальнейшем может использоваться для формирования списков, таблиц, диаграмм, графиков и т.д. Выборкой, например, является функционал для подготовки списка сотрудников подразделения, перечня кандидатов на вакантную должность или результатов прохождения сотрудником учебной программы.  
**Показатели** – это статистические характеристики, вычисляемые по заранее заданному алгоритму. Показатели обычно возвращают некоторое число или объект. В качестве примеров показателей можно привести процент прохождения курса или теста, уровень квалификации сотрудника, количество набранных сотрудником призовых баллов и т.д.   
**Удаленные действия** – это операции, связанные с добавлением, изменением, сохранением и удалением объектов, и другие действия пользователя системы. Примеры удаленных действий – запуск функционала тестирования сотрудника, деактивация учетных записей уволенных сотрудников или формирование заявки на отпуск.

Указанные объекты API в программе администрирования системы Websoft HCM перечислены в разделах модуля **Дизайнер**.  

На следующих скриншотах приведены примеры использования выборок, показателей и удаленных действий на странице портала и в приложении.

Объекты API могут характеризоваться:  
_\- входными параметрами_ (параметрами объекта, из которого вызывается данный объект API), параметрами процесса и параметрами страницы (способ формирования страниц при отображении объекта, способ сортировки и т.д.). Для задания входных параметров удаленного действия может быть разработана программистом специальная форма, которая генерируется программным кодом удаленного действия;  
_\- программным кодом_ (который может быть распределен между собственно объектом и библиотекой (библиотеками) программного кода);  
_\- выходными параметрами_ (которые могут быть связаны с соответствующими переменными интерфейса).

Программный код объекта API может выполнять следующие действия:  
\- подготовку данных для корректной реализации функциональности объекта;  
\- вызов функций библиотек программного кода;  
\- генерацию экранных форм;  
\- вывод результата (выходных параметров) в интерфейсные переменные и т.д.

Программный код функции библиотеки может реализовывать:  
\- бизнес-логику выборок и показателей;  
\- активную часть удаленных действий;  
\- элементы веб-сервиса.

Вызов функции библиотеки программного кода из программного кода объекта API реализуется следующим образом:  
**tools.call\_code\_library\_method( "название\_библиотеки", " название\_библиотечной\_функции", \[список\_входных\_параметров\] )**

Примечание – Все функции библиотек программного кода (независимо от наименования этих библиотек), как правило, доступны для вызова из объекта API. Объекты API могут использовать несколько функций из одной библиотеки или из нескольких библиотек программного кода.
