## Интеграционное тестирование в Websoft HCM

Интеграционное тестирование – это проверка объектов системы Websoft HCM, таких как удаленные действия, выборки и показатели, а также функции библиотек программного кода, к которым обращаются эти объекты.

Тестировать объекты системы Websoft HCM или функции библиотек программного кода можно с помощью отдельных тестов или целых наборов таких тестов. Набор тестов программного кода может содержать любое количество тестов, которые потом будут запускаться подряд и, тем самым, с разных сторон проверять один и тот же объект или сразу много объектов. При добавлении тестов в набор можно применять заранее подготовленные наборы параметров тестов – часто используемые однотипные проверки объектов WebSoft HCM и функций библиотек программного кода.

После выполнения каждого теста или набора тестов формируются результаты выполнения. Если какой-либо тест выполнен неуспешно, можно открыть его результат и посмотреть, какая именно произошла ошибка.

В настоящий момент в системе реализована возможность проверки выборок, показателей и функций библиотек при создании тестов программного кода. Проверка удаленных действий появится в ближайшее время.

Для лучшего понимания, что представляют собой интеграционные тесты, рассмотрим примеры их создания в интерфейсе администратора. Вы можете повторить последовательно все шаги с нуля или скачать готовые пакеты, приложенные в конце статьи.

## **Пример создания теста программного кода для выборки «Тест / Действия теста»**

Выборка «Тест / Действия теста» возвращает список действий для теста, которые может произвести сотрудник при определенных условиях («начать», «продолжить», «создать заявку» и пр.).

Предположим, что сотруднику Анисимову Геннадию назначен тест «Занимательная география». Протестируем действия сотрудника для этого теста. В данном случае Геннадию доступны кнопки **Начать** и **Завершить** тестирование.

Для создания интеграционного теста в интерфейсе администратора перейдем в раздел **Тесты программного кода** блока **Дизайнер** и нажмем кнопку **Новая запись**. В открывшейся карточке теста программного кода выполним:

1.  В разделе **Общие сведения** в раскрывающемся списке **Выбор объектов** выберем _Выборка \[remote\_collection\]_.
2.  В появившемся поле **Выборка** с помощью кнопки  выберем _Тест / Действия теста_. После чего автоматически заполнится название создаваемого теста программного кода. При необходимости это название можно изменить.
3.  Добавим в тест программного кода с помощью кнопки  необходимые проверки данных, возвращаемых выборкой:
    
    1.Проверка на ошибки:
    
    •
    
    в открывшейся форме **Редактирование записи** укажем название проверки, например, _Наличие ошибки_;
    
    •
    
    в раскрывающемся списке **Тип проверки** выберем _Проверка на номер ошибки_;
    
    •
    
    в раскрывающемся списке **Тип эталона** выберем _Integer_;
    
    •
    
    в поле **Эталон** запишем значение _0_. Если после проверки выборка вернет 0, значит, результат ее работы положительный.
    
    2.Проверка на тип возвращаемого значения:
    
    •
    
    в открывшейся форме **Редактирование записи** укажем название проверки, например, _Тип возврата_;
    
    •
    
    в раскрывающемся списке **Тип проверки** выберем _Проверка на тип возврата_;
    
    •
    
    в раскрывающемся списке **Тип эталона** выберем _String_;
    
    •
    
    в поле **Эталон** запишем значение _array_.
    
    3.Проверка на наличие полей, возвращаемых выборкой (поля перечислены в разделе **Параметры API** карточки выборки «Тест / Действия теста»):
    
    •
    
    в форме **Редактирование записи** укажем название проверки, например, _Наличие поля id_;
    
    •
    
    в раскрывающемся списке **Тип проверки** выберем _Проверка на наличие поля с указанным именем в возврате_;
    
    •
    
    в раскрывающемся списке **Тип эталона** выберем _String_;
    
    •
    
    в поле **Эталон** запишем значение _id_;
    
    •
    
    аналогично добавим проверки на наличия полей _title_ и _action\_id_.
    
    4.Проверка на наличие кнопок «Начать» и «Завершить» тест на Портале (подразумевается, что сотруднику уже назначен тест):
    
    •
    
    в открывшейся форме **Редактирование записи** укажем название проверки, например, _Наличие кнопок «Начать» и «Завершить»_;
    
    •
    
    в раскрывающемся списке **Тип проверки** выберем _Проверка на наличие в возврате указанных значений_;
    
    •
    
    в поле **Проверяемый параметр** запишем _title_;
    
    •
    
    в раскрывающемся списке **Тип эталона** выберем _JSON_;
    
    •
    
    в поле **Эталон** запишем _\["Начать","Завершить"\]_.
    
4.  Перейдем в раздел **Параметры** и в поле **Сотрудник** с помощью кнопки  выберем Анисимова Геннадия, от лица которого будет проводиться тест.
5.  В раскрывающемся списке **Тип объекта** выберем _Тест \[assessment\]_ (аналогично типу объекта из карточки выборки «Тест / Действия теста»).
6.  В поле **Тест** с помощью кнопки  выберем тест «Занимательная география».
7.  Сохраним карточку теста программного кода.
8.  Нажмем кнопку **Запустить тест**.
    
9.  После прохождения всех внесенных в тест проверок появится всплывающее окно с результатами теста. Если ошибок нет, в последнем сообщении будет указано, что «Все проверки теста пройдены успешно». В противном случае – «Часть проверок теста не пройдено».  
    

## **Пример создания теста программного кода для выборки «Электронный курс / Курсы по категориям»**

Выборка «Электронный курс / Курсы по категориям» возвращает список курсов по категориям.

На этот раз протестируем выборку «Электронный курс / Курсы по категориям» на количество возвращаемых курсов без учета категорий и архивных курсов. Начнем с исходных данных, которые будут учитываться при создании теста программного кода. Для этого в интерфейсе администратора перейдем в раздел **Электронные курсы** блока **Дистанционное обучение**, выключим кнопку **Показ категорий** и посмотрим, сколько курсов находится в системе. В нашем примере содержится 15 электронных курсов, один из которых архивный. Применим эти данные далее.

Для создания нового теста нажмем кнопку **Новая запись**. В открывшейся карточке теста программного кода выполним:

1.  В разделе **Общие сведения** в раскрывающемся списке **Выбор объектов** выберем _Выборка \[remote\_collection\]_.
2.  В появившемся поле **Выборка** с помощью кнопки  выберем _Электронный курс / Курсы по категориям_. После чего автоматически заполнится название создаваемого теста программного кода. При необходимости это название можно изменить.
3.  Добавим в тест программного кода с помощью кнопки  необходимые проверки данных, возвращаемых выборкой, например:
    
    •проверка на номер ошибки (эталон – 0);  
    •проверка на тип возвращаемого значения (эталон – array);  
    •проверка на количество элементов возврата (эталон – 14 курсов, потому что всего в системе 15 курсов, один из которых – архивный).
    
    В проверке на количество элементов возврата необходимо установить столько курсов, сколько находится в системе (не архивных), независимо от того, повторяете вы инструкцию по шагам или распаковали приложенный пакет. Иначе, если количество курсов в вашей системе не совпадет с числом, указанным в этой проверке, тест завершится с ошибкой.
    
4.  Перейдем в раздел **Параметры** и в поле **Сотрудник** с помощью кнопки  выберем Анисимова Геннадия, от лица которого будет проводиться тест.
5.  Добавим переменные, соответствующие выборке «Электронный курс / Курсы по категориям». Переменным, отвечающим за возврат архивных курсов и игнорирование категорий, установим значение «Да».
6.  Сохраним карточку теста программного кода.
7.  Нажмем кнопку **Запустить тест**.
    
8.  После прохождения всех внесенных в тест проверок появится всплывающее окно с результатами теста. Если ошибок нет, в последнем сообщении будет указано, что «Все проверки теста пройдены успешно».
    
9.  Установим переменной **bExcludeArchiveCourses** значение «Нет» (чтобы тест возвращал архивные курсы), сохраним карточку теста и запустим тест. В этом случае он завершится с ошибкой, так как архивные курсы тоже будут учитываться и общее количество курсов увеличится.
