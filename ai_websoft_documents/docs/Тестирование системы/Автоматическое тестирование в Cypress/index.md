## Автоматическое тестирование в Cypress

Cypress – это инструмент для модульного, интеграционного и EndToEnd тестирования пользовательского интерфейса, созданный для современного веба. В его основе лежит Node.js, а код автотестов пишется на языке JavaScript.

Cypress имеет браузерный движок – именно браузер будет исполнять код и алгоритмы, написанные в тесте. Это позволяет Cypress отслеживать и менять поведение браузера прямо во время выполнения автотестов, манипулируя DOM-деревом и элементами.

Один из способов запуска тестов – приложение Cypress с использованием **графического режима (UI)**, которое позволяет выбрать сценарий для выполнения и наблюдать за его прохождением в реальном времени, а также исследовать результаты и заниматься отладочными мероприятиями.

Также Cypress предоставляет возможность запускать сценарии **без графического интерфейса** в «тихом», или «безголовом» (headless), режиме через командную строку. Этот режим подходит для интеграции Cypress в конвейеры инструментов CI/CD.

По завершении тестирования Cypress может формировать видеозапись процесса выполнения сценария. По умолчанию эта опция выключена. Чтобы включить видеозапись выполнения сценария обратитесь к официальной документации Cypress.

Для проведения тестирования должны быть установлены IDE (например, Visual Studio Code), Node.js и Cypress. Если Cypress и Node.js не установлены, необходимо обратиться к официальной документации Cypress.

Cypress поддерживается браузерами:

*   Chrome (включая Microsoft Edge на основе Electron и Chromium);
*   WebKit (движок браузера Safari);
*   Mozilla Firefox.

Для наглядности разберем на простом примере создание сценария, запуск Cypress в графическом и «тихом» режимах, а также получение результатов тестирования. Более сложные примеры сценариев смотрите здесь.

## **Подготовка сценария тестирования**

Рассмотрим сценарий, в котором сотрудник Анисимов Геннадий авторизуется на Портале и переходит на главную страницу. При этом будем проверять наличие на страницах соответствующей информации.

Пройдемся по сценарию:

1.  Посетим страницу '/default':
    
    1.
    
    Проверим наличие сообщения о необходимости ввести логин и пароль.
    
    2.
    
    Проверим наличие кнопок **Сбросить пароль** и **Регистрация**.
    
    3.
    
    Введем логин и пароль в соответствующие поля.
    
    4.
    
    Нажмем кнопку **Вход**.
    
2.  Перейдем на страницу '/home':
    
    1.
    
    Проверим отображение имени и фамилии вошедшего на Портал сотрудника Геннадия Анисимова.
    
    2.
    
    Проверим приветственные сообщения.
    
    3.
    
    Проверим пункты главного меню.
    

Код сценария нашего примера приложен в конце статьи и доступен для скачивания. Чтобы воспроизвести сценарий, извлеките файл _login\_home.cy.js_ из архива и положите его в папку с любым вашим проектом Cypress. Не забудьте в файле конфигурации _cypress.config.js_ в параметре **baseUrl** указать адрес сервера и протокол для доступа через Web, например, _https://myserver:7000_.

Код сценария содержит информацию:

1.  Объявление необходимых констант используемых для проверки соответствующих данных на страницах '/default' и '/home' Портала.
    
    `const **entrancePageText** = 'Для начала работы с HR-порталом WebSoft HCM введите логин и пароль, которые вы получили в письме'   const **welcomeMessage** = 'Добро пожаловатьна HR-портал!'   const **homePageMessage** = 'Здесь вы найдете лучшие инструменты для развития своих навыков и компетенций, повышения эффективности своей работы и взаимодействия с коллегами. Желаем удачи!'   const **collLogin** = 'ag'   const **collPass** = 'ag'   const **collName** = 'ГеннадийАнисимов'   const **topMenu** = ['Сообщество', 'Сервисы', 'Знания', 'Обучение', 'Команда']`
    
2.  Блок тестов «Вход на портал».
    
    `describe('Вход на портал', () => {...}`
    
3.  Хук, выполняющий команду посещения стартовой страницы '/default' перед выполнением каждого из кейсов.
    
    `beforeEach(() => {     cy       .visit('/')   })`
    
4.  Кейс «Проверка страницы авторизации», содержащий:
    
    •
    
    проверку содержания '/default' в url;
    
    •
    
    проверку наличия сообщения о необходимости ввести логин и пароль (в соответствии с константой **entrancePageText**);
    
    •
    
    проверку наличия кнопки «Сбросить пароль»;
    
    •
    
    проверку наличия кнопки «Регистрация».
    
    `it('Проверка страницы авторизации', () => {           // Проверка содержания '/default' в url           cy               .url()               .should('include', '/default')           // Проверка наличия сообщения о необходимости ввести логин и пароль           cy               .get('#WT_0x5F633EFD2A482C67')               .should('contain', entrancePageText)               .and('be.visible')           // Проверка наличия кнопки 'Сбросить пароль'           cy               .get('#WT_0x5F8397333E973DE3')               .should('contain', 'Сбросить пароль')               .and('be.visible')           // Проверка наличия кнопки 'Регистрация'           cy               .get('#WT_0x5F839B6822890DCB')               .should('contain', 'Регистрация')               .and('be.visible')       })`
    
5.  Кейс «Авторизация. Проверка элементов главной страницы Портала», содержащий:
    
    •
    
    ввод логина в соответствующее поле (значение берется из константы **collLogin**);
    
    •
    
    ввод пароля в соответствующее поле (значение берется из константы **collPass**);
    
    •
    
    нажатие кнопки **Вход**;
    
    •
    
    проверку содержания '/home' в url;
    
    •
    
    проверку отображения имени и фамилии вошедшего на Портал сотрудника (в соответствии с константой **collName**);
    
    •
    
    проверку приветственных сообщений (в соответствии с константами **welcomeMessage** и **homePageMessage**);
    
    •
    
    проверку пунктов главного меню (в соответствии с массивом **topMenu**).
    
    `it('Авторизация; Проверка элементов главной страницы портала', () => {           // Ввод логина в соответствующее поле           cy               .get('input[name="user_login"]').eq(1)               .type(collLogin)           // Ввод пароля в соответствующее поле           cy               .get('input[name="user_password"]').eq(1)               .type(collPass)           // Нажатие кнопки "Вход"           cy               .contains("Вход")               .click()           // Проверка содержания '/home' в url           cy               .url()               .should('include', '/home')           // Проверка отображения имени и фамилии, вошедшего на портал сотрудника           cy               .get('.username')               .should('contain', collName)               .and('be.visible')           // Проверка приветственных сообщений           cy               .get('.slider-main-header')               .should('contain', welcomeMessage)           cy               .get('.slider-small-header')               .should('contain', homePageMessage)           // Проверка пунктов главного меню           topMenu.forEach((item) => {               cy                   .get('.menu-main')                   .should('contain', item)                   .and('be.visible')           }       })`
    

## **Порядок выполнения сценария**

### Выполнение сценария в графическом режиме

Чтобы выполнить сценарий с использованием графического режима Cypress, выполним действия:

1.  Запустим Cypress в графическом режиме.
2.  Выберем необходимый сценарий (в нашем примере – _login\_home.cy.js_) из списка всех доступных сценариев и кликнем по его названию левой кнопкой мыши.
    
3.  Запустится автоматический процесс прохождения сценария, в котором будут выполнены действия:
    
    •
    
    посещение страницы '/default';
    
    •
    
    проверка содержания '/default' в url;
    
    •
    
    проверка наличия сообщения «Для начала работы с HR-порталом WebSoft HCM введите логин и пароль, которые вы получили в письме»;
    
    •
    
    проверка наличия кнопок **Сбросить пароль** и **Регистрация**;
    
    •
    
    посещение страницы '/default';
    
    •
    
    ввод логина и пароля в соответствующие поля;
    
    •
    
    нажатие кнопки **Вход** и последующее посещение страницы '/home';
    
    •
    
    проверка содержания '/home' в url;
    
    •
    
    проверка отображения имени и фамилии вошедшего на Портал пользователя: Геннадий Анисимов;
    
    •
    
    проверка наличия сообщения «Добро пожаловать на HR-портал!»;
    
    •
    
    проверка наличия сообщения «Здесь вы найдете лучшие инструменты для развития своих навыков и компетенций, повышения эффективности своей работы и взаимодействия с коллегами. Желаем удачи!»;
    
    •
    
    проверка пунктов главного меню: **Сообщество**, **Сервисы**, **Знания**, **Обучение**, **Команда**.
    
4.  По завершении тестирования получим результаты на экране Cypress, который состоит из двух фреймов: в одном фрейме открыта страница Портала '/home', в другом фрейме отображены успешно пройденные тесты и указано их количество.

### Выполнение сценария в «тихом» режиме

Чтобы выполнить сценарий в «тихом» режиме Cypress выполним действия:

1.  Откроем IDE (например, Visual Studio Code).
2.  В терминале введем команду, где _.\\cypress\\e2e\\WebSoft\\login\_home.cy.js_ – путь к сценарию относительно корневого каталога:
    
    `**npx cypress run** --spec **.\cypress\e2e\WebSoft\login_home.cy.js** --browser **chrome**`
    
3.  В этом случае выполнение сценария будет проходить без использования графического интерфейса, а результат работы отобразится в консоле.
    

### Пример неудачного выполнения сценария

Чтобы сценарий завершился неуспешно, фактическое содержимое любого элемента должно отличается от ожидаемого. Предположим, что нашего сотрудника зовут иначе. Для этого в коде сценария _login\_home.cy.js_ изменим соответствующую константу:

`const **collName** = 'ГенаАнисимов'`

В таком случает первый тест завершит свою работу успешно, а при выполнении второго теста вызовется ошибка и он завершится неуспешно.
