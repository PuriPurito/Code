## Тестирование системы

Для начала немного теории. Тестирование – это проверка соответствия ожидаемых и реальных результатов поведения системы, проводимая на различных наборах автоматических и ручных тестов.

Для чего нужно тестировать систему?

*   для проверки соответствия системы предъявленным требованиям;
*   для обнаружения возможных ошибок на этапах разработки и обновления системы;
*   для проверки корректной работы компонентов и всей системы в целом;
*   для имитации поведения пользователя в системе с целью выявления возможных ошибок.

Все виды тестирования можно условно разделить на функциональное и нефункциональное.

**Функциональное тестирование** рассматривает заранее указанное поведение системы и имитирует фактическое ее использование. В настоящий момент мы представляем себе функциональное тестирование в виде пирамиды, состоящей из трех уровней:

1.  Фундамент пирамиды – интеграционные тесты, которые предназначены для тестирования бэкенда. Эти тесты встроены в систему и разработаны компанией WebSoft адресно для обеспечения контроля качества системы специализированными средствами. В тесты заложен широкий спектр возможностей с перспективой расширения. Интеграционные тесты выполняются в системе на уровне функций и объектов WebSoft HCM и проверяют работу единицы компонента (выборки, показателя) при разных условиях.
2.  В центре пирамиды автоматические регрессионные и smoke тесты, которые мы проводим с использованием фреймворка Cypress. На этом уровне выполняется набор EndToEnd тестов, с помощью которого тестируется весь user flow, а именно, тестируются все действия, которые пользователи могут выполнять в приложении. Процесс, настройка окружения и запуск тестов интегрированы в конвейер CI/CD и выполняются по расписанию.
3.  На вершине пирамиды стоят индивидуальные тесты, которые проводятся, в том числе, вручную. На этом этапе проверяется пользовательский интерфейс системы WebSoft HCM, простота и ясность взаимодействия пользователя с системой, корректная работа удаленных действий, выборок и показателей на Портале, а также лаконичность дизайна Портала.

К **нефункциональному тестированию** мы относим тестирование производительности, а именно, нагрузочное тестирование. Оно проводится для того, чтобы оценить поведение системы под заданной ожидаемой нагрузкой. Этой нагрузкой может быть, например, ожидаемое количество одновременно авторизующихся пользователей системы. Нагрузочное тестирование мы выполняем с помощью инструмента JMeter. Он представляет собой десктопное приложение с открытым исходным кодом на базе Java.

Для тестирования нашей системы мы выбрали представленные в статье инструменты. Вы можете последовать нашим примерам или выбрать для себя другие. К слову, EndToEnd тестирование мы проводим в Cypress из-за близкого нашей системе JavaScript. Вы можете использовать любой другой удобный инструмент, например, Selenium.
