## Нагрузочное тестирование в JMeter

Нагрузочное тестирование – это автоматизированное тестирование, имитирующее работу определенного количества пользователей на каком-либо общем ресурсе.

Мы выполняем нагрузочное тестирование с помощью инструмента JMeter, который был нами выбран по ряду причин:

*   бесплатный свободно распространяемый продукт с открытым исходным кодом;
*   прост в использовании, при этом он позволяет создавать сложные сценарии тестирования;
*   имеет все возможности, которые нам необходимы, в том числе, работу с WebSocket (при установке соответствующего плагина);
*   постоянно обновляется и имеет много документации, обучающих видео, инструкций, уроков, курсов.

JMeter позволяет определить, может ли тестируемая система удовлетворять требованиям высокой нагрузки или нет. Он также помогает проанализировать работу всего сервера под высокой нагрузкой.

Чтобы установить JMeter, обратитесь к официальному источнику. Там же вы найдете всю необходимую документацию по работе с JMeter.

Рассмотрим пример тестирования авторизации нескольких пользователей. Для этого мы проверим скорость загрузки страниц Портала, если одновременно, например, 4 пользователя, зайдут на страницу «/default», введут свои логины/пароли и перейдут на страницу «/home».

Чтобы приступить к тестированию, нужно составить план тестирования (**Test Plan**), описывающий серию шагов, которые JMeter выполнит при запуске.

Представленный в статье план тестирования – один из возможных вариантов получения ожидаемых результатов. Создавайте любой план тестирования в соответствии с вашими потребностями. В конце статьи приложен готовый проект, доступный для скачивания. Распакуйте архив и перетащите файл _forDoc.jmx_ в открытое окно JMeter. Файл _accounts.txt_ – это аккаунты сотрудников.

Рассмотрим пошагово пример выполнения нагрузочного тестирования:

1.  В **Test Plan** добавим **Test Script Recorder** и в его настройках пропишем порт, через который будет соединяться браузер с JMeter.
    
2.  Нажмем кнопку **Start**, после чего запустится прокси-сервер.
    
    Обратите внимание, в момент нажатия кнопки **Start** генерируется сертификат длительностью 7 дней, который необходимо импортировать в браузер, чтобы иметь возможность переходить по https ссылкам. 
    
3.  Откроем браузер Mozilla Firefox и настроим параметры соединения, указав такой же номер порта, который мы выбрали в JMeter.
    
    Для работы с JMeter удобнее всего использовать браузер Mozilla Firefox, потому что у него есть возможность настроить прокси не на всю систему в целом, а конкретно указать HTTP/HTTPS прокси и номер порта только для браузера Firefox. Поэтому после начала тестирования всё, что будет выполняться в Firefox, можно увидеть в **Test Script Recorder**.
    
4.  В браузере авторизуемся на Портале под любым пользователем, после чего сценарий, который мы прошли «вручную», запишется в **Recording Controller**.
5.  Остановим **Test Script Recorder**, нажав кнопку **Stop**.
    
6.  Найдем POST запрос, который авторизует пользователя, и изменим его название на «Авторизация» для удобства поиска результата тестирования. Здесь же в поле **Value** находится значение .json в закодированном виде, которое перехватил JMeter. Раскодируем это значение, например, в редакторе Notepad++, представив его в «читаемом» виде.
    
7.  В редакторе Notepad++ в объектах со значениями _"user\_login"_ и _"user\_password"_ ключей **"name"** заменим фактические значения ключей **"value"** переменными _"${user\_log}"_ и _"${user\_pass}"_, которые далее будем использовать при авторизации.
    
8.  Скопируем изменённый .json и заменим им значение в поле **Value**, указав, что это значение не закодировано.
    
9.  Создадим файл .csv или .txt, содержащий логины и пароли пользователей, которые будут одновременно проходить авторизацию на Портале. Пример файла (первая строка – заголовок):
    
    `user_log,user_pass   ag,ag   ln,ln   IF,IF   ms,ms`
    
10.  В элементе конфигурации **CSV Data Set Config**:
     
     •
     
     в поле **Filename** укажем файл, сохраненный на прошлом шаге;
     
     •
     
     в поле **Variable Names** запишем название созданных переменных;
     
     •
     
     в поле **Ignore first line** установим **True**, так как первая строка файла – заголовок;
     
     •
     
     в поле **Delimiter** запишем знак, разделяющий значения в файле.
     
11.  В запрос **Авторизация** добавим утверждение (Assertion) **Response Assertion** – это проверка на возвращаемое сервером значение. В нашем случае будем ожидать, что ответ от сервера содержит _"error":0_.
     
12.  Чтобы начать тестирование, выполним действия:
     
     •
     
     создадим в **Test Plan** ветку **Thread Group** и в поле **Number of Threads (users)** запишем значение _1_ (начнем проверку с одного пользователя);
     
     •
     
     перенесем в **Thread Group** весь пул запросов из **Recording Controller**;
     
     •
     
     создадим слушатель (Listener) **View Results Tree**, отображающий все запросы, которые отправил JMeter, и ответы от сервера;
     
     •
     
     создадим слушатель (Listener) **Summary Report**, который содержит таблицу с результатами пройденного тестирования по каждому запросу.
     
13.  Запустим сценарий от имени одного пользователя с помощью кнопки  и перейдем в слушатель **View Results Tree** для просмотра результатов запроса **Авторизация**:
     
     •
     
     во вкладке **Request** находится запрос, в который были подставлены первые значения переменных _${user\_log}_, _${user\_pass}_ из сохраненного ранее файла .csv или .txt, а именно, _ag_, _ag_.
     
     •
     
     во вкладке **Response data** находится ответ сервера:
     
     `{"error":0,"error_text":"","action_completed":"eval_action","result":{"command":"redirect","redirect_url":"/home"}}`
     
     •
     
     рядом с запросом **Авторизация** стоит зеленая галочка, так как ответ от сервера содержит значение, указанное в **Response Assertion** (_"error":0_).
     
14.  Запишем в **Response Assertion** отличное от эталона значение, например, _"error":1_. В таком случае запрос **Авторизация** завершится неудачно.
     
15.  Протестируем одновременную авторизацию четырех пользователей. Для этого в **Thread Group** в поле **Number of Threads (users)** запишем значение _4_ и запустим сценарий с помощью кнопки . В результате в слушателе **View Results Tree** появится четыре запроса **Авторизация**, в каждом из которых будут использованы логин/пароль из сохраненного ранее файла .csv или .txt.
     
16.  Перейдем в слушатель (Listener) **Summary Report** и посмотрим результаты прохождения тестирования запроса **Авторизация**.
     

## **Запуск JMeter в CLI Mode режиме** 

При запуске JMeter рекомендует использовать CLI Mode режим (ранее – NON-GUI), который позволяет запускать тесты без интерфейса. Он необходим в случае, когда проводятся реальные тесты на больших и сложных данных. Таким образом, процесс тестирования будет отличаться от описанного в статье лишь тем, что, создав сценарий, мы не будем нажимать кнопку , а запустим командную строку с нужными нам параметрами (о них можно почитать в официальной документации), в том числе с созданием web отчёта в виде html файла с результатами тестирования.

Пример команды:

`jmeter -n -t [jmx file] -l [results file] -e -o [Path to web report folder]`
