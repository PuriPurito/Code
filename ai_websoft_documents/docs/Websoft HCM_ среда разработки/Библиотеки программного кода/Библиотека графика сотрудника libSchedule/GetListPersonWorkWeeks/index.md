## GetListPersonWorkWeeks

Метод GetListPersonWorkWeeks предназначен для получения списка рабочих периодов сотрудника.

_Синтаксис (вызов из JS-кода):_  
      **tools.call\_code\_library\_method ("libSchedule", "GetListPersonWorkWeeks", <arrParams>)**

_Аргументы:_  
     _<arrParams> (обязательный)_  
      Тип: **Массив**. Массив, элементы которого будут переданы методу в качестве параметров. Порядок следования элементов в массиве должен соответствовать порядку параметров метода. Параметры могут быть перечислены через запятую, а весь массив - заключен в квадратные скобки.   
     Массив включает в себя восемь параметров:  
     _dInitDate_ \- исходная дата (дата). Если исходная дата не задана, то берется текущая дата (**Date()**).  
     _iWeekDay_ – индекс дня недели начала периода (целое число). Допустимые значения: _1_ (понедельник), _2_ (вторник), _3_ (среда), _4_ (четверг), _5_ (пятница), _6_ (суббота), 7 (воскресенье).  
     _iPeriodSize_ – продолжительность периода (задается в календарных днях (целое число).  
     _iPeriodsNext_ \- количество периодов учета вперед (целое число).  
     _iPeriodsPrev_ \- количество периодов учета назад (целое число).  
     _iPersonID_ \- ID сотрудника по которому делается отбор (целое число).  
     _sCollaboratorType_ \- тип сотрудников для отбора (строка). Допустимые значения: _'my', 'all', 'org', 'colleagues', 'subordinates'_.  
     _aPresenceState_ \- массив ID типов присутствия/отсутствия (массив целых чисел).

_Возвращаемое значение:_  
      Тип: **Объект**. Содержит перечень рабочих периодов сотрудника, а также ряд дополнительных атрибутов:  
\- _aPeriods_ \- массив рабочих периодов сотрудника (массив объектов).  
     Атрибуты отдельного объекта:  
     _id_ \- ID периода (строка).  
     _start\_period\_date_ \- дата начала периода учета (строка).  
     _end\_period\_date_ \- дата конца периода учета (строка).  
     _is\_project_ \- в периоде учета имеются графики со статусом _"Проект"_ (булево).  
     _is\_agreement_ \- в периоде учета имеются графики со статусом _"На согласовании"_ (булево).  
     _is\_active_ \- в периоде учета имеются графики со статусом _"В работе"_ (булево).  
     _status\_period\_date_ \- статус периода учета (строка). Если в периоде все графики всех сотрудников согласованы, то устанавливается статус _'Согласовано'_, в противном случае устанавливается статус _'На согласовании'_. Если графики в периоде отсутствуют, то в качестве статуса указывается пустая строка.  
     _person\_hours\_plan_ \- количество плановых человеко-часов (целое число). Если графики в периоде имеются, указывается суммарное значение по всем графикам всех сотрудников в периоде.  
     _person\_hours\_fact_ \- количество фактических человеко-часов (целое число). Если графики в периоде имеются, указывается суммарное значение по всем графикам всех сотрудников в периоде.  
     _str\_person\_hours\_plan_ \- количество плановых человеко-часов в текстовом формате (строка). Если графики в периоде имеются, указывается суммарное значение по всем графикам всех сотрудников в периоде.  
     _str\_person\_hours\_fact_ \- количество фактических человеко-часов в текстовом формате (строка). Если графики в периоде имеются, указывается суммарное значение по всем графикам всех сотрудников в периоде.

\- _error_ \- код ошибки (при отсутствии ошибок код равен 0) (целое число).  
\- _errorText_ – текст ошибки (строка).

_Пример:_

`_// Вызов метода с помощью функции_ _tools.call_code_library_method_   _oRes = tools.call_code_library_method ("libSchedule", "GetListPersonWorkWeeks", [dInitDate, iWeekDay, iPeriodSize, iPeriodsNext, iPeriodsPrev, iPersonID, sCollaboratorType, aPresenceState]);_` 

`_// Запись результата в основной журнал (лог) системы xhttp-<текущая_дата>.log   LogEvent('', EncodeJson(oRes));_`
