## GetSubordinateRecords

Метод **GetSubordinateRecords** предназначен для получения списка каталожных записей указанного каталога, связанных с подчиненными текущего сотрудника.

_Синтаксис (вызов из JS-кода):_  
      **tools.call\_code\_library\_method ("libMain", "GetSubordinateRecords", <arrParams>)**

_Аргументы:_  
     _<arrParams> (обязательный)_  
      Тип: **Массив**. Массив, элементы которого передаются методу в качестве параметров. Порядок следования элементов в массиве должен соответствовать порядку параметров метода.  
     Массив включает в себя два параметра:  
     _iPersonID_ \- ID руководителя (целое число).  
     _oParams_ \- объект с параметрами вызова функции (объект). Объект включает в себя следующие параметры (_arrTypeSubordinate_ \- массив типов отбора подчиненных (массив строк). Допустимые значения: _'func'_ \- функциональные, _'fact'_ - фактические (по должности или с типом «Непосредственный руководитель»); _bReturnIDs_ \- возвращать ли массив ID вместо массива каталожных записей (булево). Если _bReturnIDs=true_, то возвращается массив ID каталожных записей. В противном случае – собственно массив каталожных записей; _sCatalog_ – название каталога, из которого отбираются записи (строка). Если каталог не указан или указан каталог, не имеющий связей с сотрудниками, то результаты отбираются из каталога collaborators; _arrFieldsNames_ \- массив названий полей, которые возвращаются после выполнения функции (массив строк). Если названия полей не указаны, то возвращаются все поля; _xQueryCond_ \- фильтр дополнительного критерия отбора (XQuery-запроса) в целевом каталоге (строка); _bGetOrgSubordinate_ \- добавляются ли при поиска подчиненные по организациям (булево); _bGetGroupSubordinate_ \- добавляются ли при поиска подчиненные по группам (булево); _bGetPersonSubordinate_ \- добавляются ли при поиска персональные подчиненные (непосредственно по сотрудникам) (булево); bInHierSubdivision - выполняется ли поиск по всему дочернему поддереву подразделений (булево) (по умолчанию – true); _bGetGroupOutStaff_ - нужно ли добавлять сотрудников временного персонала, не привязанных к должности (булево); _bGetGroupCandidates_ \- нужно ли добавлять кандидатов, не привязанных к должности (булево); _arrBossTypeIDs_ \- массив ID типов руководителей для отбора по функциональному руководителю (массив целых чисел). При отборе по фактическому руководителю данный параметр не используется. Если данный массив является пустым, то производится отбор по всем типам функциональных руководителей; _bWithoutUseManagementObject_ – выполняется ли поиск без учета выбранного объекта управления (булево). Если значение параметра равно true, то поиск производится без учета выбранного объекта управления; _iManagementObjectID_ \- ID объекта управления, передаваемого для текущего вызова функции (целое число); _oSort_ - параметры сортировки (объект). Параметры объекта: _FIELD_ – наименование поля критерия сортировки (строка); _DIRECTION_ – направление сортировки (строка) (по возрастанию (_"ASC"_) или по убыванию (_"DESC"_) ).

_Возвращаемое значение:_  
      Тип: **Массив целых чисел**. Массив ID отобранных каталожных записей. 

_Пример:_

`_// Вызов метода с помощью функции_ _tools.call_code_library_method_   _oRes = tools.call_code_library_method ("libMain", "GetSubordinateRecords", [iPersonID, oParams]);_` 

`_// Запись результата в основной журнал (лог) системы xhttp-<текущая_дата>.log   LogEvent('', EncodeJson(oRes));_`
