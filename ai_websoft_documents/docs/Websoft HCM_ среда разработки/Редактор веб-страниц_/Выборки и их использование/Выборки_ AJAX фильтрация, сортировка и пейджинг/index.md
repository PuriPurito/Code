## Выборки: AJAX фильтрация, сортировка и пейджинг

### _AJAX_\-фильтрация

Основная задача при формировании фильтров, обрабатываемых на стороне сервера, - каким образом интерфейс фильтров получит коллекции entrys для полей типа «выбор из списка». Поскольку выбранные значения фильтров обрабатывает выборка то и коллекции эти должна формировать выборка.

Протокол таков:

1.  При первом вызове выборки в выборку передается массив имен полей, для которых нужно сформировать entrys. Массив передается как строка, разделенная ";" в одном из параметров wvars с именем «**\_DISTINCTS**». При последующих вызовах (при обработке выбора фильтров) этот массив не передается.
2.  Если массив \_DISTINCTS не пуст, то в глобальной (по отношению к коду выборки) переменной DATA создается атрибут «**distincts**» типа JS-объект
3.  Выборка для каждого поля из \_DISTINCTS добавляет в DATA.distincts именованный именем поля из \_DISTINCTS атрибут с массивом entrys, состоящий из пар name/value. Получается примерно вот такое:  
    `{          "distincts": {                 "role_id": [                        {                              "name": "Без категории",                              "value": ""                        },                        {                              "name": "Личная эффективность",                              "value": 6951788226769129915                        },                        {                              "name": "Лидерство",                              "value": 6951788226769129916                       }                 ],                 "state_id": [                        {                              "name": "Назначен",                              "value": "0"                        },                        {                              "name": "В процессе",                              "value": "1"                        },                        {                              "name": "Завершен",                              "value": "2"                        }                 ]          }   }`
4.  Выбор значений фильтров сопровождается обращением к выборке с передачей в выборку выбраных значений
5.  Выбранные значения фильтров передаются в еще одном параметре wvars с именем «**\_FILTERS**».
6.  В переменной \_FILTERS передаются все выбранные фильтры в виде коллекции структур {id, name, type, value}, где
    1.  id – имя поля, по которому идет отбор
    2.  name – наименование поля
    3.  type – тип фильтра:
        1.  число – int
        2.  дата – date
        3.  выбор из списка – select
        4.  поиск - search (имя поля зарезервировано тоже - «search»)
    4.  value – выбранное в фильтре значение
7.  Для поля типа select в value возвращается массив объектов name/value, соответствующий выбранным entrys
8.  Для полей типа data и int возвращается интервал значений в виде двух полей value – «value\_from» и  «value\_to»

### _AJAX_\-сортировка

AJAX-сортировка включается вместе с AJAX-пейджингом и AJAX-фильтрами. Этот функционал должен выполняться перед AJAX-пейджингом, но после отбора в соответствии с входящими параметрами (в т.ч. AJAX-фильтрацией)

Информация для сортировки приходит в стандартном объекте SORT, имеющем свойства FIELD – имя поля, по которому нужна сортировка и DIRECTION – направление сортировки.

У AJAX-сортировки есть концептуальная сложность, связанная с тем, что собственно процесс сортировки оптимально делать в XQuery, но набор имен полей, по которым может понадобиться сортировка, определяется при финальном формировании набора записей выборки. И между полями финального набора и полями, доступными в запросе XQuery может не быть даже опосредованной связи. Поэтому AJAX-сортировка – довольно творческая задача.

### _AJAX_\-пейджинг

AJAX-пейджинг используется для постраничного вывода коллекции в интерфейсе с формированием страницы на стороне сервера. Помимо собственно вывода он позволяет на больших коллекциях на порядки уменьшить время финального формирования записей – вычисления значения полей в финальную выдачу выборки. Для достижения такого эффекта страница пейджинга должна «отрезаться» после отбора в соответствии со значениями фильтров и после сортировки, но до формирования финального набора записей. То есть «отрезание» окна пейджинга должно являться предпоследней операцией в функционале выборки.

Информация для пейджинга приходит в стандартном объекте PAGING. Для запуска обработки пейджинга в выборке необходимо установить свойство объекта MANUAL в true, установить значение свойства TOTAL – общее количество записей (еще и поэтому пейджинг – предпоследняя операция) и отрезать страницу в соответствии с INDEX и SIZE.

Для сортировки и пейджинга желательно использовать штатную функцию библиотеки Main.

tools.call\_code\_library\_method( 'libMain', 'select\_page\_sort\_params', \[ array, PAGING, SORT \] );

При этом сортировку внутри функции делать стоит только тогда, когда выборка гарантировано небольшая или когда сортировать внутри XQuery нет возможности. А так – order by внутри XQuery, а в функцию вместо SORT отправлять пустой объект :

oPagingResponse = tools.call\_code\_library\_method( 'libMain', 'select\_page\_sort\_params', \[ xarrFinishedCourses, PAGING, ({}) \] );)
