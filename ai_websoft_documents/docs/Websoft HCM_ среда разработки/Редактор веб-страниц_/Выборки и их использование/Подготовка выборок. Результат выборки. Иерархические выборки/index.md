## Подготовка выборок. Результат выборки. Иерархические выборки

Для того, чтобы выборку можно было использовать в виджетах с заполнением из базы данных она должна обладать следующими обязательными свойствами:

1.  Результат выборки должен представлять из себя JSON-объект стандартной структуры, содержащей массив элементов 
2.  Поля элемента выборки, предназначенные для прямого использования в виджете, должны быть описаны в поле «Поля результата» карточки выборки.

Опционально можно задать для выборки **Тип объекта** - это упростит ее выбор в редакторе для страниц с тем же базовым объектом.

Опционально выбоорка может принимать на вход параметры, определяемые как переменные шаблона (**wvars**). Если они определены, параметры будут показаны в редакторе как параметры выборки. На примере ниже видно, что выборка связана с типом объекта Wiki статья и для нее определен ряд входных параметров разных типов.

### Формат результата выборки

Переменная, в которую надо записать результат выборки имеет фиксированное имя RESULT. Например:

`RESULT = tools.call_code_library_method( "libWiki", "get_wiki_article_childs", [ OptInt( iWikiArticleID, OptInt( sWikiArticleID, curObjectID ) ), iWikiArticleCommunicationTypeID, undefined, false, null, sQueryQual, bGetDesc, bGetAnnotation, bGetComment, bChangeNullPublicate, sSortField, sSortDirection ] ).array;`

RESULT представляет собой массив элементов. 

`RESULT = [ { id: 349283758674507546, … },  …  ]`

Массив _RESULT_ должен содержать объекты с обязательным свойством _id_, со свойствами, описанными в карточке выборки в поле "Поля результата", а также опционально может содержать другие неописанные свойства.

“id” – обязательное свойство (которое при этом не обязательно описывать в "Поля результата", оно всегда считается существующим и ключевым). Если у элементов выборки нет собственного id, нужно создать случайные уникальные id.

Свойства, описанные в "Поля результата", вставляются в виджет напрямую (через привязку полей виджета к полям коллекции в диалоге виджета) и являются обязательными, они не могут отсутствовать. Если они пусты, указывается пустое или дефолтное значение, но исключать их нельзя.

Неописанные свойства являются опциональными и могут использоваться только в текстовых подстановках на основе ITEM или кастомных JavaScript-обработчиках в локальных действиях.

### Типы свойств в элементе выборки

Описанные в "Поля результата" свойства ограничиваются типами данных, пригодных для показа в текстовом виде на веб-странице. Т.е. одномерными, приводимыми в итоге к _string_.

Для типа _date_ ожидается строка в формате ISO8601, но, если нужен показ даты в «человеческом» формате, возможно будет лучше преобразовать дату в строку нужного формата на стороне коллекции. Единственный виджет, который принимает формат ISO8601 и преобразует его самостоятельно – **Табличные данные** (где ISO8601 нужен для сортировки по дате). Для универсальности коллекции можно выводить в разные свойства дату с типом _date_ и свойство типа _string_ с текстовым форматом даты, предоставляя автору выбор.

Для типа _boolean_ будет использовано текстовое представление всюду, кроме виджета **Табличные данные**, где в строке таблицы будет показан чекбокс.

Дополнительные неописанные свойства могут иметь любые типы, которые можно использовать в JavaScript на стороне браузера.

### Особенности результата иерархических выборок

Элементы иерархических выборок (для использования в виджетах, строящих иерархические меню, деревья и оргструктуры) должны иметь дополнительное обязательное свойство _parent\_id_, содержащее _id_ родительского элемента. Для элементов верхнего уровня иерархии _parent\_id_ должен быть пуст.
