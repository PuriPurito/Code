## Команды для показа диалогов и форм (display_form, wizard, select_object, select_action, close_form)

Ответ удаленного действия может содержать команды для управления показом модального диалогового окна с формами.

## display\_form

Показывает диалоговое окно с формой с набором полей.

`RESULT =   {`

    `command: "display_form",       title: "Это заголовок окна",       message: "Опциональный текстовый блок в самом верху диалога - пояснение, инструкция",       css_class: "my-custom-class-1 my-custom-class-2",       width: "1000",       height: "600",       columns: [ 30, 30, 40 ],       tabs:       [            { id: "t1", name: "Tab 1", selected: true, columns: [ 30, 30, 40 ] },            { id: "t2", name: "Tab 2", selected: false, columns: [ 50, 50 ] }       ],       form_fields:       [            { name: "fld0", type: "hidden", value: "1" },            { name: "fld1", label: "String", type: "string", value: test_string, mandatory: true, validation: "nonempty", column: 1, css_class: "fld-custom-class", tab: "t1" },            { name: "fld2", label: "Integer", type: "integer", value: test_integer, mandatory: true, validation: "nonempty", column: 2, tab: "t2" }        ],        buttons:        [            { name: "submit", label: "Сохранить", type: "submit", submit_type: "m1", css_class: "btn-submit-custom" },            { name: "submit", label: "Сохранить и перейти", type: "submit", submit_type: "m2", css_class: "btn-submit-custom" },            { name: "cancel", label: "Отменить", type: "cancel", css_class: "btn-cancel-custom" }        ],        no_buttons: false   }`

`_**title**_ - текст заголовка диалогового окна`

_**message**_ \- первый текстовый блок окна, пояснение или инструкция

**_css\_class_** - класс(ы) CSS, которые будут добавлены к основным классам диалогового окна, контейнера поля или кнопки

_**width, height**_ - опционально, ширина и высота диалогового окна в единицах, приемлемых для показа в браузере или для интерпретатора действий административного клиента.  
_Единицы измерения._ Для показа в браузере: если параметр числовой - ожидается значение в пикселах, если параметр строковой - строка проверяется на наличие % и пересчитывается в пикселы по текущему размеру viewport, если это не проценты - строка отдается в диалог as is и будет интерпретирована диалогом "как получится". Для  интерпретатора действий административного клиента это могут быть любые поддерживаемые им единицы.

_**columns**_ - массив ширин колонок для данного диалога (числа), будет автоматически приведен к сумме 100%. Если этот параметр присутствует, то атрибут column у поля будет помещать его в колонку с этим номером (нумерация колонок начинается с 1)

_**tabs**_ - опционально, массив вкладок. Позволяет распределять поля по вкладкам, для чего в атрибуты поля добавляется _id_ вкладки: _id: "TAB\_ID"_. Опционально может содержать  атрибут _selected_, указывющий на изначально выбранную вкладку, а также опционально columns - массив ширин колонок для данной вкладки

_**form\_fields**_ \- массив описаний полей формы, правила его заполнения см. ниже

_**buttons**_ \- массив кнопок, поддерживаются три типа кнопок: _submit_ (нажатие на нее вызывает текущее удаленное действие с командой _submit\_form_), _draft_ (работает аналогично кнопке submit, но не проверяет обязательность заполнения полей перед отправкой на сервер) и _cancel_ (закрывает текущий диалог, данные на сервер не отправляются, выполнение действия прекращается). Кнопок типа submit может быть более одной - в этом случае каждая кнопка должна иметь атрибут _submit\_type_, который при отправке формы будет записан в массив полей как значение автоматически добавленного поля _\_\_submit\_type\_\__.

_**no\_buttons**_ \- массив кнопок может быть пустым, но при этом пустой блок кнопок диалогового окна все равно будет показан, для полного скрытия блока используйте эту переменную

## wizard

Показывает диалоговое окно с многостраничной формой.

Объект "Визард" в редакторе страниц вызывается в виде динамического диалога при помощи удаленного действия, возвращающего в RESULT команду: wizard.

Можно, например, реализовать вызов соответствующего удаленного действия на нажатие кнопки:

Структура данных RESULT, возвращаемых в удаленном действии, имеет следующий вид:

`RESULT = {`

    `command: "wizard",`

    `title: "",`

    `form_fields: [],`

    `pages: [],`

    `buttons: [],`

    `no_buttons: false`

`}`

где:

*   `command` \- это наименование команды, которая будет вызываться на стороне клиента. В данном случае это "wizard", вызывает создание объекта WTLPWizard, т.е. динамический диалог с заданным набором страниц/полей
*   `title` \- это заголовок диалога
*   `css_class` \- класс(ы) CSS, которые будут добавлены к основным классам диалогового окна
*   `form_fields` \- массив объектов, описывающих список полей нужного типа

    `form_fields: [ {  }, {  }, {  } ... ]`

    каждый объект - это набор свойств, описывающих заданное поле, например:

`{ name: "fld5", label: "Выпадающее меню", type: "select", value: test_select, entries: [ { name: "Value 1", value: "v1" }, { name: "Value 2", value: "v2" } ], page: "page_one" }`

1) `name` \- название поля на латинице

2) `label` \- название (лейбл) поля в самом диалоге

3) `type` \- тип поля из стандартного набора полей (select, integer, real, bool, file, string, date, text, foreign\_elem, hidden)

4) `value` \- значение, полученное из поля формы на клиенте. Описывается в переменных самого удаленного действия: 

5) `entries` \- массив объектов, описывающих возможные варианты объектов ключ/значение для данного типа поля select. Для других типов полей это свойство не применимо

6) `page` \- название страницы (page), на которой будет размещаться данное поле (порядок полей соответствует порядку, определенному в удаленном действии). Нужен для разделения набора полей на несколько "страниц" между которыми можно пошагово перемещаться. 

Находясь на первой странице нам доступна только одна кнопка "Далее". На всех других, кроме последней, доступны кнопки "Далее" и "Назад". На последней странице уже доступен набор кнопок, определенный в самом удаленном действии в свойстве buttons.

Помимо перечисленных, есть возможность определять дополнительные свойства у полей:

1) `mandatory` \- означает, что поле обязательно к заполнению (рядом с label соответствующего поля будет проставлена звездочка \*). Для поля типа bool будет означать, что должна быть проставлена галочка.

2) `validation` \- определяет тип проверки. Всего пока предусмотрено 3 типа проверки: 

\* number - проверка для полей типа real, integer. Если введенное в поле integer значение является не целочисленным или пустым, проверка вернет сообщение об ошибке. Если введенное в поле real значение является не целочисленным/ дробным или пустым, вернется сообщение об ошибке

\* `email` \- проверка для поля типа string, если поле не заполнено или не корректно, возвращается сообщение об ошибке

\* `nonempty` \- проверка на пустоту, если поле не заполнено, возвращается сообщение об ошибке

3) `error_message` \- текст сообщения об ошибке, который будет отображаться в случае некорректного заполнения поля

4)  `column` \- может быть либо 1, либо 2. Определяет ширину поля, занимает оно всю доступную ширину или 50% от доступной, т.е. два поля с column: 2 будут находится на одной строке

5)  `css_class` \- класс(ы) CSS, которые будут добавлены к основным классам диалогового окна

*   `pages` \- представляет собой массив объектов. Пока у объекта page одно свойство name:

`{ name: "page_one" }`

*   `buttons` \- массив объектов со следующими свойствами:

`{ name: "submit", label: "Сохранить", type: "submit" },`

`{ name: "cancel", label: "Отменить", type: "cancel"}`

`name` \- наименование кнопки

`label` \- ее наименование в форме:

`type` \- тип кнопки, определяет действие после нажатия

5) `visibility` \- массив объектов типа ключ/значение

`{ parent: "fld5", value: "v1" }`

`parent` \- это наименование родительского поля, значение которого определяет видимость текущего поля

`value` \- значение, которое должно быть у родительского поля parent для показа текущего поля

На текущем этапе предусмотрена проверка лишь по одному условию (объекту) массива visibility. Если этих условий будет несколько, то когда одно из них будет верно, поле отображается. Условия идут через "ИЛИ".Вариант с "И" пока не доступен и будет реализовываться уже по мере развития объекта "Визард". 

6) `no_buttons` \- свойство, определяемое в удаленном действии для вызова стандартной формы диалога. Если предусмотрено наличие кнопок, то всегда `false`

Пример удаленного действия, вызывающего Визард, прикреплен в файлах

## select\_object

Показывает стандартное диалоговое окно для выбора элементов из каталога. 

`RESULT =   {           command: "select_object",           catalog_name: "collaborator",           doc_id: "",           xquery_qual: "",           multi_select: true,           title: "Выберите сотрудников",           selected_object_ids: "6557979819734402999;6958979819734402969",` 

         disp\_hier\_view: true,

         disp\_tree\_selector: true,

                 page\_url: "",

                 page\_param: "",

                 flds\_dlg: ""

  
`}`

где:

*   `_title_ - текст заголовка диалогового окна, опциональный`
*   _catalog\_name_ \- название каталога для выбора, обязательный
*   _doc\_id_ - идентификатор документа - будет передан в диалог as is, опциональный
*   _xquery\_qual_ \- строка дополнительных условий для передачи в XQuery, будет передан в диалог as is, опциональный
*   _multi\_select_ \- флаг множественного выбора, опциональный, по умолчанию - единственный выбор.
*   _selected\_object\_ids_ \- строковой массив идентификаторов выбранных элементов, опциональный
*   disp\_hier\_view - показывать каталог в иерархическом виде (false - только в виде плоского списка, true - использовать иерархический вид, если каталог поддерживает иерархию)
    
*   disp\_tree\_selector - флаг, показывать чекбокс "В виде структуры" (true - показывать, если каталог поддерживает иерархию, false - не показывать в любом случае, если параметр disp\_hier\_view = false, то чекбокс не показывается никогда, параметр не учитывается)
    
*   page\_url - адрес кастомного диалога выбора объектов, если пусто - показывается стандартный шаблон с кодом dlg\_select
    
*   page\_param - строка параметров, будет передана в кастомный диалог выбора (через URL)
    
*   flds\_dlg - строка названий полей, через точку с запятой, значения которых будут переданы в кастомный диалог (через URL), можно передать значение "none", чтобы не передавать значения полей в диалог, если пусто или параметр отсутствует - то будут переданы полностью все поля формы
    

После подтверждения выбора пользователем вызывается то же самое действеи с командой _submit\_form_, обработка аналогична таковой при приеме данных от диалога формы, в массиве _form\_fields_ при этом содержатся элементы:

\- если был установлен параметр multiple: true

*   _selected\_object\_ids_ \- строковой массив идентификаторов выбранных элементов
*   _elemNamesArray_ \- stringified JSON-массив названий выбранных элементов

\- если был установлен параметр multiple: false

*   object\_id - идентификатор объекта, если это целое число (ID)
*   object\_str - код объекта, если используемая выборка возвращает уникальные ключи в виде строк (code|id)
*   object\_name - наименование выбранного объекта, возвращается выборкой/запросом (name|title)

Пример полной посылки при подтверждении множественного выбора:

`{"action":"eval_action","remote_action_id":"0x5E57C99D0F3E5AB9","command":"submit_form","form_fields":[{"name":"selected_object_ids","value":"6557979819734402999"},{"name":"elemNamesArray","value":"[\"Василий Пупкин\"]"}],"wvars":[] }`

при подтверждении единственного выбора:

`{"action":"eval_action","remote_action_id":"0x5E57C99D0F3E5AB9","command":"submit_form","form_fields":[{"name":"object_id","value":"6557979819734402999"},{"name":"object_str","value":"6557979819734402999"},{"name":"object_name","value":"Василий Пупкин"}]}`

если первичный ключ записей выборки - строка:

`{"action":"eval_action","remote_action_id":"0x5E57C99D0F3E5AB9","command":"submit_form","form_fields":[{"name":"object_id","value":null},{"name":"object_str","value":"code_1"},{"name":"object_name","value":"Элемент справочника 1"}]}`

## select\_action

Показывает простое модальное диалоговое окно для выбора действия из списка. 

`RESULT =   {           command: "select_action",           title: "Выберите действие",           actions:            [               { hex_id: "0x5E57C99D0F3E5AB9", title: "Действие 1", "wvars":[{"name":"_object_id","value":"0x555555555555555D"},{"name":"test_string","value":"6148914691236517121"},{"name":"test_bool","value":false},{"name":"test_select","value":"v1"}] },               { hex_id: "0x5E57C99D0F3E5AA6", title: "Действие 2", "wvars":[{"name":"test_string","value":"6148914691236517121"},{"name":"test_bool","value":true},{"name":"test_select","value":"v2"}], "form_fields":[{"name":"fld1","value":"6148914691236517121"}] }           ]`  
`}`

где:

*   `_title_ - текст заголовка диалогового окна, опциональный`
*   _actions_ \- массив удаленных действий для выбора, обязательный

Элемент массива:

*   _hex\_id_ - идентификатор действия, обязательный, 
*   _title_ \- название действия для показа в диалоге выбора, обязательный
*   _wvars_ \- массив wvars из исходного действия, будет возвращен ровно в том виде, в котором прислан из действия
*   _form\_fields_ \- массив полей из исходного действия, будет возвращен ровно в том виде, в котором прислан из действия

## close\_form

Закрывает диалоговое окно. В случае, если присутствует параметр _msg_ \- будет показано всплываеющее соощение с этим сообщением (_alert_).

`RESULT =`

`{       command: "close_form",       msg: "Данные сохранены"   }`

Альтернативно может содержать любые подчиненные команды в ветке _confirm\_result_  \- ветка будет обработана  как полноценный объект _result_.

`RESULT =`

`{       command: "close_form",       confirm_result:`

    `{`

        `command: "confirm",`  
        `msg: "Данные сохранены. Перегрузить страницу?",`  
        `confirm_result:`

        `{`  
            `command: "reload_page"`  
        `}`  
    `}   }`

## Описание полей

В массиве form\_fields поля описываются как объекты типовой структуры с двумя общими обязательными параметрами - name и type (для некоторых типов полей есть дополнительные обязательные). Например:

`{ name: "fld_file", type: "file" }`

### Опциональные общие параметры:

_label_ - название поля, которое будет показано пользователю

_value_ - начальное значение поля

_mandatory_ - признак обязательности заполнения

_validation_ \- сценарии проверки значений

_column_ \- поля можно распределить по колонкам, возможные значения 1 и 2

_disabled_ \- запрет редактирования если true

_css\_class_ \- класс(ы) CSS, которые будут добавлены к контейнеру поля

_title -_ текст подсказки при наведении на поле, транслируется в title контейнера поля. Исключение: поле типа foreign\_elem - там поддерживается title как название кнопки и title при наведении

### Типы полей

### hidden

Скрытое поле. Может быть удобно например для показа цепочки диалогов в одном действии.

`{ name: "fld_page", type: "hidden", value: "page1" }`

### string

Обычное текстовое поле.

`{ name: "fld1", label: "Название поля", type: "string", value: "Начальное значение", mandatory: true, validation: "nonempty", column: 1 }`

_maxlegth | max\_chars_ - максимальное число символов, которое можно ввести в поле

### text

Многострочное текстовое поле (textarea).

_maxlegth | max\_chars_ - максимальное число символов, которое можно ввести в поле (игнорируется для ричтекстового варианта)

Опциональный булевский параметр richtext включает показ ричтекстового редактора.

`{ name: "fld4", label: "Комментарий", type: "text", value: "", richtext: true, mandatory: true, validation: "nonempty" }`

Для ричтекстовго варианта доступны дополнительные опции:

*   _rte\_type = "inline|iframe"_ (по умолчанию inline) - режим с всплывающим тулбаром (удобно для небольших текстов), либо с постоянным тулбаром в изолированном iframe (удобнее для редактирования больших документов)
*   _rte\_config = "inline|wiki"..._ (по умолчанию inline) - вариант конфигурации редактора - состав кнопок на тулбаре, ограничения редактирования и т.п. В коробку добавлены два файла конфигурации (папка _wt/web/scripts/rte/ckeditor_ - c_onfig\_inline.js, config\_wiki.js_), дополнительные файлы могут быть добавлены по шаблону имени  
    config\_" + rte\_config\_param + ".js.  
    ВАЖНО: режим _inline_ имеет ограничения по использованию, не рекомендуется использовать в нем любые файлы конфигурации, кроме _inline_.
*   Для конфигурации _wiki_ для нормальной работы плагина _wiki\_link_ (вставка ссылки на документ внутри базы) дополнительно можно передать параметры:  
    catalog - каталог для показа в диалоге выбора (по умолчанию wiki\_article)  
    xquery\_qual - опциональные дополнительные условия по выборке

`{ name: "fld4", label: "Wiki-статья", type: "text", value: "", richtext: true, rte_type: "iframe", rte_config: "wiki", catalog: "wiki_article", xquery_qual: "status='active'" }`

### integer, real

Целое или действительное число

`{ name: "fld2", label: "Целое число", type: "integer", value: 44, mandatory: true, validation: "nonempty", column: 2 }`

`{ name: "fld3", label: "Действительное число", type: "real", value: 36.6, mandatory: true, validation: "nonempty", column: 1 }`

### date

Дата. Возвращает значение в формате ISO 8601. Начальное значение также должно  быть в этом формате.

`{ name: "flddate3", label: "Дата", type: "date", value: "2020-06-24", mandatory: true, validation: "nonempty", column: 2 }`

### file

Поле для передачи файла. Важно - в действие в этом поле передается не сам файл, а путь к файлу, сохраненному во временной папке сервера.

`{ name: "fld_file", label: "Добавьте фото", type: "file" }`

### bool

Флаг Да-Нет. Опциональный параметр view=flip|check - представление в виде флипбокса или чекбокса (по умолчанию флипбокс).

`{ name: "fld8", label: "Boolean", type: "bool", value: false, view: "check" }`

### select

Выпадающее меню с единственным выбором. Дополнительный параметр - массив entries для перечисления опций.

`{ name: "fld5", label: "Selector", type: "select", value: test_select, entries: [ { name: "Value 1", value: "v1" }, { name: "Value 2", value: "v2" } ] }`

### list

Список с множественным выбором. Начальное значение должно быть массивом. Дополнительные параметры - массив entries для перечисления опций и size - размер поля по вертикали в строках.

`{ name: "fld_list", label: "Multiselect (list)", type: "list", size: 10, value: ["v1"], entries: [ { name: "Value 1", value: "v1" }, { name: "Value 2", value: "v2" } ], mandatory: true, validation: "nonempty", column: 1 }`

### foreign\_elem

Выбор элемента из базы данных. Обязательный параметр - catalog. Опциональные параметры: query\_qual - дополнительные условия XQuery, которые будут переданы в диалог выбора, display\_value - текстовое значение для начального значения (при отсутствии будет показан ID), title - текст на кнопке, если значение не выбрано, _selected\_object\_ids_ \- строковой массив идентификаторов выбранных элементов, disp\_hier\_view - показывать каталог в иерархическом виде (false - только в виде плоского списка, true - использовать иерархический вид, если каталог поддерживает иерархию), disp\_tree\_selector - флаг, показывать чекбокс "В виде структуры" (true - показывать, если каталог поддерживает иерархию, false - не показывать в любом случае, если параметр disp\_hier\_view = false, то чекбокс не показывается никогда, параметр не учитывается), page\_url - адрес кастомного диалога выбора объектов, если пусто - показывается стандартный шаблон с кодом dlg\_select, page\_param - строка параметров, будет передана в кастомный диалог выбора (через URL), flds\_dlg - строка названий полей, через точку с запятой, значения которых будут переданы в кастомный диалог (через URL), можно передать значение "none", чтобы не передавать значения полей в диалог, если пусто или параметр отсутствует - то будут переданы полностью все поля формы

`{ name: "fld7", label: "DB Object", type: "foreign_elem", catalog: "collaborator", query_qual: "", value: 3050438886317795229, display_value: "Курвиметр", title: "Выберите элемент" }`

Для множественного выбора следует добавить булевский параметр multiple. Для дефолтных значений value при этом можно записать строку идентификаторов с разделителем ";", для текстовых значений display\_value - строку с разделителем "|||", например:

`{ name: "fld7", label: "DB Object", type: "foreign_elem", catalog: "collaborator", multiple: true, value: "3050438886317795229;1105387902724063521;1105387902724063519", display_value: "Значение 1|||Значение 2|||Значение 3" title: "Выберите элементы" }`

Для выбора объекта с использованием выборки следует добавить параметр collection со значением конкретной выборки и параметр collection\_params (переменные выборки) co строкой JSON с набором объектов-переменных в формате name - value (работает с версии 2023.2.1029). Например:

`{ name: "remote_action", label: "Выберите удаленное действие", type: "foreign_elem", catalog: 'remote_action', collection: 'GetRemoteActions', collection_params:" [ { name: 'sApplicationID', value: 'nameApp' }]", value: '', display_value: "", title: "Выберите элементы", multiple: true }`

### paragraph

Особый тип, в отношении которого не действуют общие параметры (кроме css\_class). Текстовый блок. Может содержать любой валидный HTML.

`{ name: "p1", type: "paragraph", value: "<h1>Hello!</h1>" }`

## Типы валидации

_nonempty_ - непустое значение

_number_ \- значение является числом

_date_ \- значение является датой

_email_ \- значение соответствует шаблону электронной почты.
