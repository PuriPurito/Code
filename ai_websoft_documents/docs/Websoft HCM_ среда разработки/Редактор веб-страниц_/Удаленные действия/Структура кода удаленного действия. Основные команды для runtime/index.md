## Структура кода удаленного действия. Основные команды для runtime

Каждый вызов удаленного действия сопровождается командой, транслируемой в переменную command. В настоящее время на вход принимается 3 команды: eval, eval\_action и submit\_form (eval\_action вызывается после выполнения confirm). Допускается отсутствие команды, что воспринимается как команда eval. Отличие действий только в том, что последнее действие подразумевает сохранение передаваемых в действие значений полей и передается в действие по заполнению диалога с формой или визарда. Таким образом, если действие универсально, стоит начать его код со _switch(command)._

В действии (при вызове действия через lpapi.html) доступны следующие глобальные объекты:

*   _curUser_
*   _curObject_ (если существует)
*   _Request_

### Входные параметры действия

Переменные, определенные как WVARS, передаются в действие as is, т.е. переменная WVAR _test\_string_ будет доступна как _test\_string_ и иметь соответствующий тип. Значение переменной будет равно либо определенному редактором страницы, либо, если содержит подстановки, будет заменено на актуальное значение подстановки. Поддерживаются как локальные, так и серверные подстановки.

### Передача значений полей в действие. Массив form\_fields

В случае если в виджете для удаленного действия добавлена опция "Передавать значения полей страницы в действие", а также при передаче команды submit\_form в переменные окружения будет добавлен stringified JSON массив _form\_fields_, содержащий объекты со свойствами name/value.

Для поля типа file значение value будет содержать путь к файлу, сохраненному во временной папке сервера.

Альтернативный способ передачи значений полей со страницы – через подстановку локальной переменной типа _FIELD_ в переменную WVAR действия. Этот способ имеет свои плюсы, поскольку передаются только нужные поля, причем в заранее известных переменных, но есть и ограничение: передать таким способом поле можно только через поля текстового типа: _string_ или _text_, т.е. возможно произойдет потеря типа данных (что нужно учитывать), а поле типа файл таким способом передать не получится совсем.

### Выдача результата. Объект RESULT

После выполнения всех нужных действий обязательно следует определить объект RESULT, который будет возвращен на страницу как ответ исполненного действия и обработан на стороне. Объект должен содержать команду для кода страницы и сопровождающие команду параметры. Например, самый простой вариант ответа для показа на странице алерта с нужным нам сообщением:

                `RESULT = {                       command: "alert",                       msg: sMsg,                       confirm_result: {                           command: "reload_page"                       }                   };`  
**Доступные команды и их параметры:**

*   _reload\_page_ – перезагрузить текущую страницу. Не имеет параметров.
*   _new\_window_ – открыть новое окно/вкладку по ссылке в параметре. Единственный обязательный параметр – _url_.  
    Опциональный параметр _on\_window\_close_ включает отслеживание существования дочернего окна и должен содержать команду, которая будет исполнена после его закрытия (аналогично _confirm\_result_). Независимо от наличия этого параметра, если url содержит **course\_launch.html, test\_launch.html, poll\_launch.html** отслеживание будет включено и по закрытию окна произойдет перезагрузка страницы (если по какой-то причине это поведение надо отключить, добавьте опциональный параметр _prevent\_watch: true_).  
    Опциональный параметр _alert\_on\_block_ (_true|false,_ по умолчанию _true_) – показывать предупреждение о блокировании открытия окна браузером. Дополнительно параметр _message\_on\_block_ может содержать текст сообщения, показываемого в случае, если настройки браузера блокируют открытие окна (если параметра нет – покажется текст по умолчанию).
*   _redirect_ – перейти на указанную в параметре _redirect\_url_ страницу. Опциональный параметр _no\_history=true|false_ для перехода без сохранения текущей страницы в истории браузера
*   _alert_ – показать алерт с сообщением в параметре _msg_ (может содержать HTML). Опциональный параметр _confirm\_result_ может содержать команду, которая будет исполнена после нажатия кнопки OK.
*   _confirm_ – показать сообщение с выбором Да-Нет, аналогично команде _alert_, но может иметь не только _confirm\_result_, но и _cancel\_result_.
*   _refresh_ – выполнить обновление одного или нескольких виджетов на странице. Для одного виджета ожидается параметр _hex\_widget\_id_ (обязательно в формате 0xHEX), для нескольких – ожидается параметр _hex\_widget\_ids_, содержащий массив идентификаторов. Также можно использовать boolean-атрибут _source\_widget_. При указании _source\_widget: **true**_ будет обновлен тот виджет, из которого было вызвано удаленное действие.

Команда _refresh не выполняется в приложениях админки_

*   _set\_field_ – установить значение для одного или нескольких полей. Для одного поля ожидаются параметры _fld\_name_ и _fld\_value,_ для многих – параметр _flds_, содержащий массив объектов вида _{ name: "somename", "value": "somevalue"}_.
*   _set\_variable_ – установить значение для одной или нескольких локальных переменных. Для одной переменной ожидаются параметры _var\_name_ и _var\_value,_ для многих – параметр _vars_, содержащий массив объектов вида _{ name: "somename", "value": "somevalue"}_.
*   select\_object – вызывает показ диалога выбора элеиментов из каталога
*   _display\_form_, _wizard, select\_object_, _close\_form_ – см. подробнее **Команды для показа диалогов с формами**
*   _sign_ – подписать документ, дополнительно ожидается получение объекта params со свойствами _doc\_url_ (адрес загрузки документа для подписи), doc\_name (имя документа), cert\_name (имя сертификата), info (комментарий)
*   _open\_doc_ (только при выполнении действия в приложении администратора) – открыть в интерфейсе карточку объекта, параметры вызова:
    *   doc\_id (идентификатор объекта),
    *   is\_dialog (true/false – открывать в диалоге или полном окне),
    *   is\_edit (true/false – открывать в режиме редактирования),
    *   catalog\_name (тип объекта – для определения экранной формы),
    *   form\_url (адрес размещения экранной формы, если нужно не стандартную форму для данного типа объекта, а свою),
    *   post\_action (объект, содержащий параметры действия, которое надо выполнить после закрытия окна документа, со свойствами:
        *   action – тип выполняемого действия, сейчас поддерживается только значение "lib",
        *   lib – код библиотеки программного кода,
        *   method – имя метода из библиотеки, при вызове метода в него передаются следующие параметры, по порядку – ID объекта/doc\_id, признак редактирования/is\_edit, ID текущего приложения, TopElem текущего выполняемого действия – для получени идентификатора/кода объекта действия и текущего набора параметров вызова wvars),
    *   если с командой присылается массив form\_fields – то для нового документа (doc\_id пустой или отсутствует) перед открытием по форме поля массива будут установлены в документе (поля аналогичного названия)
    *   wvars – объект параметров, который будет проброшен в открывающееся окно документа, аналогичен объекту SCOPE\_WVARS. Для извлечения данного объекта в коде экранной формы (xms) необходимо использовать вызов функции SCOPE\_WVARS = ms\_tools.get\_doc\_screen\_wvars ( TopElem.Doc );
*   _eval_ – вызвать выполнение действия еще раз (используется для подтверждения от пользователя через confirm), если будет прислан набор полей формы form\_fields – они будут скопированы и добавлены в набор параметров выполняемого действия. Если в confirm\_result приходит не команда submit\_form, а команда eval, то в посылку подставляется команда eval\_action.
*   _download_ (только при выполнении действия в приложении администратора) – загрузить файл с сервера (без создания ресурса базы или размещения файл в доступе), ожидается параметр url схемы x-local://trash/temp.
*   _call_ – выполнить функцию JS или метод объекта, существующего в текущем окне (например, при вызове интерпретатора УД из внешнего JS приложения)
    *   fn – код вызова, должен быть любой непустой строкой
    *   fn\_name – имя функции, или имя объекта, должен существовать в контексте текущего окна браузера
    *   fn\_method – имя метода (для объекта fn\_name), который будет вызван при исполнении команды
    *   args\_array – массив аргументов, которые будут переданы вызываемой функции в качестве параметров
