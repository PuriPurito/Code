## Кэширование в системе

## Кэширование дизайна

Режимы кэширование дизайна Портала:

1.  Кэширование шаблонов xaml.
2.  Кэширование элементов шаблонов.
3.  Кэширование структуры.

### **1\. Кэширование шаблонов xaml**

Настраивается и сбрасывается в разделе **Общие настройки**→**Системное администрирование** интерфейса администратора.

Этот режим кэширования распространяется на XAML-портал и на меню, footer (подвал), левые, правые панели на странице для Портала на редакторе страниц. При использовании Портала на редакторе страниц в редакторе изменяется только зона main, к ней применяется второй или третий вид кэширования, которые описаны далее.

Если в общих настройках включено кэширование шаблонов xaml, при входе на Портал создается документ, куда переоткрываются все шаблоны и сохраняется их текст. У этого документа есть код, который складывается из mode, сайта, дизайна и некоторых настроек пользователя (например, роль, уровень). Это обеспечивает то, что страница на одном сайте и дизайне для большой группы пользователей имеет одинаковый набор шаблонов в соответствии с правами доступа.   
  

Рекомендуется в поле **Тип кеширования шаблонов портала** выбирать значение _Кеширование веб-шаблонов и шаблонов разметки_, который позволяет также кэшировать шаблоны, выступающие в роли плэйсхолдеров, имеют соответствующий код (например, view\_doc\_placeholder.html) и тип – шаблоны разметки.

### **2\. Кэширование элементов шаблонов**

Этот режим кэширования работает, если в карточке типа страницы (раздел **Дизайнер**→**Портал**→**Типы страниц**) выключен параметр **Кеширование структуры**.  
При этом механизме кэш существует отдельно для каждого виджета, участвующего в типе страницы, и записывается в элемент шаблона. При сборке такого типа страницы берется кэш из каждого виджета, запускается шаблон типа страницы и заполняет этот кэш данными, полученными из коллекций и показателей.

В этом режиме в редакторе страниц для виджетов выбирается способ кэширования информации для пользователей: только дизайн или и дизайн, и данные. Второй вариант рекомендуется использовать при относительно редком изменении отображаемых данных, что позволяет ускорить загрузку и отображение виджета.

Кэширование элементов шаблонов обновляется тремя способами:

1.  При запуске страницы с параметром адресной строки ?lpe\_preview=1.
2.  При выполнении предпросмотра в редакторе страниц.
3.  С помощью кнопки **Сбросить кэш шаблонов виджетов** в карточке дизайна портала (раздел **Дизайнер**→**Портал**→**Дизайны портала**). В этом случае кэш будет сброшен у всех типов страниц, используемых в данном дизайне.

  
Минусы этого вида кэширования: кэш элементов шаблонов создается для пользователя, под которым было запущено lpe\_preview=1 (или выполнен предпросмотр), то есть с учетом прав этого пользователя. Поэтому если данные на странице по-разному отображаются для разных ролей участников (например, для руководителя и подчиненного), то компилируется кэш только тех виджетов, которые доступны текущему пользователю. В этом случае для обновления кэша для второй роли нужно зайти еще раз и запустить lpe\_preview=1. 

### **3\. Кэширование структуры страницы**

Новый вид кэширования, который работает, если в карточке типа страницы (раздел **Дизайнер**→**Портал**→**Типы страниц**) включен параметр **Кеширования структуры**.  
  

_Примечание: параметр **Постзагрузка контента** не влияет на кэширование, он предназначен для возможности постзагрузки всех виджетов зоны main: если параметр включен, сначала загружается содержимое других зон, включается маска загрузки, после чего загружается содержимое зоны main. Включение параметра актуально для сложных страниц с большим количеством данных._

Кэш структуры – это все виджеты, которые задействованы в этом типе страницы, полностью скомпилированные без данных. Вместо данных там есть, условно говоря, места для подстановок или вызова коллекций. Соответветственно при показе страницы, в которой включен параметр кэширования структуры, берется весь кэш целиком и запускается его стрим, попутно находя специальные метки, по которым должна произойти подстановка показателя либо вызов коллекции. То есть в этом случае документы шаблонов виджетов не задействуются вообще, таким образом достигается значительное ускорение загрузки страниц.

Компиляция этого вида кэша осуществляется:

1.  При первом обращении к странице, у которой кэша еще нет.
2.  При изменении даты сохранения типы страницы.
3.  Вручную при запуске страницы с параметром адресной строки ?fcache=1.
4.  При запуске агента сервера «Обновление кеша структуры всех типов страниц».

Кеширование структуры нельзя использовать для страниц, на которых есть кастомные виджеты в зоне main, а также старые коробочные виджеты (типа «Моя команда»), так как кастомные виджеты по умолчанию не готовы к использованию в этом режиме и нуждаются в доработке. В карточках таких типов страниц параметр **Кеширование структуры** должен быть выключен.

## Кэширование данных

Помимо кэширования дизайна в системе существуют большое количество видов кэширования, например, кэш авторизационных данных (выполняется на 10 минут), кэш клеймов (прав доступа), кэш библиотек, кэш групп (5 минут), кэширование запросов к базе данных, кэш работы с файловой системой, кэш загрузки ресурсов базы и т.д.
