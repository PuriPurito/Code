## Принципы организации доступа

Разделение доступа в системе осуществляется по многоуровневой схеме.

На верхнем уровне в модуле «Безопасность» должен быть зарегистрирован список приложений, потенциально имеющих права на использование API. Каждому приложению присваивается индивидуальный идентификатор **APP-ID** (**ClientID**  в терминах стандарта), который (идентификатор) приложение обязано добавить в заголовок запроса _«x-app-id»_ при отправке запроса к серверу WebTutor. Доступ будет разрешен только зарегистрированным приложениям.

Для регистрации приложения необходимо в модуле «Безопасность – API - Внешние приложения API» создать новый документ «Внешнее приложение API», указав название и идентификатор.

Необходимо различать индивидуальный идентификатор внешнего приложения **APP-ID** (_x-app-id_) и идентификатор объекта **Внешнее приложение API**. Первый указывается в карточке внешнего приложения API (см. скриншот, приведенный выше). Второй определяется стандартным способом, который описывается в статье "Как определить идентификационный номер (ID) объекта".

На следующем уровне для заявленного приложения определяется список возможных вариантов авторизации. Для каждого варианта определен способ авторизации (анонимный или Basic), а также логин и пароль для авторизации. Варианты авторизации регистрируются в модуле «Безопасность – API - Удостоверения». Одно или несколько удостоверений могут быть затем прикреплены к объекту «Внешнее приложение API».

Уровнем ниже определяется профиль безопасности – список возможных объектов и функций, с которыми может работать приложение по данному удостоверению. Профили создаются в модуле «Безопасность – API – Профили безопасности». В профиле определяется набор модулей (Блоков каталогов), с которыми может работать авторизованное по текущему удостоверению приложение, и профили (наборы) объектов и функций, описанных в настроечных файлах, расположенных в директории wtv\\oapi\\profiles. Название каждого xml-файла является именем отдельной схемы. В один профиль безопасности может быть включено несколько схем(профилей) для разных модулей(блоков каталогов) системы.

Следующий уровень распределения доступа – это xml-файлы профилей, расположенные (как было упомянуто выше) в директории wtv\\oapi\\profiles. Каждый файл содержит структуру, содержащую два блока:

\- блок _objects_, описывающий возможные объекты и права на них (для LowLevel)

\- блок _functions_, описывающий возможные функции и параметры их вызовов (для HighLevel)

В профиле может быть заполнен, как один из блоков (если в нем описывается функционал одного уровня), так и оба (если профиль подразумевает использование обоих уровней).

Для **публикации функций библиотек программного кода по API 3.0** выполните следующие действия (данная функциональность добавлена в релизе 2021.2):

1) Откройте в Администраторе раздел **Безопасность - API – Профиль безопасности**.

2) Создайте новую запись профиля безопасности.

3) Укажите название профиля безопасности.

4) Укажите источник – **Библиотека функций**.

5) Добавьте строку и выберите нужную библиотеку программного кода.

6) При необходимости в поле **Фильтр** перечислите через точку с запятой функции, необходимые для подключения.

7) Сохраните карточку профиля безопасности.
