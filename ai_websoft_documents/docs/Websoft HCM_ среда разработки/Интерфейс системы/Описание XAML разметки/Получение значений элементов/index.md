## Получение значений элементов

Элемент разметки  
Название:    Получение значений элементов  
Краткое описание:    Как прочесть данное  
Тип:    Справка  
Содержимое:      
Подробное описание:    

В действияLite Тестирование, параметрыLite Тестирование и много чего другого добавляются значения из элементов на форме, используя конструкцию {}  
Есть нюансы извлечения данных. Например из некоторых сложных элементов, типа DataGridLite Тестирование, данные можно извлекать по разному (в данном случае используя суффиксы - об этом ниже)

  
Если в конструкции {} в начале идет восклицательный знак (!), это означает что извлекаемое значение маскироваться не будет.  
Например  
Value="{!Edit1}"

Текстовые поляLite Тестирование, спискиLite Тестирование и т.п.

Здесь просто - возвращается текст элемента.  
ЧекбоксLite Тестирование

Если у чекбокса не отмечен, возвращается false.  
Если был отмечен и:  
\- был указан параметр Value, возвращается значение этого параметра.  
\- Value не был указан - возвращается true  
РадиоLite Тестирование

Возвращается значение Value отмеченного элемента  
Поле с датойLite Тестирование

Если значение есть, оно будет сконвертировано в текст по формату, указанному в настройках плеера по умолчанию.  
Если значения нет - null  
ТаблицаLite Тестирование

Результаты данных из таблицы очень сильно различаются в зависимости от настроек.  
Таблица всегда старается вернуть массив (кроме случая ниже красным цветом). Массив состоит из объектов на каждую строку из выборки, свойствами которых являются значения столбцов.  
По умолчанию попадают столбцы, у которых свойство Editable равно true. Всё меняется при вступлении в силу параметра Ghost:  
\- если true, то из данного столбец никогда не вынимаются данные, даже если оно редактируемое.  
\- если false, то из данного столба будут извлекаться данные в любом случае.

Если нет ни одного столбца, из которого можно извлечь данные, то в результате данных таблицы будет не массив, а null

В таблице с пейджингом всё ограничено данными на текущей странице. Кроме них в данный момент ничего не существует.

Плеер возвращает объект в формате XML или JSON. Поэтому для чтения полученных данных лучше использовать стандартную функцию tools.read\_object(\[data\])

а) Стандартный вызов

Пример: Set=Edit1,{Grid1}

Если у таблицы свойство Selection равно "none", будут возвращены все строки из таблицы.  
Если Selection равно "multiple", будут возвращены только выделенные.  
Если Selection равно "single", будет возвращен массив из одной выделенной записи.

В последних двух случаях если не выделено ни одной записи, будет возвращен пустой массив.

б) Использование суффиксов (о суффиксах см. ниже)

Для дополнительной выборки данных можно использовать:  
\- селекторы  
\* - выбрать все данные. Интересна тем, что при Selection, равном "single" или "multiple" вернет все строки, как-будто Selection равнялся бы "none"  
^ - выбрать первое значение. Берет первый объект из выборки. Возвращается уже не массив объектов, а объект!  
\- пути  
\[идентификатор столбца\] - если был выбран массив, то вернется плоский массив, состоящий из значений данного столбца. Если в выборке объект (например после селектора " ^ "), то вернется голое значение из этого объекта.

  
Пример: Set=Edit1,{Grid1:^/name}

ДеревоLite Тестирование

Возвращается объект на выделенной ветке, пришелдший из выборки.  
Могут быть использованы следующие суффиксы:  
\- пути  
\[название свосйства из выборки\] - вместо объекта вернется значение это свойство (которое было в исходных данных ветки)

Пример: Set=Edit1,{MyTree1/id}  
Панель закладокLite Тестирование

Возвращается порядковый номер начиная с 0 выбранной закладки. Но только, если у панели указан параметр Name

КалендарикDocument Link Icon

Возвращает объект с тремя свойствами: start - начало периода, end - конец периода, date - текущая дата, и mode - текущий режим. Если одного из значений нет (например в режиме категорий нет текущей даты), то соответствующее свойство будет равно null

Могут быть использованы следующие суффиксы:  
\- пути  
\[название свосйства из возвращаемого объекта\] - вместо объекта вернется одно из четырёх свойств выше. Соответственно в пути можно только их и указывать.

Пример: Set=Date1,{MyCalendar1/start}

Орг-чарт Document Link Icon

Возвращает массив тех объектов, пришедших из выборки, которые отмечены пользователем.

Для дополнительной выборки данных можно использовать:  
\- селекторы  
\* - выбрать все данные из выбранных пользователем.  
^ - выбрать первое значение из выбранных пользователем.  
\- пути  
\[идентификатор поля из выборки\] - если был выбран массив, то вернется плоский массив, состоящий из значений данного элемента выборки. Если в выборке объект (например после селектора " ^ "), то вернется голое значение из этого объекта.

Пример: Set=Edit1,{OChart1:\*/title}

Контекст

В качестве значения также можно использовать зарезервированное слово {CONTEXT}. В контекст попадают значения ВСЕХ активных элементов формы. Переопределить (или выключить) контекст в данной цепочке вызовов можно контекстной группойLite Тестирование.  
Контекст по умолчанию не позволяет использовать суффиксы. С контекстной группой пожалуйста.  
Контекст автоматически передается некоторыми действиямиLite Тестирование и во время перегрузки закладкиLite Тестирование  
Данные из окружения

При запросе данных, они ищутся по всему текущему окну. Но в некоторых случаях к этим данных добавляются дополнительные.   
У дополнительных данных приоритет выше! Другими словами, если в дополнительных данных есть переменная XXX=100500, а на форме есть текстовое поле XXX со значением "9000", то при обращении к {XXX} будет возвращено значение из доп. окружения, т.е. "100500"

а) Окружение таблицы

При вызове действия из строки таблицы (столбцы с кнопками, ссылками и т.д.) дополнительными данными являются значения из этой строки. К каждому значению соответственно обращаемся по идентификатору столбца (которое DataIDLite Тестирование).

б) Окружение из диалога

При положительном закрытии диалога, из него возвращается контекст, собранный внутри этого диалога. Значения этого контекста и будут дополнительными данными. К ним также обращаемся по идентификаторам.

в) Использование суффиксов

Суффиксы нужны для уточнения выборки или нарушения законов выборки.  
Суффикс состоит из селектора и/или пути.

Селектор меняет закон выборки или корректирует выборку.  
Путь извлекает отдельные данные из каждого объекта в массиве выборки.

Синтаксис:  
ID\_Элемента:селектор/путь

После элемента идет селектор, отделяемый двоеточием. После селектора идет путь, отделяемый прямым слешом. Если используется и селектор, и путь, то путь всегда после селектора.

Т.к. селектор и путь можно указывать по одному, то правильная запись правила будет:

ID\_Элемента\[:селектор\]\[/путь\]
