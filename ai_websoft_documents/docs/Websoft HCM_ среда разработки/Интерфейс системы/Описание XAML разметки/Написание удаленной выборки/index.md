## Написание удаленной выборки

Сложные элементы, например, таблицы, деревья и прочие "леса" требуют отдельно подготовленных данных, которыми являются удаленные выборки. Внешне выборка похожа на удаленное действие, за исключением нескольких особенностей.

Параметры, если они нужны, передаются с помощью описания Collection (кроме переменной curUserID - она не объявлена явно, но присутствует).  
Также есть переменная PAGEURL, которая содержит URL из строки браузера.

## Написание выборки для таблиц

Результат кода должен всегда возвращать объект. Либо это XQUERY, либо массив объектов, либо обычный массив. Этот результат нужно записать в параметр RESULT. Для проверки результата нажмите на кнопку "**Проверка**" и посмотрите, нормально ли сформируется XML/JSON, который будет передан в таблицу. Также тут можно протестировать, правильно ли работает пейджинг.

  
При необходимости можно здесь же описать колонки таблице, передав в переменную COLUMNS массив объектов. Каждый из этих объектов может/должен иметь следующие параметры:

*   **data** \- поле из **RESULT**, в котором хранятся данные;
*   **title** \- заголовок колонки;
*   **width** \- ширина колонки в пикселях;
*   **type** \[date, checkbox, **string**, button, image, fixedimage, link\] - тип колонки, нужен для сортировки и правильности отображения. При выборе необходимо убедиться, что поле из RESULT имеет тот же тип, что и колонка;
*   **editable** \[true,**false**\] - признак возможности редактировать значение в колонке;
*   **sortable** \[true,**false**\] - признак возможности сортировки по данной колонке;
*   **hidden** \[true,**false**\] - признак скрытой колонки;
*   **ghost** \[true,**false**\] - данные из колонки с этим признаком не будут извлекаться для передачи на сервер. Если параметр не указан, то извлекаются только редактируемые колонки (editable=true);
*   **colorsource** \- имя поля из **RESULT**, в котором определяется цвет значений в колонке (в формате #RRGGBB), либо само значение цвета #RRGGBB;
*   **classsource** \[ExtJS Player 5\] - имя поля из **RESULT**, в котором указан CSS-класс для ячеек колонки;
*   **click** \- действие для кнопки аналогично типу Button. Особенность - дополнительно передаются данные текущей строки, которые также можно использовать. Например, _OPENWINDOW=http://www.google.ru/search?q={name}_;
*   **multiline** \[ExtJS Player 5\] \[true,**false**\] - признак возможности переноса текста на несколько строк (для типа "string").

  
При необходимости вместо стандартного превращения массива в строку можно вернуть строку с готовыми данными в нужном формате (XML, JSON и т.д.) Данные в таком случае:

*   нужно помещать в объект **RESULTSTREAM**. **RESULTSTREAM** \- это объект SPXML BufStream (тот который с методами PrepareWriteSpace, WriteStr и т.д.);
*   общее количество элементов ручками записывать в переменную **TOTAL** объекта **PAGING**, чтобы работал пейджинг;
*   узнать в каком формате плейер ждёт результат можно из переменной **FORMAT** \[xml,json\].

Если нужно делать сортировку на сервере, в контексте будут две переменные, пришедшие с сервера, записанные в объект **SORT**:

*   **FIELD** \- id колонки. Тои идентификатор, который **Value** в DataGridColum или **data** из **COLUMNS** (SORT.FIELD);
*   **DIRECTION** \- направление сортировки \[ASC,DESC\] (SORT.DIRECTION).

Пейджинг работает автоматически. Для ручного режима есть объект **PAGING**. Включается ручной режим присвоением свойству **MANUAL** этого объекта значения true (PAGING.MANUAL = true). Из этого объекта также можно прочитать индекс текущей страницы (свойство **INDEX**) и размер одной страницы (свойство **SIZE**). Общее количество элементов находится в свойстве **TOTAL** (PAGING.TOTAL = ArrayCount(aMyResultset)).

## Написание выборки для деревьев

Также, как и для таблиц, результат кода должен всегда возвращать объект. Либо это XQUERY, либо массив объектов, либо обычный массив. Для проверки результата нажмите на кнопку "**Проверка**" и посмотрите, нормально ли сформируется XML/JSON, который будет передан в дерево. Для асинхронного дерева для каждой раскрываемой ветки будет сделан запрос в эту выборку с передачей идентификатора этой ветки. Идентификатор передается в переменной **TREE\_NODE\_ID**. При первоначальной инициации дерева **TREE\_NODE\_ID** равен "_source_".

Это также можно протестировать в коде выборки с помощью поля "_ID ветки_".

  
Поля массиве **RESULT**, из которых будут браться названия, иерархия и пр. описываются в XAML в элементе Tree. 

При необходимости можно описать источник данных для дерева, передав в переменную **COLUMNS** массив из одного объекта. Объект может/должен иметь следующие параметры:

*   **id** \- поле из **RESULT**, в котором содержится уникальный идентификатор ветки дерева;
*   **title** \- поле из **RESULT**, из которого дерево будет извлекать название ветки;
*   **parent** \- поле из **RESULT**, в котором содержится идентификатор родительской ветки. Должен сочетаться с параметром **id**, используется для статического дерева;
*   **fatherhood** \- поле из **RESULT**, в котором содержится признак (true/false или 1/0), что у ветки есть дочерние листья  (для асинхронного дерева). При нажатии на эту ветку, будет сделан еще один запрос к данной выборке с передачей идентификатора выбранной ветки, который будет доступен в переменной **TREE\_NODE\_ID**;
*   **click** - действие при нажатии на ветку (смотри аналогично в Button). Особенность - плюс ко всему передаются данные **id**, **title**, **parent** и **fathrhood**, которые можно также использовать. Например: _OPENWINDOW=http://www.google.ru/search?q={title}_;
*   **icon** \- путь до картинки узла дерева;
*   **expanded** \[true/false\] - признак развернутости ли узла дерева.

Синхронные и статические ветки можно комбинировать, как в примере.

## Написание выборки для календаря

По аналогии с предыдущими пунктами - в **RESULT** возвращается массив данных о событиях. Поля-источники указываются в календаре с помощью параметров **DataTitle**, **DataStart** и т.д. (см. Calendar). По умолчанию:

*   **title** \- название события;
*   **start** - дата начала;
*   **end** \- дата завершения;
*   **format** \- формат даты;
*   **color** \- цвет (#RRGGBB);
*   **class** \[ExtJS Player 5\] - CSS-класс;
*   **category** \- категория (для категоризованного вида);
*   **desc** \- описание (для категоризованного вида);

В выборку всегда передаются два параметра: **start** (начало периода) и **end** (конец периода).

В **RESULT** возвращается массив объектов с полями, к которым будет обращаться сам OrgChar. Здесь перечислены значения по умолчанию, если не переопределены:

## Написание выборки для MindMap

В **RESULT** возвращается массив объектов с полями, к которым будет обращаться сам MindMap.

Здесь перечислены значения по умолчанию, если не переопределены:

*   **id** \- идентификатор элемента;
*   **parent** \- идентификатор родителя элемента;
*   **turnround** \- направление от родителя. Если true, направление сменится на 180°, иначе останется прежним;
*   **color** \- цвет фона в формате #RRGGBB;
*   **title** \- заголовок;
*   **text** \- содержание в формате HTML;
*   **expanded** (bool) - признак раскрытия элемента по умолчанию (по умолчанию true);
*   **clickable** (bool) - признак наличия у элемента кнопки-скрепки, по нажатию на которую сработает событие **Click**.
