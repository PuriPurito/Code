## create_notification

Создает объект нового неотправленного уведомления. 

Уведомление после создания сразу попадает в очередь отправки и со временем будет отправлено. Если требуется внеочередная отправка уведомления, то можно использовать функцию **send\_notification**. Если выполнять внеочередную отправку уведомления не требуется, то функцию **send\_notification** можно не использовать.

  
В теле уведомления (шаблоне уведомления) обращение к первому параметру идет через objDocID, к документу, открываемому автоматически при вызове функции по отправке уведомления, objDoc. objDoc- это TopElem документа.  
Обращение ко второму параметру идет через objDocSecID, к документу, открываемому автоматически при вызове функции по отправке уведомления objDocSec. objDocSec- это TopElem документа.  
Если документ отрыт ранее, то для ускорения работы функции отправки уведомления, можно передать открытый документ в функцию, что позволит избежать его повторного открытия. Для этого вместо tools.create\_notification( code, id1, '', id2) вызывается функция, куда передаются дополнительные параметры tools.create\_notification( code, id1, '', id2, TopElem1,TopElem2 ).

**Примечание** – Сформированные сообщения можно просмотреть в интерфейсе Webtutor Administrator в разделе **Системное администрирование** **- Неотправленные сообщения**. В некоторых случаях для просмотра сообщения нужно обновить данный раздел с помощью клавиши **F5**.

**Внимание!** Для корректного формирования сообщений необходимо указать следующие настройки в разделе **Сервис – Общие настройки... – Администрирование – Отправка сообщений**:  
\- Поля **Адрес электронной почты** и **SMTP** **сервер** не должны быть пустыми.  
\- Переключатель **Действие с карточкой после отправки** должен быть установлен в позицию **Сохранять со статусом "Отправлен" в течение ... часов** (продолжительность сохранения отправленного сообщения может составлять, например, _80 часов_)  
\- Должен быть установлен флажок **Создавать отправленное уведомление в случае, если у сотрудника поле** **Email** **пустое**.  
  

**Примечание** - Сформированное сообщение через определенное время автоматически отправляет специальная фоновая программа, работающая в составе WebTutor. После успешной отправки сформированного сообщения его статус будет изменен с "**Создан**" или "**Отправляется**" на "**Отправлен**".

_Синтаксис:_  
      **tools.create\_notification( <oTypeParam>, <iObjectIDParam>\[, <sTextParam>\],\[ <iSecondObjectIDParam>\],\[ <oObjectParam>\],\[ <oSecondObjectParam>\],\[ <teSourceParam>\])**  
      или  
      **tools.create\_notification( '0', <iObjectIDParam>\[, <sTextParam>\],\[ <iSecondObjectIDParam>\],\[ <oObjectParam>\],\[ <oSecondObjectParam>\], <teSourceParam> )**  
      или  
      **tools.create\_notification( '', <iObjectIDParam>\[, <sTextParam>\],\[ <iSecondObjectIDParam>\],\[ <oObjectParam>\],\[ <oSecondObjectParam>\], <teSourceParam> )**

_Аргументы:_  
     <oTypeParam> (обязательный)  
      Тип: **Строка**. Код типа уведомления (см. раздел **Дизайнер – Типы уведомлений** в интерфейсе Webtutor Administrator), которое будет отправляться. Если параметр пустой ('') или равен '0', то в параметр teSourceParam необходимо передавать структуру, из которой будут заполняться типы получателей (recipients), тип отправителя (sender\_selector), тема сообщения (subject), тип текста в теле сообщения (body\_type), тело сообщения (body) и адрес отправителя (sender\_email). Если oTypeParam - это реальный код типа уведомления, то типы получателей (recipients), тип отправителя (sender\_selector) и адрес отправителя (sender\_email) будут браться из указанного объекта. А тема сообщения (subject), тип текста в теле сообщения (body\_type), тело сообщения (body) из шаблона уведомления, прикрепленного к типу сообщения с указанным в параметре кодом. Если в существующих в системе типах уведомления не найдено типа уведомления с указанным кодом, то уведомление не формируется и функция возвратит значение _false_.  
     В определенных случаях в качестве данного аргумента вместо кода типа уведомления может быть указан ID открытого документа типа уведомления.  
     _<iObjectIDParam> (обязательный)_   
      Тип: **Целое число**. ID первого объекта (обыкновенно, по данным первого документа формируется, в частности, перечень сотрудников, которым нужно отправить сообщение. В теле уведомления (шаблоне уведомления) обращение к этому параметру идет через objDoc (например, <%=objDoc.name%>) и objDocID. О первом прикрепленном объекте - см. подробнее статью **Общие принципы формирования уведомлений в системе**. См. также **Примеры 1 и 2** в настоящей статье.  
      _<sTextParam> (необязательный)_  
      Тип: **Строка**. Строка, к которой можно обращаться в теле шаблона уведомления как к Text (<%=Text%>).  
     _<iSecondObjectIDParam> (необязательный)_  
      Тип: **Целое число**. ID второго объекта, который прикрепляется к уведомлению. В теле уведомления (шаблоне уведомления) обращение этому параметру идет через objDocSec (например, <%=objDocSec.name%>) и objDocSecID. О втором прикрепленном объекте - см. подробнее статью **Общие принципы формирования уведомлений в системе**. См. также **Пример 2** в настоящей статье.

Внимание! Перед тем, как добавлять в качестве аргумента второй объект, обязательно просмотрите соответствующий шаблон уведомления. В шаблоне уведомления в ряде случаев дается ссылка на второй объект с использованием конструкции _ForeignElem_ (например, "<%=objDoc.course\_id.ForeignElem.name%>" при назначении сотруднику курса). При этом второй объект определяется программно из системы. 

  
      _<oObjectParam> (необязательный)_  
      Тип: **TopElem**. TopElem карточки первого объекта, определяемого аргументом _iObjectIDParam_.  
      _<oSecondObjectParam> (необязательный)_  
      Тип: **TopElem**. TopElem карточки второго объекта, определяемого аргументом _iSecondObjectIDParam_.  
      _<teSourceParam> (необязательный, используется, если атрибут oTypeParam пустой ('') или равен '0')_  
      Тип: **Объект** **XmlDoc**. Структура, позволяющая создать собственное (пользовательское) уведомление "на лету". Из нее берутся данные о типах получателей (recipients), тип отправителя (sender\_selector), тема сообщения (subject), тип текста в теле сообщения (body\_type), тело сообщения (body) и адрес отправителя (sender\_email) (см. **Пример 3** в настоящей статье).

**Примечание** - Пользовательское уведомление можно также сформировать, создав новый тип уведомления и привязанный к нему новый шаблон уведомления. В этом случае в качестве аргумента _<oTypeParam>_ указывается код данного нового типа уведомления.

_Возвращаемое значение:_  
      Тип: **Булево**. Флаг успешности создания уведомления. Значение true демонстрирует, что уведомление создано успешно, false – что уведомление не сформировано или сформировано ошибочно.

`_// Пусть в системе имеется сотрудник Васильева Людмила Петровна (должен быть указан электронный адрес сотрудника в поле **E-mail** на вкладке **Анкетные данные** карточки сотрудника в интерфейсе Webtutor Administrator)_`

`_// Находим сотрудника Васильеву Л.П.   try {        _query_str = "for $elem in collaborators where $elem/fullname = 'Васильева Людмила Петровна' return $elem";        personArray = XQuery(_query_str);        // personArray является массивом объектов Сотрудник, отобранных запросом. Запрос отбирает сотрудника, ФИО которого имеет значение 'Васильева Людмила Петровна' (в данном случае массив состоит из одного элемента)        A1 = ArrayFirstElem ( personArray ); // функция возвращает первый (и, в данном случае, единственный) элемент массива сотрудников personArray        alert ('Найден сотрудник: ' + A1.fullname); // на экран выводится полное имя отобранного сотрудника   }    catch (err){        alert ('Сотрудник не найден!');   }_`

`_// Формируем сообщение для сотрудника; для примера формируем сообщение с кодом типа уведомления '9' - Уведомление сотрудника о логине и пароле (см. раздел_ _**Дизайнер – Типы уведомлений**_ _в интерфейсе Webtutor Administrator)    A3 = tools.create_notification( '9', Int(A1.id), '' );   if ( A3 == true )      alert ( 'Сообщение сотруднику ' + A1.fullname + ' сформировано успешно');   else          alert ('Сообщение не сформировано!');_`
