## Общие принципы формирования уведомлений в системе

См. также статью **"Уведомления"**.  Значения типов шаблонов и первого и второго объектов для основных кодов типов уведомлений в приложенном файле к статье **"Уведомления"**. 

Для программирования формирования уведомлений необходимо знать основные принципы формирования уведомлений.  
  
  Схематически процесс формирования уведомления может быть изображен следующщим образом:  
  
  
  1) При формировании уведомления выбирается тип уведомления. Для выбора типа уведомления обычно используется его код. Коды типов уведомлений можно найти в разделе **Дизайнер – Типы уведомлений** в интерфейсе Webtutor Administrator.  
    
  
2) Тип уведомления связан с соответствующим шаблоном уведомления (см. раздел **Дизайнер – Шаблоны уведомлений** в интерфейсе Webtutor Administrator).  
Числовое значение кода стандартного шаблона уведомления обычно на 100 больше кода соответствующего типа уведомления. Например, тип уведомления '1' (сообщение о заявке сотрудника) связан с шаблоном уведомления '101' и т.д.  
  
  
Шаблон уведомления содержит, в частности, текст уведомления с переменными, отображающими контент, подлежащий изменению.  
  
  
Примеры расшифровки переменных приведены в Вики-базе на странице **Создание шаблона уведомлений**.  
  
При формировании уведомлений с помощью функции **tools.create\_notification** используются некоторые специфические выражения переменных. Приведем примеры этих выражений:  
_<%=objDoc.name%>_ - наименование первого прикрепленного объекта (о первом прикрепленном объекте – см. п. 3);  
_<%=objDoc__ID%>_ - ID первого прикрепленного объекта;  
_<%=objDocSec.name%>_ - наименование второго прикрепленного объекта (о втором прикрепленном объекте – см. п. 3);  
_<%=objDocSec__ID%>_ - ID второго прикрепленного объекта;  
_<%=Text%>_ - дополнительный текст, приведенный в аргументе _<sTextParam>_ функции **tools.create\_notification**.  
  
3) К уведомлению в функции **tools.create\_notification** прикрепляются один или два объекта, из которых в уведомление передаются данные.  
Первый объект (_<iObjectIDParam>_) содержит адреса рассылки уведомления, а также значения переменных, отображающих изменяемый контент. Данный объект является обязательным.  
При необходимости к уведомлению добавляется еще один, второй (дополнительный) объект, который также может содержать информацию для уведомления.  
Например, для типа уведомления с кодом '53' «Вы были включены в состав ответственных за подготовку мероприятия» к сообщению необходимо прикрепить два объекта (см. **tools.create\_notification (Пример 2)**):  
\- первый объект – карточка сотрудника и  
\- второй объект – карточка мероприятия.  
  
4) В стандартных уведомлениях запрограммированы соответствующие типы адресатов (получателей).  
В случае формирования новых (пользовательских) уведомлений могут быть программно добавлены следующие типы адресатов, состав и коды которых (<recipient\_type>) определены в файле _\\wtv\\wtv\_common.xml_ :  
_\- Адрес в объекте_ (указанный в первом прикрепленном объекте; например, адрес сотрудника) – код адресата 'in\_doc'  
_\- Руководители подразделения объекта_ - 'boss\_in\_doc'  
_\-_ _Руководители центра затрат объекта_ - 'cost\_center\_boss\_in\_doc'  
_\- Высшие руководители подразделения объекта_ - 'main\_boss\_in\_doc'  
_\- Функциональные руководители объекта_ - 'func\_manager\_in\_doc'  
_\- Функциональные руководители подразделения объекта_ - 'sub\_func\_manager\_in\_doc'  
_\- Функциональные руководители организации объекта_ - 'org\_func\_manager\_in\_doc'  
Можно также добавить исполняемый код получения ID пользователей ('eval\_person\_ids') и дополнительную информацию об адресатах ('add').  
  
Все перечисленные адресаты могут быть отображены в карточке нового типа уведомления:  
  
  
5) Уведомления, сформированные с помощью функции **tools.create\_notification** (в системе WebTutor они именуются «неотправленными сообщениями»), отображаются в разделе **Системное администрирование – Неотправленные сообщения**.       
  
  
Первоначально сообщение получает статус **«Создан»**, затем – **«Отправляется»**.  
Через определенное сообщение время автоматически отправляется специальной фоновой программой, работающей в системе WebTutor. После успешной отправки сообщения его статус будет изменен на **«Отправлен»**.

О нумерации кодов типов стандартных уведомлений и наименованиях переменных для таких уведомлений - см. статью **«Использование в тексте шаблона уведомлений операторов и выражений»**.
