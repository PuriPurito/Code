## xss_neutralize

Функция **tools\_web.xss\_neutralize** предназначена для "очистки" текста, поступившего от внешнего источника, от возможных вредоносных фрагментов (XSS).

Описание функции актуально для релиза 2025.1.

_Синтаксис:_  
      **tools\_web.xss\_neutralize( <sText>, <sType> )**

_Аргументы:_  
     **<sText>** (обязательный)  
      Тип: **Строка**. Исходный текст, который надо очистить.   
     **<sType>** (обязательный)  
      Тип: **Строка**. Режим обработки. 

Стандартные настройки функции указываются в файле resource\_sec.json.  
Имеются три стандартных режима:   
    - plaintext - для чисто текстовых полей (название, ФИО, код и т.д.) - очистка всех тегов/атрибутов HTML/Script - т.е. на выходе будет только введенный текст, все вставки HTML-разметки будут убраны.   
   - richtext - для текста, где принципиально нужна возможность различного оформления (описание, ответы экспертов и т.п.) - очистка активного, возможно вредоносного, содержимого - тегов (iframe, script) и атрибутов событий on... (onerror, onload и т.п.), остальные теги/атрибуты разрешены.  
   - formattedtext - для сообщений в чатах, форумах, комментариях, где допустимо только ограниченное оформление -  в тексте будут оставлены только разрешенные теги ( b, i, s, u, br ) и атрибуты (style).  
  
Для режима plaintext специальных настроек не предусмотрено.  
Остальные режимы можно настроить путем изменения файла resource\_sec.json, лежащего в корне сервера.  
Для этого в объекте JSON из файла должен наличествовать объект "xss", а в нем - объект "patterns".  
Для настраваемого режима должен пристуствовать объект с тем же именем, например - "richtext" или "formattedtext".   
Внутри него имеются различные варианты объектов:  
 - "disallowed\_tags" – массив строк – теги разметки, которые не разрешены к использванию для режима и будут удалены (остальные оставлены).  
 - "disallowed\_attributes" – массив строк – не разрешенные к использованию наименования атрибутов.  
 - "allowed\_tags" – массив строк – разрешенные к использованию теги разметки.  
 - "allowed\_attributes" – массив строк – разрешенные атрибуты.  
 - "disallowed\_attr\_exclude" – массив строк – массив значений атрибутов, которые будут пропущены (с точно таким же значением, включая регистр букв и пробелы) при фильтрации, даже если название атрибута попадает под условия запрета;  
 - "allow\_href\_js" – булево – разрешен (true) или не разрешен (false) js-код в атрибуте href (по умолчанию – не разрешен). Если false, js-код будет вычищаться в атрибуте href, если true – js-код вычищаться не будет.  
  
  
Массивы disallowed\_tags и allowed\_tags исключают друг друга, поскольку allowed\_tags означает, что в данном режиме разрешено использование только перечисленных тегов (остальные будут удалены), а disallowed\_tags - что удалены будут только те теги, которые перечислены (все другие теги будут оставлены в тексте без изменения).  
Аналогично - для массивов разрешенных/запрещенных атрибутов.

Пример настройки коробочного файла для стандартных режимов приведен ниже:

    "xss":   
    {  
        "patterns":  
        {  
            "richtext":  
            {  
                "disallowed\_tags": \["script","iframe"\],  
                "disallowed\_attributes": \["on\*"\],  
                "disallowed\_attr\_exclude": \["try { WTPopupThis(this); }catch(e){}"\],  
                "allow\_href\_js": false  
            },  
            "formattedtext":  
            {  
                "allowed\_tags": \["b","br","i","u","strike","font"\],  
                "allowed\_attributes": \["style","face","color"\]  
            }  
        }  
    },

_Выходные данные:_  
     **sResult** \- текст, очищенный от не разрешенных к использованию тегов и атрибутов (строка).

     sResult = tools\_web.xss\_neutralize( sText, sType );
