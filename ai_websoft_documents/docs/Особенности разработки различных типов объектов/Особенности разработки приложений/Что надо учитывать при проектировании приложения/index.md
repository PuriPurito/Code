## Что надо учитывать при проектировании приложения

1.  _Определить и зафиксировать код приложения_. Предлагается код приложения составлять из двух частей (части объединяются в одну строку через тире (например, _websoft-exit-interview_)):  
    \- код вендора (_websoft_);  
    \- код приложения внутри вендорского реестра.
2.  _Определить, будут ли в приложении использоваться процессы_. Приложение может быть _«унитарным»_, когда его настройки едины для всех процессов внутри приложения, или _«процессным»_, когда в рамках приложения могут быть запущены один или несколько процессов, каждый из которых может использовать как общие настройки приложения, так и иметь собственные настройки, отличающиеся от настроек других процессов. В зависимости от бизнес-логики в приложении может быть несколько процессов, активных одновременно (например, _для приложения по оценке_ – это несколько запущенных одновременно оценочных процедур с разными настройками, _для приложения по опросам_ – разные опросы), или несколько процессов, разнесенных по времени (например, приложение сбора заявок на обучение, с индивидуальными процессами/настройками на каждую заявочную кампанию, на год или квартал), или вообще может не быть процессов (например, приложение бизнес-процесса «**Скажи спасибо**» может использовать только глобальные настройки и при изменении этих настроек просто начинает работать несколько иначе).
3.  _Составить единый реестр настроек приложения_, проанализировать код всех составляющих элементов (агентов, шаблонов, типов заявок, дистанционного обучения и пр.), обеспечить унификацию (для понимания в будущем и документирования) и уникальность (в связи с размещением в одной структуре) параметров, собранных из разных мест.
4.  Если в приложении будут использоваться процессы, рекомендуется _разделить массив настроек на две части_ – **общие настройки** (которые будут одинаковы для всех процессов и при их изменении должны быть применены ко всем процессам) и **настройки процесса** (определяют параметры конкретного процесса и при их изменении должны применятся только к текущему процессу).
5.  _Определить набор возможных ролей приложения и необходимый набор значений уровней доступа_, ориентируясь при этом на общий справочник уровней (см. раздел "Доступ к приложению").
6.  _Определить список объектов, к которым может потребоваться доступ_ у пользователя/администратора приложения, структурировать их по необходимым правам (создание / чтение / редактирование / удаление), а также определить необходимый набор модулей, к которым относятся эти типы объектов.
