## Структура приложения

После установки приложения основные файлы приложения копируются в папку _...\\WebTutorServer\\applications\\<код приложения>_ (если папки _...\\WebTutorServer\\applications_ и _...\\WebTutorServer\\applications\\<код приложения>_ ранее не существовали на сервере, то они создаются).   
На следующем рисунке показана папка websoft-exit-interview, созданная при установке приложения **Exit-интервью**:

В папке _applications_ размещаются индивидуальные директории для каждого установленного приложения.

Внимание! для обеспечения возможности одновременной установки нескольких приложений на сервер необходимо, чтобы каждое приложение имело индивидуальный код.

Рассмотрим подробнее набор файлов приложения на примере приложения **Exit-интервью:**

Набор файлов в директории следующий:

                - универсальный (или собственный) шаблон и настроечный файл для отображения меню (структуры) приложения (в рассматриваемом приложении **Exit-интервью** - это два универсальных шаблона **app\_list.xml** и **app\_list.xms** и собственный файл приложения с настройками **menu\_structure.xml**);

                - универсальный (или собственный) шаблон показа первой страницы приложения (в приложении **Exit-интервью** - это два универсальных шаблона **app\_form0.xml** и **app\_form0.xms**, а также часть файла **menu\_structure.xml,** в составе которого имеется часть параметров для первой страницы);

                - универсальный шаблон и настроечный файл для показа страниц с настройками приложения и/или процесса (в приложении **Exit-интервью** файлы данного типа не используются);

                - универсальный шаблон и настроечный файл для показа страниц со списками объектов (в приложении **Exit-интервью** - имеется не универсальный файл, а собственный файл приложения с объектами системы (агентом и пр.), нужными для работы приложения **app\_objects.xml** (при установке объекты из этого файла будут созданы в системе). В других приложениях к данной группе могут относиться файлы универсальных шаблонов **app\_form\_objects.xml**, **app\_form\_objects.xms** и **objects\_structure.xml**);

                - библиотека **application.js** – содержит код функций, используемых в универсальных шаблонах (может отсутствовать, если приложение не использует универсальные шаблоны);

                - собственная библиотека приложения – по умолчанию, файл js с названием, совпадающим с кодом приложения – содержит коды функций, используемых в процессах приложения (в данном примере - файл **websoft-exit-interview.js;** в приложении **Exit-интервью** к файлам этой группы относятся также библиотеки готовых компонентов **app\_dlg.xmd**, **app\_general.xmd** и **app\_general.xms**);

                - специфические шаблоны (xms и xml) для административного интерфейса приложения – упрощенные формы показа/редактирования объектов (в приложении **Exit-интервью** - это файлы **dlg\_poll\_short.xml, dlg\_poll\_short.xms, parameters.xml, parameters.xms** и **report.xml**);

                - заглавная картинка приложения для показа на главной странице (по умолчанию файл формата jpg с названием, совпадающим с кодом приложения; в данном примере - файл **app\_home.jpg**).

Разработчикам приложений необходимо обратить особое внимание на три типа файлов:

1.  xml – файл, определяющий набор данных для экранной формы.
2.  xmd – файл формы, содержащий схему данных, т.е. список полей, с описанием их типов, значений по умолчанию, правил контроля и проверки. Также такой файл может содержать код функций, выполняемых при открытии документа по форме xmd, при его сохранении или связанных с этим типом документа. Файл xmd не содержит данных.
3.  xms – файл описания экранной формы, набор инструкций и мета-описаний для клиента системы (например, для WebTutor Administrator), указывающих клиенту, как нужно отобразить форму на экране, какие элементы показать, из какого поля документа взять данные для показа, куда сохранить данные и т.д..
