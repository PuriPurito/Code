## Основные объекты приложения

Приложения могут включать в себя следующие виды основных объектов:

1.  Собственно приложение **application** как объект. В этом объекте хранятся все настройки, которые необходимы для работы приложения (как базовые, так и те, что меняет пользователь).  
    Для конкретного запущенного приложения такой объект – всегда один.
2.  Процесс приложения **application\_instance** как объект.  
    Процессы приложения соответствуют экземплярам запущенного процесса. Для одного приложения может быть запущено несколько процессов (например, процедур оценки или опросов), каждый из которых может иметь свои собственные настройки. В то же время некоторые приложения могут не использовать процессы вообще (например, для приложения **Exit-интервью** необходимости создавать отдельные процессы нет). Использование процессов отставляется на усмотрение архитектора и разработчика приложения.  
    Данный объект содержит информацию об отдельном процессе и о конкретных настройках этого процесса. Настройки по умолчанию для создания новых процессов могут храниться также в объекте **application**.
3.  **Объект приложения** (**объект, связанный с приложением**) и **объект процесса приложения** (**объект, связанный с процессом приложения**).   
    Для работы приложению может потребоваться наличие в системе разных объектов:  
    \- шаблонов;  
    \- агентов;  
    \- удаленных действий;  
    \- выборок;  
    \- справочников (компетенций, опросов, тестов и др.);  
    \- рабочих объектов (результатов опросов, анкет, оценочных процедур) и т.д.  
    Эти объекты могут поставляться вместе с приложением или создаваться в процессе его работы.  
    Эти объекты также могут быть как общими для приложения (объекты приложения – агенты / элементы дизайна, справочники), так и относится к конкретному запущенному процессу (объекты процесса приложения - процедура оценки, анкеты, планы оценки).

Основные параметры приложения, содержащиеся в объекте **application**:  
\- _общие настройки_ \- код, название, пиктограмма, название вендора, дата релиза;  
\- _список используемых модулей_ – модули WT, в состав которых входят объекты, к которым пользователь приложения должен иметь доступ;  
\- _настройки интерфейса_ – форма, которая будет использована для показа меню приложения и форма, которая будет использована для показа первой страницы приложения. Могут быть использованы стандартные (универсальные формы), о которых говорится далее, или собственные, пользовательские формы;  
\- _массив общих настроек приложения_ – структура _wvars_ (аналогична используемой в шаблонах документов);  
\- _массив настроек по умолчанию_, специфических для процессов, инициируемых в рамках приложения – структура _instance.wvars_.

Основные параметры процесса приложения, содержащиеся в объекте **application\_instance**:  
\- _массив настроек конкретного процесса_ – структура _wvars_, создается первоначально путем копирования структуры данных _instance.wvars_ из объекта приложения, в дальнейшем может модифицироваться (актуален только для конкретного процесса).

Чтобы понимать, какие объекты имеются у приложения (для поиска или, например, при удалении приложения), а, с другой стороны, знать в процессе работы функционала, к какому приложению или процессу приложения обращаться для получения настроек и программного кода, все объекты, связанные с приложением или его процессами, маркируются. В специальном поле документ (_app\_instance\_id_) указывается идентификатор приложения (если объект является общим для всех процессов, например, элемент справочника или шаблон) или идентификатор процесса приложения (если элемент относится к конкретному процессу, например, оценочная процедура или план оценки сотрудника).
