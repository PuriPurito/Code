## 1.6.1.1 Режим "params" - получение параметров для работы плеера

Метод "params" вызывается плеером оценки в следующих случаях:

\- при первоначальной загрузке приложения, перед запросом списка доступных оценочных форм (метод "list");

\- при перезагрузке дерева, по получении директивы "reload\_all" (по кнопке ДО или команды API).

При вызове метода "params" обработчик формирует два пустых базовых объекта (oData.data и oData.config) и вызывает шаблон подготовки данных дерева оценки.

Т.е. шаблон подготовки дерева при запуске плеера выполняется дважды:

\- первый раз - для получения параметров (режим вызова можно определить по переменной xmlMode = "params"), при этом массив oData.data - пуст;

\- второй раз - для получения списка доступных оценочных форм (xmlMode = "list"), массив oData.data содержит список объектов - доступных анкет.

Из ответа серверного обработчика плеер извлекает объект config, который может содержать следующие параметры работы плеера:

\- load\_tree\_incremental (true|false) - определяет режим загрузки дерева - инкрементальный (в первый момент загружается не все дерево, а только формы руководителей верхнего уровня, а дальнейшие узлы подчиненных подгружаются по мере разворачивания узлов) или полный (все дерево загружается целиком за один раз и сворачивание/разворачивание узлов происходит только внутри браузера, без дополнительных запросов на сервер). Режим работы по умолчанию - false (полная загрузка); 

\- exclude\_self (true|false) - флаг, определяющий, будут ли принудительно включены в верхний уровень дерева формы самооценки. Используется при инкрементальной загрузке, в случае, когда на некоторых этапах ДО видны только формы самооценки (нельзя построить иерархию подчиненности только по формам самооценки). Значение по умолчанию - false;

\- expanded\_levels (число от 1 и больше) - указывает обработчику, сколько уровней иерархии, начиная сверху, надо вернуть плееру при первом обращении. Используется при инкрементальной загрузке для уменьшения числа запросов к серверу. Например,если количество видимых форм для руководителей высокого уровня очень велико, по в типовом режиме они работают с двумя-тремя верхними уровнями (малое количество форм) - то имеет смысл сражу загружать эти уровни (expanded\_levels = 2 или 3), и только уровни 4 и ниже подгружать отдельными запросами к серверу;

\- pa\_id - идентификатор формы, которая будет автоматически открыта после загрузки дерева. По умолчанию это значение извлекается из адресной строки плеера, но можно вычислить/указать нужны идентификатор в шаблоне подготовки данных. Если этот параметр указан, то восходящая ветка от данной формы также будет загружена (но другие формы разных уровней будут подгружаться отдельными запросам при попытке свернуть/развернуть ветви иерархии).

\- bNoCrossDialog - признак скрытия стандартной кнопки (крестика) закрытия диалоговых окон - если false - крест будет отображаться, true (по умолчанию) - будет скрыт

\- sTreeLoadMethod - режим загрузки дерева, если в адресе запуска плеера указан ИД конкретной анкеты. Может использоваться два варианта:

            - before - дерево оценки загружается до момента загрузки целевой анкеты.

            - demand - дерево оценки загружается в момент обращения к нему (при клике на пункт меню)

          Во втором варианте процесс загрузки самой анкеты ускоряется, но переход к дереву может привести к некоторой задержке (время на загрузку дерева) + теоретически возможны сложности при сложносочиненном дереве и нескольким видимым анкетам для конкретного оцениваемого. В первом варианте стартовая загрузка может быть медленнее, но риск "потери" анкеты в закладках - нулевой.

\- bExtendPa - ( по умолчанию false) - флаг, определяющий, нужно ли расширять область запрашиваемых анкет, используется для варианта, когда указана стартовая анкета, а признак загрузки дерева (sTreeLoadMethod) выставлен в "demand". В этом варианте плеер запросит с сервера только одну анкету (которая указана в адресе, как стартовая). Но, если выставить флаг, плеер в запросе пришлет команду extend\_pa = true, по которой серверный обработчик понимает, что надо попробовать "расширить" рамки запроса и вернуть не только запрошенную анкету, но и другие, которые могут располагаться в том же листе на соседних закладках.

Такой вариант предоставляет возможность, не запрашивая дерева оценки (т.е. без лишнего торможения), все же получить весть набор закладок-анкет, указав в адресе вызова только одну из них...

\- sTreeCollecionCode - код коллекции (удаленной выборки), которая будет использована при получения списка анкет при построении дерева оценки. если данный атрибут установлен, то для получения списка анкет используются не стандартные методы, а вызывается код коллекции с указанным кодом. Коллекция должна вернуть массив объектов - по одному для каждой анкеты. Особенности программирования такой коллекции приведены в п.3.2

\- sLogoAction - код действия, выполняемого при клике на логотип в левом верхнем углу плеера, возможные значения:

    none - не выполнять никаких действий (нет клика, курсор - стрелка)

    url - открыть страницу с заданным адресом

   home - открыть главную страницу портала (/\_wt/home)

   close - закрыть текущее окно браузера с плеером

   back - вернуться на предыдущую страницу в истории текущей сессии браузера

\- sLogoConfirm - текст сообщения-запроса, показываемый при нажатии на логотип, по умолчанию "Закрыть плеер оценки и перейти на портал?", если пусто - действие выполняется без предупреждения

\- sLogoUrl - адрес перехода после клика на логотип

\- sPageTitle - текст заголовка блока закладок с формами (замена текста "Оценочные формы")

\- sTreePersonSelector - по умолчанию null - если пусто или null, то фильтр по статусу форм в дереве оценки не показывается, иное значение - значение фильтра по умолчанию  
\- sTreePersonWFSelector - по умолчанию null - если пусто или null, то фильтр по этапу ДО в дереве оценки не показывается, иное значение - значение фильтра по умолчанию  
\- sTreePersonSearch - по умолчанию null - если пусто или null, то строка поиска в дереве оценки не показывается, иное значение - значение поиска по умолчанию  
\- sTreePersonIDs - по умолчанию null - если пусто или null, то фильтр по сотруднику в дереве оценки не показывается, иное значение - значение фильтра по умолчанию  
\- sTreeFilterType - по умолчанию null - режим работы фильтра, client - с сервера загружается полное дерево, фильтрация осуществляется в браузере, server - с сервера загружается              уже отфильтрованный список, при смены фильтра - вновь запрос на сервер  
\- bTreeFilterConfirm - показывать или нет, предупреждающее сообщение при выборе в фильтре режима "все формы" - используется, когда список форм велик и переключение на                  полный список может привести к увеличению времени ожидания ответа сервера  
\- sTreeFilterConfirmMessage - если предыдущий параметр установлен в true - текст сообщения/предупреждения, значение по умолчанию "Количество доступных форм оценки слишком велико, построение полного дерева оценки может занять длительное время. Рекомендуем использовать поиск для отображения части форм"

\- bCustomFilter - флаг, указывающий плееру, что будет использована настраиваемая форма фильтров для дерева оценки. По умолчанию false. Требует указания кода коллекции (sTreeCollecionCode) - которая будет формировать дерево оценки, и в которую будут переданы данные выбранных полей фильтра

\- aFilterValues - массив данных для формы фильтров - массив объектов, описывающих поля формы:

       - name - имя/код поля

       - label - заголовок поля

       - control\_type - тип поля. Допустимы значения - text, select, checkbox, radio, foreign\_elem, list, date, number

       - data\_src - имя набора данных, из которого будут браться значения длы выбора, если пустой или отстутстувует - будет использован массив items

       - items - массив значений для выбора (для полей типа radio, checkbox, select) - массив объектов с параметрами id (код значения), value (значение), name (текст значения)

       - value - текущее значение фильтра

       - value\_name - текущее название значения (для полей типа foreign\_elem)

      - catalog\_name - название каталога (для полей типа foreign\_elem)

      - layout - расположение элементов - col/row (для полей типа radio/checkbox)

      - spot\_position - положение элемента (для полей типа radio/checkbox)

      - spot\_type - тип элемента (для полей типа radio/checkbox)

      - class - CSS класс, добавляется к списку классов контрола поля

      - min - минимальное возможное значение для выбора (для полей выбора даты и числа)

      - max - максимальное возможное значение для выбора (для полей выбора даты и числа)

      - multi\_select - возможность выбора нескольких значений (для полей типа foreign\_elem)

      - xquery\_qual - доп. запрос ограничения записей каталога (для полей типа foreign\_elem)

     - show\_all - показывать все записи в каталогах Сотрудник (для полей типа foreign\_elem)

     - _page\_url: "" // для поля типа foregn\_elem - адрес кастомной страницы диалога, в которой будет осуществлятся выбор объекта_

     - title - описание поля, будет показано во всплывающем окне при показе значения в линейке фильтр

     - desc - расширенное описание поля. будет показано при наведении мышы на контрол поля на форме

     - main\_view - флаг, обознающий, будет ли показано поле в виде контрола выбора значения в линейке фильтра или в диалоговом окне формы

     - depend\_datasets - массив объектов, определяющих, какие наборы данных надо обновить при изменении значения в данном поле (как обновлять наборы - описано в статье про программирование динамических форм), элементы каждого объекта из массива - name (имя набора данных), collection (код коллекции), оба свойства обязательные

      - update\_data - объект со свойством collection - код коллекции, если присутствует, то при изменении значения в поле, с сервера будет запрошено обновление полей фильтра

      - no\_save - не сохранять (и не восстанавливать) значение поля - всегда по умолчанию или установленное на сервере значение 

\- sFilterButtonLabel - текст кнопки для показа фильтра

\- sFilterFormTitle - текст-заголовок формы выбора фильтров

\- bFilterSaveLocal - флаг, сохранять ли выбранные значения фильтров в локальном хранилище (по умолчанию false - не сохранять) - позволяет восстановить выбранные значения даже после перезагрузки страницы или переоткрытия браузера  
\- bFilterAppraiseKey - флаг, сохранять ли значения фильтров для текущей процедуры, по умолчанию - да  
\- bFilterImpersonateKey - флаг, сохранять ли значения фильтров для текущего делегирования, по умолчанию - да. Если оба параметры выставлены в true (или отстуствуют) - то сохраняются значения фильтров (за исключением полей, помеченных no\_save - не сохранять) для конкретной процедуры и конкретного участника оценки (с учетом делегирования). Выставление одного параметра в true, а второго в false позволяет устанавливать фильтры для участника (во всех процедурах) или для процедуры (для любого участника)  
\- bFilterClearBtn - флаг, показывать ли кнопку очистки значений фильтра  
\- sFilterClearMethod - метод очистки значений: default - устанавливать значения по умолчанию, full - очищать все поля. если параметр пропущен - то default  
\- sFilterClearText - заголовок кнопки очистки фильтра, если параметр пропущен - "Очистить"

\- bFilterClearFormOnly - флаг, очищать все поля фильтра (линейка над деревом + диалоговое окно) или только поля диалогового окна, по умолчанию false - очищать все поля

\- bFilterClearRestoreOnCancel - флаг, вернуть ли значения полей, если после Очистить была нажата кнопка Отмена, по умолчанию - true - вернуть установленные значения

\- sSheetSelector - режим отображения закладок для оценочных форм, возможные значения:

           - tabs (по умолчанию) - переключатель в виде закладок - ярлыки листов с названиями форм

           - select - переключатель в виде выпадающего списка с названиями форм

\- bLoadSubordinates - параметр, определяющий, будет или нет плеер загружать список подчиненных текущего сотрудника (для трансляции, например). Если системный список не нужен (нет трансляции или список формируется кастомным кодом по своему алгоритму) - то, выставив параметр в false, можно сэкономить на ресурсах, не выполняя запрос

\- bOnlyFirstPage - по умолчанию true - флаг, использующийся в ситуации, когда при клике на узел в дереве оценки загружается несколько анкет, в закладках листа. при установке в true по клику будет полностью загружена только одна, активная, анкета, остальные будут загружены частично, только заголовки.

\- bPartialLoadCode - по умочанию false - флаг, работает при установленном параметре bOnlyFirstPage - будет или нет вызыватся код подготовки формы анкет, для которых загружаются только заголовки. Позволяет ускорить загрузку листа анкет, но иногда, для модификации, например, заголовка закладки анкеты, вызов кода формы подготовки бывает нужен  
При этом в коде шаблона подготовки данных доступна глобальная переменная bIsMain - если true - то загружается полный набор данных анкеты, если false - то это вызов шаблона при подготовки данных для "ярлыка". Для качественной оптимизации шаблон должен учитывать режим вызова и не выполнять ненужных вычислений (например, списка задач - на ярлыке он все равно не покажется, а при клике на ярлык - все равно анкета будет перезагружена с сервера для получения полной информации)

\- bNoRefreshWorkflow - не вычислять и не присылать список действий (кнопок) ДО - позволяет сэкономить ресурсы, если список действий все равно вычисляется/проверяется в кастомном коде шаблона

\- sLoadMode - режим загрузки формы оценки целей, строка:

               - minmum - загружаются только идентификаторы (ID) задач из списка задач анкеты, никакая другая информация не загружается

               - optimum - загружается только информация, которую можно извлечь из анкеты, без обращения к сопряженным документам (task)

                - full - значение по умолчанию - полная загрузка данных формы

          Значение minimum подходит в случае сильно кастомизированных процедур, когда практически вся форма готовится при помощи кастом кода. В этом случае функционал серверного обработчика не нужен и он просто отключается, чтобы не дублировать кастомный

          Режим optimum формирует, помимо ID целей, еще вес и позицию цели, а также данные по оцениваемому/оценивающему, загружает (если есть) настройки показа формы

          Режим full - стандартный, загружает полные данные формы

          Параметр sLoadMode действует при первой загрузке формы, а также при любых действиях (добавление/удаление задачи, комментарий, сортировка), если только поведение для конкретного типа действия не определено отдельно одним из параметров ниже...

\- onAdd - объект, устанавливающий параметры работы плеера при добавлении новой задачи/цели, содержит элементы:

               - bPartialSave - по умолчанию false - флаг, указывающий, будет ли плеер отправлять на сервер полный набор данных анкеты (все цели) или только изменения  
               - bNoPostCode - по умолчанию false - флаг, указывающий, будет ли обработчик вызывать код формы постобработки  
               - bPartialLoad - по умолчанию false - флаг, указывающий, будет ли обработчик формировать (и отправлят на плеер) полный набор данных анкеты, или только изменения  
               - bNoLoadCode - по умолчанию false - флаг, указывающий, будет ли обработчик вызывать код формы подготовки данных после выполнения команды  
               - bNoRefreshWorkflow - по умолчанию false - флаг, указывающий, будет ли обработчик пересчитывать (и присылать) наборк кнопок документооборота  
\- onEdit - объект, устанавливающий параметры работы плеера при редактировании задачи/цели, содержит элементы, аналогично объекту onAdd

\- onDelete - объект, устанавливающий параметры работы плеера при удалении задачи/цели, содержит элементы, аналогично объекту onAdd

\- onWeight - объект, устанавливающий параметры работы плеера при сохранении формы редактирования весов, содержит элементы, аналогично объекту onAdd

\- onComment - объект, устанавливающий параметры работы плеера при сохранении комментария к форме, содержит элементы, аналогично объекту onAdd

\- onSort - объект, устанавливающий параметры работы плеера при сохранении результата изменения порядка следования целей, содержит элементы, аналогично объекту onAdd

 - onWorkFlow - объект, устанавливающий параметры работы плеера при обработке нажатия кнопки ДО, содержит элементы, аналогично объекту onAdd

\- sWorkflowFields - строка, содержащая данные дополнительных полей формы, которые будет учитывать обработчик (получение и передача значений в плеер, сохранение значений).         Может быть задан в следующих вариантах:

                - пустая строка или null - будут возвращены все видимые поля ДО

                - строковое значение - #empty# - не будут возвращены никакие дополнительные поля, даже если они есть в ДО и видимы

                - строка, содержащая имена полей из карточки документооборота, через точку с запятой

                - строка формата JSON - массив описаний полей (при этом поля могут не быть описаны в карточке ДО), объект описания каждого поля содержит:

                       - id - имя поля  
                       - title - название поля (заголовок)  
Если параметр sWorkflowFields пуст или null - то обработчик будет составлять список полей для обработки на основе документа ДО (все поля карточки ДО), иначе - только указанные.

\- oWorkflowFields - объект описания кастом-полей, если в процедуре участвует несколько анкет разных типов, для каждого из которых надо указать свой набор полей, представляет из себя список массивов-описаний полей (аналогично sWorkflowFields) с меткой каждого массива - для какого типа анкеты эти поля актуальны. пример такого объекта:   
                                         { "career\_plan": \[  { "id": "CustomField\_1", "group": "common", "type": "string", "title": "Строка 1", "editable": true },  
                                                                      { "id": "CustomField\_2", "group": "common", "type": "text", "title": "текст\_2", "editable": true },  
                                                                      { "id": "CustomField\_9", "group": "common", "type": "catalog", "title": "Строка 9", "editable": true } \],  
                                               "result": \[        { "id": "CustomField\_2", "group": "common", "type": "string", "title": "Строка 2", "editable": true },  
                                                                     { "id": "CustomField\_5", "group": "common", "type": "catalog", "title": "Строка 5", "editable": true } \] }

\- iBlockInterval - интервал блокировки на редактирование формы, в минутах. По умолчанию - 20 минут

\- iBlockCheckInterval - интервал обновления данных по блокировке (опрос сервера по состоянию блокировки), в миллисекундах. По умолчанию - 60000 мс ( 60 секунд )

\- bToogleCollapse: false - при разворачивании цели верхнего уровня не разворачивать цели уровней ниже (true - полностью разворачивается вся ветка)  
\- bToogleExpand: false - при сворачивании цели верхнего уровня не сворачивать цели уровней ниже (true - полностью сворачивается вся ветка)  
если оба параметра установлены в false (по умолчанию) - то при сворачивании/разворачивании цели верхнего уровня плашки нижних уровней показываются в том состоянии, в котором были на момент получения команды, т.е. если часть целей была свернута, то после сворачивании/разворачивании верхней цели нижние цели не меняют состояния, если параметр установлен в true - то после сворачивания/разворачивания все плашки целей второго уровня будут свернуты или развернуты

\- iDigitsNum: 2 - количество знаков дробной части, до которого будут округлены все числовые значения при показе (при редактировании - без округления)  
\- bNoLocaleNums: false - не приводить число при показе к локальным настройкам (разделитель тысяч и знак дробной части) при редактировании - приведения нет

По умолчанию при показе (без редактирования) числовых значений, они будут округлены до второго знака и приведены к локальному формату ОС.

\- sCommentBehavior: "workflow" - поведение системы при сохранении комменатариев - workflow (по умолчанию) - один комментарий на один этап ДО и редактирование тем же пользователем на том же этапе, session - один комментарий на сессию - редактирование, пока не будет перелогина, после - новый комментарий без возможности редактировать созданны в предыдущей сессии, unique - комментарии а-ля лента введенный комментарий нельзя редактировать, но можно добавить новый
