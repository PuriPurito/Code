## 3.3. Использование тонкой настройки параметров плеера для оптимизации

### **Загрузка форм из закладок листа**

Если при клике на ФИО оцениваемого в дереве оценки пользователь получает доступ к нескольким анкетам, то они показываются в виде листа с закладками, содержимое анкеты показывается при клике на заголовок листа. В начальных релизах плеера оценки при запросе к обработчику, по клику на ФИО, грузилось полное содержание всех анкет-закладок, и при клике на закладку форма показывалась без дополнительного запроса к севреру. Начиная с релиза 2 квартала 2022 в плеере предусмотрен режим, когда полностью грузится содержание только активной анкеты, которая и будет показана первой, для остальных анкет грузится только заголовок, а полное содержание подгружается с сервера отдельным запросом при клике на ярлык закладки. Это несколько увеличивает время отображения следующей анкеты, зато позволяет сильно сэкономить, если анкет много, и в конкретный момент нужна одна или две, а на остальные заглядывают не каждый раз. Для включения такого режиам необходимо в форме параметров (дерева оценки) установить флаг bOnlyFirstPage

oData.config.bOnlyFirstPage = true;

Но при таком режиме работы может возникнуть ситуация, когда заголовки ярлыков анкет не совпадают со стандартными и менялись в коде шаблона формы подготовки данных. Для исправления этой проблемы можно установить в конфиге флаг bPartialLoadCode (по умоляанию отключен, т.е. код подготовки данных для частично загружаемых форм не выполняется). Но в этом режиме код шаблона подготовки данных должен понимать, в каком режиме он запущен и не производить "лишних" вычислений. Для определения режима запуска код можно использовать глобальную переменную bIsMain (если true - шаблон запускается в режиме полной загрузки данных, false - только заголовок формы)

### **Использование инкрементальной загрузки данных формы целей при изменении данных**

В стандартном режиме плеер загружает форму с сервера целиком, со всеми задачами, полями и параметрами их отображения. А при действиях по изменению данных - добавление/удаление/изменение целей, редактирование таблицы весов, сохранение комментария и т.п. - форма целиком отправлялась на сервере и целиком же загружалась со всеми изменениями. Это, с одной стороны, позволяло более корректно и аккуратно выстроить алгоритмы подготовки и сохранения данных, но, с другой стороны, несло потенциальную потерю производительности за счет излишних запросов на отркытие и сохранение документов, обработку массивов данных. Начиная с релиза второго квартала 2022 в плеере предусмотрена возможность включения режима инкрементальной загрузки и сохранения данных. Например, при добавлении цели можно отправить на сервер только ее содержание, без остальных целей, а получить с сервере только те поля, которые перевычисляются при сохранении. При удалении достаточно передать на сервер только идентификатор той цели, что удаляется. При этом, если например, не пересчитывается сумма весов или какие-то параметры зависимых целей - то с сервера можно вообще получить только подтверждение удаления, без других данных, или только веса целей, не передавая данные других полей.

Для включенния режимов инкрементальной загрузки и сохранения нужно передать в объекте конфигурации плеера один из семи объектов режима: onAdd, onEdit, onDelete, onWeight, onComment, onSort, onWorkFlow. Каждый объект настраивает режимы работы плеера при выполнении команды на сохранение новой, добавленной, цели, на сохранение измененной цели, на удаление цели, на сохранение таблицы весов (та, где редактируются веса списка целей в отдельном диалоге), на сохранение комментария, на изменение порядка следования целей (сохранение после выхода из режима Drag'n'Drop), на обновление формы после нажатия кнопки документооборота.

Каждый из этих объектов содержит пять параметров настройки:

\- bPartialSave - если установлен в true, то плеер отправит на сервер только тот элемент, что был изменен - поля добавленной или измененной цели, идентификатор удаленной, таблицу весов или позиций целей, текст комментария. Другая информация на сервер передаватся не будет

\- bNoPostCode - означает, что дополнительный код сохранения (указанный в карточке процедуры) при выполнении этой команды вызываться не будет. если, например, операции стандартного обработчика при выполнении этой команды (например, сохранение порядка или весов, или комментария) вас устраивают, то включение этой опции позволяет вам сэкономить время на запуске код постсохранения - обработчик просто пропустит эту операцию

\- bPartialLoad - установка этого флага дает команду плееру, что с сервера придет не полный набор данных формы, а только его часть, например, после удаления цели на плеер придет структура целей, содержащая только идентификаторы и значения оценок и весов, которые будут пересчитаны, после того, как одна цель удалена. поскольку другие значения не менялись. плеер в этом режиме "накатывает" полученные данные поверх имеющихся. Это позволяет сократить объем посылки и перечень необходимых вычислений, если подготовка данных формы целей требует таких вычислений

\- bNoLoadCode - этот флаг указывает, что плеер не будет вызывать код подготовки формы (указанный в карточке процедуры). Опять-таки, аналогично коду постсохранения, системный процесс выполнения каких-то команд, например, сохранения комментария, вас устраивает и необходимости вызывать дополнительный код нет

\- bNoRefreshWorkflow - флаг указывает, что плеер не будет пересчитывать и возвращать плееру массив кнопок ДО. Позволяет сэкономить на выполнении этого действия, если, например, вы кнопки ДО формируете сами и системный процесс не нужен. Или действие, например смена порядка следования целей, точно не может изменить набор кнопок.

### **Задание списка полей для автоматической обработке их плеером**

В стандартном режиме плеер обрабатывает (извлекает значения и включает их в посылку, автоматически сохраняет при обработке команд) по названиям все поля, которые включены в список полей документооборота. В реальном процессе, зачастую, наборы таких полей отличались на разных этапах или для разных пользователей. Но приходилось все равно включать их все, чтобы не возится с кастомной обработкой. Начиная с релиза 2 квартала 2022 можно прислать плееру список нужных полей в параметре sWorkflowFields - коды полей через точку с запятой, или JSON массив с объектами полей. Причем при использовании варианта с JSON поля могут не быть указаны в карточке ДО, что сильно упрощает работу разработчика.
