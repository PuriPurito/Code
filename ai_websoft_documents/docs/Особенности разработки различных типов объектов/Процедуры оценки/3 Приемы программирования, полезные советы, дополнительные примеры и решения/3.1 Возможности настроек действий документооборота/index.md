## 3.1 Возможности настроек действий документооборота

Для программиста в варианте реализации оценочной процедуры с использованием плеера оценки появляются новые возможности:

\- можно управлять поведением плеера после обработки кода действия ДО. Так, если действие не приводит к изменению состояния этой или других форм (например, выставляются флаги в дополнительных полях или рассылаются уведомления) – то можно не тратить время на перерисовку дерева оценки или, даже, текущей оценочной формы – не выставлять команду вообще, или, если нажатую раз кнопку надо скрыть – просто дать команду на перерисовку текущей оценочной формы (RELOAD\_PA = true); 

\- можно, по итогам выполнения действия ДО, перебросить пользователя в нужное место, например, после согласования форм одного сотрудника открыть руководителю несогласованную форму другого сотрудника (REDIRECT\_TO\_PA = …); 

\- в дополнение, к предыдущему пункту, можно объявить об этом пользователю, установив, параллельно с командой REDIRECT\_TO\_PA еще и текст сообщения в переменной BRUTE\_MESSAGE; 

\- дополнительно, в переменной BRUTE\_MESSAGE\_CLASS можно задать стиль окна сообщения, которое будет показано после обработки нажатия кнопки ДО. В системе предусмотрено два стиля окна

             - сообщение об ошибке с красным восклицательным знаком и заголовком "Ошибка" - стиль по умолчанию

             - информационное сообщение с синим восклицательным знаком и без заголовка - если задан стиль  "wt-info-dialog"

             - собственные дополнительные стили можно задать в дополнительном шаблоне CSS, как описано в статье выше данного раздела

\- в дополнение, к предыдущему варианту, можно использовать новый, расширенный синтаксис, когда вместо строки текста на плеер пересылается строка закодированного объекта 

BRUTE\_MESSAGE=EncodeJson({  
"type": "confirm",   
"text": "Текст сообщения настраиваемый",   
"text\_ok": "Да, делаем",   
"text\_cancel": "Нет, отмена",   
"action": {   
"type": "iframe",   
"command": "",   
"id": "man\_select"   
}                 
}); 

Пересылаемый массив данных должен соответствовать структуре объекта msg из набора данных формы. Такая возможность дает новую гибкость в настройке действий ДО. Например, если перед нажатием кнопки надо заполнить комментарий, том можно сообщить об этом пользователю и сразу открыть ему окно заполнения комментария. Или, если некорректно заполнены данные какой-либо задачи, сразу открыть диалог редактирования этой задачи. Или, после выполнения действия, дать пользователю диалог выбора – перейти к оценке другого сотрудника или открыть дерево для самостоятельного выбора анкеты.

Атрибут action.type может принимать следующие значения:   
api - вызов команды api плеера    
select - переход на другую вкладку (анкету) того же пользователя   
workflow - выполнение другого действия ДО (эмуляция нажатия кнопки) из числа имеющихся на форме   
print - открытие печатной формы (эмуляция нажатия кнопки Печать, если она есть на форме)   
comment - открытие окна ввода комментария   
objective - открытие окна редактирования/просмотра конкретной цели   
iframe - выполнение действия дополнительной кнопки, имеющейся на форме или в левом меню  
 

Для типа команды action.type = "comment" доступен атрибут repeat - если установлен в true, то после сохранения комментария по кнопке ОК в диалоге ввода, произойдет повторная отправка данных ДО на сервер (повторное "нажатие" кнопки) - BRUTE\_MESSAGE = EncodeJson({type:"action", action:{ type:"comment", repeat:true}});

Также для action.type = "comment" доступны следующие дополнительные атрибуты:

sTitle - заголовок окна ввода комментария

sDesc - дополнительный текст, который будет показан в диалоге ввода комментария

sDescPosition - положение места вывода дополнительного текста:

                top (по умолчанию) - между заголовком и полем ввода комментария

                middle - ниже поля ввода комментария, но выше кнопок ОК и Отмена

                bottom - самая нижняя часть окна, ниже кнопок ОК и Отмена

sBtnSave - текст кнопки отправки комментария на сервер (по умолчанию ОК)

sBtnCancel - текст кнопки отмены ввода комментария (по умолчанию Отмена)

Для типа команды action.type = "api" и command = "remote\_action" - доступны следующие параметры:

\- remote\_action\_id - ID вызываемого удаленного действия (обязательный параметр)

\- wvars - объект переменных, которые будут переданы в действие, соответстует по структуре объекту SCOPE\_WVARS или PARMETERS (название переменной - имя элемента, значение переменной - значение элемента)
