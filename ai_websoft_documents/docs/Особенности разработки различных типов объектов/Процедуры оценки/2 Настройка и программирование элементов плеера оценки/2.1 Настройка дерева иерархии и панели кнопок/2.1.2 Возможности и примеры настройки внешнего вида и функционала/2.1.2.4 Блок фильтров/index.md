## 2.1.2.4 Блок фильтров

Блок предназначен для предоставления возможности уменьшить количество анкет в дереве, что актуально для руководителей высшего звена, количество видимых форм (сотрудников) для которых достаточно велико. Выбирая параметры фильтра, можно оставить там только формы на определенном этапе ДО, требующего вмешательства руководителя, или быстро найти формы оценки конкретного сотрудника, или оставить в дереве только формы самого руководителя, убрав подчиненных. По умолчанию блок не показывается (скрыт от пользователя). Для его активации в коде шаблона дерева необходимо сформировать массив oData.data.config.tree\_person\_filter. Структуру массива смотри в разделе 2.1.2.3.2.

_Необходимо показать в интерфейсе:_  
\- фильтр «по сотрудникам» с названием «Фильтр» и выбором «Мои формы/Все формы»  
\- фильтр «по этапам ДО» с названием «Этап ДО» - «Самооценка(1)/Завершено(10)/Все формы»  
\- при первом открытии дерево должно открываться в режиме «Мои формы на всех этапах»  
В шаблон вставляем следующий код  
oData.config.tree\_person\_filter = \[  
                {“type”:”selector”,  
”title”:”Фильтр”,  
”default\_value”:”self”,  
”items”:\[{“id”:”self”,”name”:”_Мои формы_”}, {“id”:”self”,”name”:”_Все формы_”}\]},  
                {“type”:”wfselector”,  
”title”:”_Этап ДО_”,  
”default\_value”:”all”,  
”items”:\[  
{“id”:”1”,”name”:”Самооценка”},  
{“id”:”10”,”name”:”Завершено”},  
{“id”:”all”,”name”:”_Все формы_”}\]}  
\];

По умолчанию фильтр работает на клиенте, т.е. в буквальном значении слова фильтрует полученный с сервера массив анкет по критериям, установленным в полях фильтра.

Если же прислать с сервера значение sTreeFilterType = "server", то список анкет будет фильтроваться на сервере, т.е. при первом запросе дерева на сервер будут переданы значения полей фильтра, выставленные по умолчанию ( default\_value ) и сервер вернет массив анкет согласно этим ограничениям. При смене значений в полях фильтра на сервере будет вновь отправлен запрос с измененными полями и сервер вернет массив, в соответствии с выбором.

Если с сервера при запросе параметров прислан флаг bCustomFilter = true, и код коллекции в переменной  sTreeCollecionCode (код коллекции обязателен для такого выбора) - то фильтр считается полностью пользовательским и набор полей устанавливается, исходя из массива aFilterValues, который должен содержать описания и значения полей фильтра. 

При этом поля пользовательского фильтра поделены на две группы, в зависимости от значения флага main\_view - если он в true, то поле показывается в основной линейке, и при смене значения в нем происходит запрос на сервер, который передает набор выбранных значений в коллекцию, которая должна вернуть список анкет в соответствии с параметрами.

Если же флаг main\_view = false, то поле показывается для изменения в отдельном диалоговом окне формы, которое открывается по специальной кнопке, а в общей линейке фильтра показывается только выбранное в данном поле значение.

При этом, независимо от того, расположено ли поле в общей линейке или в отдельном окне формы, на сервер при каждом изменении фильтра отправляется полный набор значений для всех полей. перечисленных в массиве aFilterValues.

Коллекция должна уметь учитывать значения полей и условия ДО, и строить список анкет, согласно заданным параметрам.

Если для поля задан объект depend\_datasets - то при изменении значения в поле будет вызвана на сервере коллекция для обновления значений одного или нескольких наборов данных, которые, возможно, используются при выборе значений в других полях (зависимые поля фильтра). Подробнее механизм вызова коллекции обновления наборов описан в статье 2.2.5.4.2

Если для поля задан объект update\_data - то при изменении значения в поле будет вызвана коллекция, возвращающая изменения в полях фильтра, в частности список полей может быть изменен, изменены контролы для выбора, установлены значения полей и т.д.

Выборка, запускаемая на сервере, получает параметры:  
\- sMode - "filter" - режим работы выборки (для возможности использовать одну выборку в разных функциях)  
\- filter\_values - содержание установленных значений полей текущего фильтра  
\- curUserID (ID текущего пользователя)  
\- curPersonID (ID текущего участника оценки) - если используется делегирование, то отличается от ID текущего пользователя  
\- impersonate\_id (ID запрошенного делегирования) - обычно совпадает с curPersonID, но может оличатся, если запрос на делегирование отклонен  
\- assessment\_appraise\_id - ID текущей процедуры оценки

Выборка может вернуть:  
\- массив RESULT - .массив описаний и значений полей фильтра  
\- если массив RESULT пустой, то данные берутся из объекта DATA.filter\_values  
Полученный масив полей заменит на сервере установленный до этого и форма фильтров будет перерисована
