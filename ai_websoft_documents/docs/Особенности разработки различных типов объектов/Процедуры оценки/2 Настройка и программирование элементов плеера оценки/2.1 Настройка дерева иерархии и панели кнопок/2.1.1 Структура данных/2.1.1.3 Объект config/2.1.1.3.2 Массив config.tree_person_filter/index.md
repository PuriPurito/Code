## 2.1.1.3.2 Массив config.tree_person_filter

Массив содержит настройки показа фильтров, расположенных над деревом оценки.

Имеется возможность определить три фильтра:

\- фильтр по сотруднику (формы, где я оцениваемый, оценивающий и т.д.)

\- фильтр по этапам документооборота

\- поиск по ФИО сотрудника

По умолчанию все фильтры скрыты, для показа массив настроек должен содержать элемент, описывающий нужный фильтр. Структура объекта настроек фильтра следующая:

{

"type": "selector", //тип фильтра

"title": "Роль", // заголовок фильтра

"items": \[ {“id”:””, “name”: “”},… \], // список значений для выбора

"default\_value": "self" // значение по умолчанию, при первом открытии плеера

}

Типы фильтров:

\- selector – фильтр по сотруднику

\- wfselector – фильтр по этапам ДО

\- search – поле поиска по ФИО

Массив значений items\[\] позволяет задать список значений для конкретного фильтра. Если массив пуст или отсутствует в структуре, список значений будет следующим, для фильтра по сотруднику:

\- Я оцениваемый (id:self) – только мои формы, где пользователь указан, как оцениваемый (curPersonID == person\_id)

\- Я оценщик (id:manager) – только формы, где пользователь указан, как оценивающий руководитель (curPersonID == expert\_person\_id)

\- Я согласующий (id:expert) – только формы, где пользователь упомянут только в списке дополнительных экспертов (curPersonID in custom\_experts)

\- Все формы (id:all) – показать все формы, без ограничений

При установке кастомного списка значений перечень должен включать подмножество из вышеуказанного списка (all,self,manager,expert)

Для фильтра по этапам ДО список значений по умолчанию будет состоять из полного списка этапов ДО (id: код этапа, name: название) + значение Все формы (id:all) для показа всех форм.

Если в описании фильтра присутствует заполненный атрибут default\_value, в фильтре будет выбрано данное значение, а дерево форм будет отфильтровано в соответствии с установленным значением.
