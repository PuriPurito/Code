## 2.1.1.1 Объект dataset

Содержит массивы данных справочников, общих для всего интерфейса.

Доступен в кода шаблона обработки дерева в виде переменной **oData.dataset**

В стандартном интерфейсе дерева оценки таких справочников два:

\- **workflow** – объект, содержит массив **states** – перечень всех этапов документооборота, массив объектов с параметрами:

      - **id** (код этапа)

      **- name** (название этапа)

      - **hidden** (признак скрытия) - этапы помеченные этим признаком, будут присутствовать в линейке виджета этапов (справа от ФИО) только тогда, когда текущий сотрудник находится на этом этапе, в других случаях кружок этапа в линейке будет отсутствовать - это позволяет рисовать сжатую линейку, только с основными этапами, но, при этом, показыать местоположение текущего этапа в общей псоледовательности

Справочник используется для показа названий этапов ДО в дереве оценочных форм;

\- **impersonation** – объект, содержит массив **persons** – перечень всех актуальных (с учетом дат) делегирований (сотрудников, от имени которых может выступать текущий пользователь). Каждый элемент массива содержит два атрибута - **person\_id** (идентификатор личной карточки сотрудника) и **name** (ФИО сотрудника). Справочник используется для отображения списка выбора делегирующего сотрудника.

Структура доступна для изменения программным кодом настраиваемого шаблона дерева.

Переопределять нужно каждый элемент объекта, т.е. при записи в коде шаблона дерева строки:

oData.dataset.workflow = { states: \[.......\]}

В итоговой посылке заменится только объект workflow, а объект impersonation, например, останется неизменным.

Настройка процедуры dataset дает возможность, например, задвать общие наборы справочников (бюджетные периоды, список сотрудников или подразделений и т.п.) для всего набора оценочных форм для текущего пользователя, что может съкономить ресурсы и объекм данных - например, у текущего пользователя с десяток оценочных форм, где он выстыпает в разном статусе (руководитель, самооценка, эксперт) или разного типа (оценка компетенций, оценка целей, постановка целей, ИПР), но во всех формах есть поле "период", опирающееся на значения одного и того же справочника. В таком случае справочник периодов можно задать непосредственно в плеере в целом, при открытии дерева оценки, а не передавать много раз с каждой формой.

Также надо помнить, что изменять объект impersonation в шаблоне дерева с надеждой дать кому-то доступ к функционалу оценки - занятие бессмысленное, поскольку, даже если вы в интерфейсе нарисуете потенциальную возможность делегирования от имени сотрудника, не упомянутого в карточке процедуры, то все равно при серверных операциях (построение дерева, открытие формы, выполнения действий ДО) проверка наличия прав делегирования будет производится на основе записи о деоегировании в карточке процедуры на сервере.
