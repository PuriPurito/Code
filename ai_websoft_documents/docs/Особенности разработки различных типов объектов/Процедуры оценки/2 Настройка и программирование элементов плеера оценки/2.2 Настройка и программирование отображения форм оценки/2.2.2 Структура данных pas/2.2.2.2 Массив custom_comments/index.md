## 2.2.2.2 Массив custom_comments

Содержит набор объектов с данными комментариев участников оценки.

Структура каждого объекта:

{

comment: “”, // Текст комментария

date: “”, // Дата заполнения комментария

person\_fullname: “”, // ФИО комментатора

person\_id: “”, // Идентификатор личной карточки комментатора

workflow\_state: “” // Этап ДО, на котором оставлен комментарий

}

Персонифицированные комментарии в системе стандартно сохраняются и хранятся по следующей логике:

\- каждый комментарий «привязан» к двум ключам – идентификатор комментатора и код этапа ДО, т.е. один участник на одном этапе может оставить только один комментарий;

\- при подготовке данных формы обработчик извлекает из структуры custom\_comments запись с ключами, соответствующими текущему участнику оценки и этапу ДО. Если такая запись есть – текст комментария помещается в атрибут «comment» структуры «pa»;

Т.е. в плеере оценки комментарий размещен в двух элементах – в поле “comment” – текущий комментарий, который предлагается пользователю для изменения в диалоге а потом отправляется на сервер для сохранения, и в структуре “custom\_comments” – там лежат все комментарии по форме (включая текущий) – по этой структуре формируется блок комментариев в интерфейсе формы.
