## 2.2.2.4 Объект config

Содержит информацию об общих параметрах дизайна и поведения формы. Создается и настраивается только в программном коде (обработчик этот объект не создает). Имеет следующие атрибуты/структуру (частично совпадает по атрибутам с объектом config, формируемым при запросе дерева оценки – в этом случает атрибуты, приходящие с конкретной оценочной формой имеют приоритет над атрибутами из дерева и параметры отображения плеера могут изменятся при переходе от формы к форме):

\- iDigitsNum: 2 - количество знаков дробной части, до которого будут округлены все числовые значения при показе (при редактировании - без округления)  
\- bNoLocaleNums: false - не приводить число при показе к локальным настройкам (разделитель тысяч и знак дробной части) при редактировании - приведения нет

Данные значения, будучи заданы для конкретной формы, заменяют такие же параметры в общей конфигурации плеера

\- sCheckAction - код Удаленного Действия, которое будет исполнено на сервере ДО СОХРАНЕНИЯ задачи/анкеты. В действии, например, можно проверить актуальность заполнения полей или что-то еще... В коде действия можно установить:  
        - код ошибки (ERROR) 306 (фиксированный код) и текстовую строку сообщения (MESSAGE) - в этом случае диалог редактирования задачи не будет закрыт, сохранения задачи не произойдет, поверх диалога будет показано присланное сообщение  
        - код ошибки (ERROR) 306 (фиксированный код) и JSON-строку сообщения (MESSAGE) - в этом случае диалог редактирования задачи будет закрыт, сохранения задачи не произойдет, будет исполнена команда API плеера, заданная в объекте, полученном после парсинга строки, полученной из кода действия  
        - любой другой код ошибки (0 или еще что-то) - задачи и анкета будут сохранены, диалоговое окно редактирования закрыто, экранная форма анкеты в плеере обновлена

\- user\_info - объект настроек динамической загрузки блока плашек с информацией об участниках оценки (см. отдельную статью)

\- flow\_info - объект настроек динамической загрузки данных для линейки этапов документооборота (см. отдельную статью)

\- check\_require\_on\_select - только для формы оценки компетенций - предупреждать об обязательности комментария сразу после выбора значения оценки (по умолчанию - проверка при нажатии кнопки Сохранить)

\- sCommentBehavior: "workflow" - поведение системы при сохранении комменатариев - workflow (по умолчанию) - один комментарий на один этап ДО и редактирование тем же пользователем на том же этапе, session - один комментарий на сессию - редактирование, пока не будет перелогина, после - новый комментарий без возможности редактировать созданны в предыдущей сессии, unique - комментарии а-ля лента введенный комментарий нельзя редактировать, но можно добавить новый
