## 2.2.2.6 Масссив wfbuttons

Массив содержит данные о доступных кнопках документооборота. Обработчик формирует этот массив обычным для оценки образом: проверяя условия видимости всех кнопок и, при положительном результате проверки, добавляя данные кнопки в результирующий массив. Обновление/перевычисление списка осуществляется при каждом обновлении формы (при открытии или после сохранения). Структура элемента массива следующая:

{

code: “”, // Код кнопки (из документа ДО)

title: “”, // Название кнопки (из документа ДО)

desc: “”, // Описание кнопки, показывается при наведении мыши на кнопку

class: “”, // Класс, который будет добавлен в таблицу стилей контейнера кнопки

confirm\_msg: “”, // текст подтверждающего запроса при нажатии на кнопку

msg\_class: “” // класс, устанавливаемый окну запроса

comment\_require: false // флаг, показывающий, что при выполнении этого действия ДО требуется заполненный комментарий

is\_private: false // флаг, обозначающий, что данную кнопку необходимо показывать только в режиме редактирования (при параллельном редактировании/блокировках)

zone: "top-left" // строка, определяющая положение кнопки на форме - сверху/снизу, справа/слева - top-right, bottom-left и т.п.

posindex: позиция кнопки в блоке, чем число больше - тем кнопка левее, учет позиций ведется по всем кнопкам блока (ДО, Печать, кнопки формы)

}

Обработчик, в процессе формирования массива, устанавливает только два атрибута – code и title. Остальные атрибуты не являются обязательными, но могут быть, по желанию разработчика, установлены программным кодом шаблона подготовки данных формы.

Установка атрибута class позволяет менять цвет или пиктограмму кнопки ДО.

Установка атрибута desc – показывать информационное сообщение (подсказку).

Установка атрибута confirm\_msg позволяет не сразу выполнять действие ДО, а вызывать дополнительное окно с текстом сообщения и кнопками «Да» и «Отмена», разъясняющее пользователю последствия его действия и дающее возможность отказаться, если кнопка нажата случайно, а установка атрибута msg\_class – раскрасить/оформить данное предупреждающее окно нужным образом, чтобы дать пользователю сигнал – это формальное предупреждение или он действительно может, не подумав до конца, выполнить действие, которое потом будет трудно отменить.

При установленном атрибуте comment\_require плеер проверяет заполнение текущего комментария ( oData.data.comment ), и если он пуст - то выводится окно ввода комментария, из которого, по нажатию ОК, идет сохранение комментария в анкете, и только после возврата данных с сервера - отправка данных по кнопке ДО

При показе, если не определен атрибут posindex, плеер рисует кнопки в блоке справа-налево, т.е. первая кнопка в массиве будет самой правой, а последняя - самой левой...
