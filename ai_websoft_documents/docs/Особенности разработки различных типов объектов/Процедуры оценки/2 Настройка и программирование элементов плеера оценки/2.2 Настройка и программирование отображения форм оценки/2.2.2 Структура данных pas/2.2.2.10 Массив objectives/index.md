## 2.2.2.10 Массив objectives

Массив содержит набор объектов, описывающих цели, связанные с формой оценки (массива tasks анкеты). Структура описания каждой цели следующая:

{

id: “”, // Идентификатор цели

class: “”, // Класс, если установлен, будет добавлен в перечень стилей контейнера цели

type: “”, // Тип цели, служит как инструкция обработчику

//            “task” – создается документ задачи, и ссылка размещается в массиве tasks анкеты

//            “kpi” – создается запись в массиве kpis анкеты

//            любое другое значение обработчик пропускает, т.е. не сохраняет информацию по цели, не создает документов или записей, что позволяет формировать нужную визуальную структуру при помощи псевдоцелей разного назначения. При этом обработка таких целей – задача программиста.

objective\_block\_id: “”, // Идентификатор блока целей, если структура objective\_blocks сформирована, цели будут сгруппированы в верхний уровень дерева

collapsed: false, // Признак состояние плашки цели. По умолчанию все дерево целей развернуто и цели открыты. Если у цели выставить данные атрибут в true, то текущая цель будет отображаться в свернутом виде (только заголовок)

editable: true, // Признак возможности редактирования полей цели

can\_add\_child: true, // Признак возможности добавления цели следующего уровня

can\_delete: true, // Признак возможности удалить цель

can\_translate: true, // признак возможности транслировать цель подчиненным

wfparameters: {}, // Массив настроек отображения и редактирования цели

objectives: \[\], // Массив, содержащий данные по целям следующего уровня

_sum\_weight: null, // Сумма весов дочерних целей. Если этот параметр приходит, то плеер именно его показывает в поле "Суммарный вес задач цели", если параметр не указан - плеер автоматически суммирует вес дочерних задач (если они есть) и выводит полученную сумму в нужное поле формы_

_tabs\_object: {} // Объект, содержащий инструкци плееру по отображению дополнительных закладок карточки цели_

<field\_name\>: { // Объект, содержащий данные по конкретному полю.

                value: “”, // Значение поля (для полей типа url – адрес ссылки)

               name: "" //  для поля с типом foreign\_elem - названия выбранных обхектов, через точку с запятой

                editable: “”, // Признак возможности редактирования значения поля

                class: “”, // Класс, будет добавлен в таблицу стилей контейнера поля

                cell\_class: “”, // Класс, будет добавлен в таблицу стилей ячейки со значением поля

                file\_name: “”, // для полей типа file – название файла

                file\_type: “”, // для полей типа file – тип файла (doc, txt, pdf и т.п.) – для пиктограммы

                file\_url: “”, // для полей типа file – url на скачивание файла

                file\_size: “”, // для полей типа file – размер файла в байтах

                link\_text: “” // для полей типа url – текст названия ссылки

                _desc\_form: "", // Текст всплывающего сообщения (tooltip/title), будет показан при наведении мыши на значение в окне редактирования_

                _desc\_from\_class: "", // дополнительный класс для сообщения_

                _desc\_view: "",_ _// Текст всплывающего сообщения (tooltip/title), будет показан при наведении мыши на значение в списке/таблице_

                _desc\_view\_class: "",_ _// дополнительный класс для сообщения_

                }

}

Названия полей формируются обработчиком по следующему принципу: есть список стандартных полей, которые формируются обработчиком особым образом и всегда присутствуют в наборе данных. Список стандартных полей:

\- name – название цели (поле name из объекта task)

\- plan – плановое значение цели (поле plan из объекта task)

\- fact – фактическое значение (поле fact из объекта task)

\- period\_plan – _плановый период_ (_поле_ plan\_budget\_period\_id _из объекта_ task)

\- date\_plan – дата планирования (поле date\_plan из объекта task)

\- period\_fact – фактический период (поле fact\_budget\_period\_id из объекта task)

\- date\_fact – фактическая дата (поле date\_fact из объекта task)

\- mark – оценка по цели (поле value из объекта task)

\- weight – вес цели (поле weight из структуры tasks объекта pa – оценочной формы)

\- position _- порядковый номер цели в списке задач анкеты (поле_ position _из структуры_ tasks _объекта_ pa _– оценочной формы) (2019.2.3.83)_

Помимо стандартных, обработчик автоматически включает в набор данных поля документооборота, видимые согласно условиям, описанным в объекте ДО.

Внимание: При сохранении формы обработчик размещает значения полей в структуре custom\_fields объекта task, а при формировании набора для отправки на плеер – извлекает их из этого массива. Структуру workflow\_fields обработчик не изменяет.

При формировании объектов полей обработчик определяет только два атрибута: value и editable. Остальные атрибуты объекта данных поля могут быть установлены разработчиком в коде шаблона подготовки данных. Значения editable, class и cell\_class, если они установлены, замещают настройки, установленные для поля в объекте wfparameters.

Структура объекта objectives.wfparameters полностью совпадает со структурой pas.wfparameters, см. описание в соответствующем разделе документации.

Массив objectives содержит объекты настроек целей нижнего уровня. Структура объектов аналогична описанной выше.
