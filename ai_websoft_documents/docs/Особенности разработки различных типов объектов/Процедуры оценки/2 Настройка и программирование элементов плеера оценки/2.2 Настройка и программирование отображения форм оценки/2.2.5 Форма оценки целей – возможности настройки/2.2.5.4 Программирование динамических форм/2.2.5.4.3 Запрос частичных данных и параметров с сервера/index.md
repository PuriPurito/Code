## 2.2.5.4.3 Запрос частичных данных и параметров с сервера

Функционал предоставляет возможность задать для некоторых полей (аналогично ключевым из соседней статьи данного раздела) условие, по которому плеер, при измении значения в данном поле, вызовет на сервере выполнение некоторого кода (передав ему текущую редактируемую цель, как данные, так и параметры отображения), в котором  (коде) программист может модифицировать значения полей и/или, по желанию, параметры отображения формы. Потом измененные данные возвращаются плееру, который перерисовывает форму, в соответствии с присланными данными/параметрами.

Активация функционала: для поля (wfparameters.objective.<имя\_поля>) добавляется параметр update\_data - объект с элементами collection (код объекта выборки, которая будет вызвана на сервере) и params (true|false - признак, показывающий плееру, надо ли передавать и получать данные параметров отображения формы - если false - то обновляются только даные, без параметров)  
Активация функционала для цели в целом - параметр update\_data добавляется в описание события (onAdd, onEdit... и т.д.)

Выборка, запускаемая на сервере, получает параметры:  
\- sMode - "task" - режим работы выборки (для возможности использовать одну выборку в разных функциях)  
\- context (содержание полей текущей цели, заполненных значениями по умолчанию или введенными пользователем) - если не запрещено параметром no\_task  
\- parent\_context (содержание полей родительской цели, если она есть) - если не запрещено параметром no\_parent  
\- params (объект параметров отображения текущей цели - содержимое wfparameters.objective) - если не запрещено параметром no\_params  
\- assessment\_appraise\_id (ИД текущей процедуры оценки)   
\- pa\_id (ID текущей анкеты оценки)  
\- task\_id (ID текущей цели) - если цель еще не сохранена на севрере, то null  
\- parent\_task\_id (ID родительской цели) - если нет, то null  
\- curUserID (ID текущего пользователя)  
\- curPersonID (ID текущего участника оценки) - если используется делегирование, то отличается от ID текущего пользователя  
\- impersonate\_id (ID запрошенного делегирования) - обычно совпадает с curPersonID, но может оличатся, если запрос на делегирование отклонен

Если вызов данных с сервера осуществляется по событию onAdd - то в переменной context возвращается JSON-строка со значениями только тех полей формы, для которых определены значения по умолчанию  
Если вызов коллекции происходит по событию изменения данных поля (при открытом диалоге редактирования цели) - то возвращаются текущие установленные значения полей цели  
Если объект параметров цели - массив (для динамического переключения по ключевым полям или несколько кнопок добавления задачи) - то в переменной params возвращается тот элемент массива, который актуален для текущего состояние цели

Выборка может вернуть:  
\- массив RESULT  состоящий из одного или двух элементов: первый - набор данных цели (объект с набором вложенных объектов, где имя объекта - код поля, а свойство value - значение поля), второй объкт массива (опционально) - параметры отображения формы цели (объект, совпадающий по структуре с объектом wfparameters.objective), которые будут применены к текущей цели (новой несохраненной или существующей).  
\- если массив RESULT пустой, то данные берутся из объекта DATA - DATA.task (данные цели) и DATA.params (параметры отображения)

В каждом из объетов (tasks и params) выборка может вернуть параметр hasFullData.  
Если hasFullData = false (или не прислан) - то обновление данных цели производится в инкрементальном режиме (новые атрибуты добавляются, существующие изменяются, атрибуты/объекты, отсутствующие в присланном объекте, но имеющееся в цели, остаются без изменений.  
Если hasFullData = true - то происходит полная замена соответствующего объекта цели на сформированный выборкой.

Пример. У нас есть код предварительной обработки формы, в котором мы для поля period\_plan (control\_type="select", выбор значения из списка бюджетных периодов)  устанавливаем признак обновления с вызовом выборкм UPDATE\_DATA\_TEST, указав при этом возможность смены параметров

\_wf\_obj = oData.data.wfparameters.objective;

\_wf\_obj.period\_plan.update\_data = {collection: "UPDATE\_DATA\_TEST", params: true};

В самой выборке с кодом "UPDATE\_DATA\_TEST" пишем следующий код:

var oContext = tools.read\_object(context); // получаем объект данных цели  
var oParams = tools.read\_object(params); // объект параметров цели  
id = OptInt(oContext.GetOptProperty("period\_plan").value, 0); // идентификатор выбранного бюджетного периода  
te = tools.open\_doc(id).TopElem; // открываем документ периода  
RESULT = \[\]; // инициализация объекта результата  
oContext.name = {value: "Выбран период с названием - " + te.name.Value}; // изменяем значение поля nsme цели  
oParams.name.control\_type = "text"; // меняем тип отображения поля nsme на однострочное поле ваода  
RESULT.push(oContext); // добавляем в целевой массив измененный объект значений цели  
RESULT.push(oParams); // добавляем в целевой массив измененный объект параметров отображения цели

Итог:

При добавлении новой цели она открывается с настройками по умолчанию (например, если модифицировать базовую процедуру планирования и оценки целей - то поле "Название" пустое и преддставлено в виде контрола textarea с многострочным вводом)

После изменения значения в поле "Плановый период" в поле "Название" появляется текст "Выбран период с названием - " и название периода, а само поле меняет контрол на text (однострочный ввод)

 Данный функционал более универсален, чем работа с ключевыми значениями полей, но требует обращения к серверу при каждом изменении значения поля. Пожтому его стоит применять в случаях, когда: либо число возможных вариаций параметров внешнего вида формы очени велико, либо определяется по связанным данным (вы выбираете объект из спика, а вид формы отпределяется не самим объектом, а категорией, к которой он относится. (Но и в этом случае можно использовать и функционал ключевых полей, заранее разбив объекты списка по категориям и проставив в ключевых полях наборы значений)

Второй посыл использования функционала - динамическое изменение значений полей формы при выборе некоторого основного элемента из справочника, например - вы выбираете КПЭ в поле формы и хотите динамически обновитьь текст в поле "Описание"
