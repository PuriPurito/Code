## 2.2.5.4.2 Реализация функционала зависимых наборов данных.

  
Для описания поля указывается атрибут depend\_datasets - объект, описывающий массив наборов данных, которые надо обновить с сервера при изменении значения поля.  
Каждый элемент массива содержит два атрибута - name (имя набора данных) и collection (код объекта удаленной выборки, которая вернет измененный набор данных).  
Логика работы функционала следующая - после отрисовки формы на контрол поля, для которого указан атрибут depend\_datasets, вешается обработчик, отслеживающий событие изменения значения поля.  
При изменении значения (это может быть установка флага в чекбоксе, клик в радиокнопке, выбор нового значения из списка) на сервер отправляется запрос на обновление нужных наборов данных. Код серверного обработчика последовательно обрабатывает полученный массив наборов, для каждого определяется заданная коллекция. Для коллекции устанавливается набор переменных:  
\- sMode - "dataset" - для возможности использовать одну коллекцию в разных режимах работы  
\- curUserID - текущий пользователь  
\- assessment\_appraise\_id - текущая процедура оценки  
\- dataset - название текущего набора данных  
\- context - набор полей текущего объекта (задачи/цели),  
после чего выполняется код удаленной выборки. Коллекция должна вернуть (в массиве RESULT) стандартный JSON-массив данных, аналогичный тому, что задается в плеере (массив объектов со свойствами id, name, desc).  
После вычисления всех наборов/коллекций из присланного запроса, серверный обработчик возвращает весь масив обратно плееру. Плеер обновляет все нужные наборы данных и перерисовывает форму в соответствии с изменениями.

Задача - при добавлении КПЭ организовать выбор по категориям. Форма состоит из двух полей - категория КПЭ и выбор КПЭ, при изменении категории список выбора для КПЭ должен перестраиваться.

Формируем наборы данных по умолчанию:  
oData.data.dataset.kpi\_types = ArrayExtract(XQuery("for $elem in roles where $elem/catalog\_name = 'kpi' return $elem/Fields('id','name')"), "({'id': This.id.Value+'', 'name': This.name.Value})");  // список категорий КПЭ  
oData.data.dataset.kpis = ArrayExtract(XQuery("for $elem in kpis where IsEmpty($elem/role\_id) = true() return $elem/Fields('id','name')"), "({'id': This.id.Value+'', 'name': This.name.Value})");  // список КПЭ, не привязанных к категории

Задаем описание параметров формы - два поля типа "выбор из списка", ссылающихся на наборы данных, задаем связку по набору:  
wfparameters.objective = {  
    kpi\_type: {  
        label: "Тип КПЭ",  
        control\_type: "select",   
        editable: true,  
        visible: true,  
        data\_src: "kpi\_types",  
        depend\_datasets: \[{name: "kpis", collection: "update\_kpi"}\]  
    },  
    kpi\_id: {  
        label: "Тип КПЭ",  
        control\_type: "select",   
        editable: true,  
        visible: true,  
        data\_src: "kpis"  
    }  
}

Создаем на сервере объект удаленной выборки с кодом "update\_kpi". В программном коде объекта пишем примерно следующее:  
var oContext = tools.read\_object(context);  
var sRoleID = oContext.GetProperty( "kpi\_type" ).value;  
var arrCurCatalogItems = ArraySelectAll(XQuery("for $obj in kpis where MatchSome($obj/role\_id,(" + sRoleID + ")) order by $obj/name return $obj/Fields('id','name')"));  
RESULT = ArrayExtract(arrCurCatalogItems, "({'id': This.id.Value+'', 'name': This.name.Value})");

В итоге - при созданни новой цели показывается окно со двумя полями типа "Выбор из списка". По умолчанию в первом поле список выбора с категориями, относящимися к каталогу kpis, а в списке выбора второго поля - список объектов типа kpi, не относящихся ни к одной из категорий. При выборе в первом поле какой-либо категории список значений во втором поле изменения - показываются только объекты, относящиеся только в выбранной категории.
