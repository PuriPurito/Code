## 2.2.1 Общие сведения

Формы оценки показываются блоками. Каждый блок объединяет все формы на одного и того же оцениваемого сотрудника и одного и того же оценивающего руководителя. Такие формы группируются в одну строку в дереве оценки (см. раздел 2.1).

При клике на ссылку в дереве плеер посылает на сервер запрос на получение данных по всем оценочным формам блока.

\- параметры строки запроса:

format = json // при работе в режиме совместимости с предыдущим вариантом плеера надо выставить xml

assessment\_appraise\_id = …. // идентификатор процедуры оценки

\- данные формы:

{

"mode":"request", // метод обработчика – получение данных по анкетам

"pas":\[ // массив идентификаторов анкет, информацию по которым надо вернуть

{"id":"…"},

…

\],

"options":{ // объект настроек

"showtranslation":true, // возвращать объекты трансляций для оценки целей

"show\_wf\_parameters":true, // возвращать объект настроек для формы целей

"workflow":true, // информация по действиям документооборота

"person\_info":true, // возвращать информацию по оцениваемому сотруднику

"person\_icon":true, // возвращать данные по фото оцениваемого

"mark\_self":true, // возвращать значения самооценки для формы руководителя (значение зависит от соответствующего флага в настройках процедуры оценки)

"mark\_manager":true, // возвращать значения оценки руководителя для формы оценки эксперта (по настройке процедуры)

“mark\_expert”: false, // возвращать значения оценки эксперта для формы итоговой оценки (по настройке процедуры)

"expert\_info":true, // возвращать информацию по оценивающему

“expert\_icon”: true, // возвращать данные по фото оценивающего

"update\_dataset":true, // возвращать данные по общим справочникам (этапы ДО, временные периоды и т.п.)

"impersonate\_id":"1105387902724063510" // идентификатор текущего участника оценки, с учетом делегирования

}

}

Обработчик, принимая этот запрос:

\- проверяет идентификатор текущего участника, если он отличается от идентификатора текущего авторизованного пользователя, по списку делегирования в карточке процедуры;

\- проверяет по условиям документооборота права доступа текущего участника к запрошенным анкетам;

\- по каждой анкете формирует структуру данных, содержащую данные анкеты и параметры, описывающие настройки ее дизайна. Настройки дизайна формы формируются исходя из типа оценки, параметров процедуры и параметров текущего этапа документооборота (описано ниже);

\- сформированная обработчиком структура данных обрабатывается дополнительным шаблоном, указанным в процедуре оценки для данного типа оценки и статуса анкеты;

\- в коде дополнительного шаблона программист может изменять настройки элементов формы нужным ему образом;

\- после обработки дополнительным шаблоном структура данных анкеты возвращается в обработчик;

\- обработчик собирает данные всех анкет в массив, формирует посылку и отдает данные плееру.

Возвращаемая структура данных:

{

“pas”: \[\], // массив данных оценочных форм

"error": { // структура кода возврата

                "code": 0, // код возврата – 0, если все нормально, иное значение – код ошибки

                "message": "Fetched 3/3 forms." // сообщение, информация или расшифровка ошибки

},

"assessment\_user": { // структура информации об участнике оценки, с учетом делегирования

                "id": "1105387902724063523", // ID (при делегировании может отличатся от идентификатора аутентифицированного пользователя портала

                "name": "Лезова Надежда Семеновна" // ФИО участника оценки

},

"sid": "910762673556160512" // контрольная сумма текущей сессии

}
